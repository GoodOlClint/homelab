# Make targets

Every target with what it does. `make help` and the Makefile are the source; this table carries the gotchas.

| Target | What it does |
|--------|-------------|
| `make apply` | Full deploy: terraform → inventory → ansible-all |
| `make bootstrap` | First-time: terraform (adguard+infisical only) → inventory → ansible-bootstrap |
| `make plan [vm]` | Terraform plan (optionally scoped to one VM) |
| `make build <vm>` | Terraform + inventory + ansible for a single guest or a numbered pair (`make build adguard` builds `adguard1`+`adguard2` via `group-targets`; `scripts/guest-targets.sh` resolves type, HA, and cloud-init targets; resolution failure aborts before terraform runs) |
| `make rebuild <vm>` | Replace guest in one atomic `-replace` apply → clean SSH → ansible (reconciles VM↔LXC conversions + stale HA registrations) |
| `make backup-jobs` | Apply only `proxmox_backup_job.jobs` after editing `backup_jobs` in `vars.auto.tfvars` (re-author as replacements land; never a bare apply while old-shape guests sit outside state) |
| `make sdn-apply` | Apply only the network module (SDN zones + VNETs from `vlans.yaml`) — how a new guest VLAN lands without a bare fleet apply. `REAPPLY=1` re-creates the SDN applier when the cluster shows a VNET `state: new` (the applier only re-runs for changes in the same plan) |
| `make data-volumes` | ADR 0020 holder step: apply the holder VM 900 ALONE, then `playbooks/data-volumes.yml` formats (`mkfs.ext4`, blkid-guarded) and chowns each new volume to the CT-root mapped owner. Run after adding a `data_volumes` entry and BEFORE `make build` of its consumer — never both in one apply |
| `make ansible <vm>` | Run site.yml limited to one host (supports `TAGS=`) |
| `make ansible-all` | Run full site.yml (supports `TAGS=`) |
| `make ansible-infra` | Run infrastructure.yml only (supports `TAGS=`) |
| `make ansible-services` | Run services.yml only (supports `TAGS=`) |
| `make update` | Fleet patch in three halves: `make update-nodes` → `update-all.yml` on `all:!proxmox:!mcp` (guests, worklab, VPS; `mcp` is skipped because a restart drops its pending approval tickets; apt/apk dist-upgrade, reboot-if-required one host at a time so a dns/adguard pair never loses both members) → `make k8s-update`. The `plex` host checks whether apt has work first and only then waits for an idle Plex (`ansible/tasks/wait_until_idle.yml`: passes on the first idle poll, re-polls every minute while busy, 30 max, `IDLE_MAX=<minutes>` overrides), waits again right before its reboot, and is skipped, upgrade and reboot, if it never goes idle. `VM=<host>` runs only the guest play, limited. The 2026-08-10 B4 gate is lifted (2026-09-11) |
| `make update-nodes` | Patch the cluster nodes one at a time (`LIMIT=` for one). When apt has work the node is emptied FIRST — drain every `talos-*` guest on it through its own cluster's kubeconfig (the cluster comes from `terraform/talos-nodes.json`; a guest missing from the map fails the play, a cluster with no kubeconfig yet is skipped with a message), `ha-manager crm-command node-maintenance enable` (with `shutdown_policy=migrate` the VMs live-migrate, CTs restart-migrate), `ceph osd set noout` — then `dist-upgrade`, a reboot only when the newest installed kernel is not the running one (live `uname -r`, never the cached `ansible_kernel`), then the recovery tail, which always runs so a re-run heals a half-finished node: wait for quorum + the LRM, unset noout, leave maintenance, uncordon, wait for the Talos node Ready and Ceph `HEALTH_OK`. Refuses to start unless Ceph is `HEALTH_OK` or the only warning is the play's own `noout`. A node with no apt work is untouched; a node holding the Plex CT or a pod of a `homelab/idle-check` Deployment runs ONE wait whose check is the AND of every check that applies (Plex over ssh + `pct exec`, each Deployment over `kubectl exec`), so it passes on the first poll where all are idle at once and the drain starts immediately; it polls every minute while busy up to 30 minutes (`IDLE_MAX=<minutes>`) and the node is skipped for the run if it never does. Evacuating before the upgrade is deliberate: a wedged postinst (2026-09-11, `pve-ha-lrm` stop hung forever on a kernel-faulted worker with `TimeoutStopSec=infinity` and apt's shutdown inhibitor — `systemctl reboot -i`) then strands nothing |
| `make vps-deploy` | 3-phase: terraform (SSH open) → ansible → terraform (SSH closed). Initial provisioning only — phase 2 needs root SSH, which hardening removes |
| `make vps-ansible` | Day-2 VPS deploy over the tunnel (survives the wg restart via async handler) |
| `make vps-close-ssh` | Close the Vultr provisioning SSH rule after a failed vps-deploy |
| `make vps-rebuild` | Destroy + rebuild VPS |
| `make rebuild-infisical` | Replace the Infisical VM and restore the vault from its newest PBS `databases/infisical` dump (ADR 0039): unprotect via the cluster API → `make rebuild` (the first `site.yml` pass may end 401 once the empty stack answers — expected) → `make infisical-restore` → `make ansible infisical` → `make refresh-identity`. Never re-bootstraps — the PKI root and every identity survive |
| `make infisical-restore` | `scripts/infisical_pbs_restore.sh`: PBS creds from `secrets.sops.yml` (take `make infisical-backup` first — a PBS rebuild rotates the token), newest snapshot → `pg_restore` → `/api/status` → one identity read; `HOST=`/`DIR=` aim it at a throwaway stack (rehearsed on wl-resolute 2026-08-25) |
| `make infisical-seed` | Restore Infisical from backup (disaster recovery only) |
| `make infisical-backup` | Export Infisical → SOPS backup |
| `make refresh-identity` | Refresh Infisical machine identities (supports `LIMIT=`, `FORCE=true`) |
| `make clean` | Destroy all (protected VMs preserved). `FORCE=true` to destroy everything |
| `make node-answers` | Bake the PXE answer file for every node in `host-bindings.yaml` (ADR 0026); `make ansible pxe` ships them |
| `make node-arm NODE=<n>` | **Arm a node for PXE install (the wipe confirm).** The answer server refuses (404 → no wipe) until armed; auto-expires after `ARM_MINUTES` (default 30). `make node-disarm NODE=<n>` cancels; `make node-arm-status` lists armed nodes. iPXE also defaults to local-disk boot, so an accidental PXE never auto-installs |
| `make proxmox-hosts` | WP2 cluster plane on the `proxmox` group (`inventory/proxmox.yaml`, first host creates the cluster): resolver+repos → mgmt re-home to `vmbr0.30` + rings + ceph link → cluster create/join (API) → QDevice while 2-node (qnetd host = `cluster.qdevice_addr`, prepped hands-off) → keepalived VIP (`cluster.vip_cidr`) → logging/mounts/firmware. Run after `make hosts-apply` on every node; second run = 0 changed (proven 2026-08-19). `TAGS=mounts` scopes it to the NAS host mounts (`cluster.nas_mounts` in `host-bindings.yaml`, ADR 0017) |
| `make adguard-pause MINUTES=n` | Disable AdGuard filtering on every resolver instance for n minutes (default 10) — POST `/control/protection` with the Infisical `/homepage` admin creds (ADR 0029) |
| `make dns-records` | Push every inventory-derived name into the flat service zone over RFC 2136 (ADR 0040): guests + nodes (A + PTR), VIPs, MetalLB names, mirrored public records; both inventories + `host-bindings.yaml`; second run = 0 changed |
| `make flux-check [CLUSTER=…]` | ADR 0048 pre-flight: every `${VAR}` a Flux tree emits has a key in `cluster-bindings` — Flux blanks an unbound token and fails open. `CLUSTER=` picks the Flux root whose trees are checked and the kubeconfig the bindings are read through: services (default) checks `kubernetes/flux/apps/`, `ci` checks `kubernetes/flux-ci/apps/` (`flux_check.py --cluster ci --kubeconfig …`) |
| `make k8s-seed [CLUSTER=…]` | The seed play (`--tags seed`, `k8s_seed` role, ADR 0048). `CLUSTER=services` (default): the full allowlist. `CLUSTER=ci` (ADR 0063) passes `-e k8s_seed_cluster=ci` and seeds only `tasks/ci.yml` through `kubernetes/talos/.secrets/ci/kubeconfig`: namespaces `flux-system`/`arc-systems`/`arc-runners`, the `flux-ci-arc` account and its RoleBindings, an empty `cluster-bindings`, and `github-app` from Infisical `/github-runner` `ci_github_app_id`, `ci_github_app_installation_id`, `ci_github_app_private_key`. Flux on the ci cluster is installed once from `kubernetes/flux-ci/`, which reuses the services root's `gotk-components.yaml` from outside its directory: `kubectl kustomize --load-restrictor LoadRestrictionsNone kubernetes/flux-ci \| kubectl --kubeconfig kubernetes/talos/.secrets/ci/kubeconfig apply --server-side -f -` |
| `make k8s-apps` | WP7 (ADR 0048): the in-app tail of `ansible/playbooks/kubernetes.yml` (`k8s_apps` role, play tag `apps`) — jellyfin (first-run wizard, LDAP-Auth plugin against `ak-outpost-ldap.authentik-ext.svc`, Movies/TV/Music libraries, all through `kubectl exec … curl localhost:8096`; plugin config merged only when it differs, one `POST /Library/Refresh`), plex-services (arr `authenticationMethod=external`, SAB `host_whitelist` additive), authentik-ext (`generate_secret.yml` on `/authentik-ext`; the blueprint is applied through `POST /api/v3/managed/blueprints/<pk>/apply/` only when the discovered instance's `last_applied_hash` ≠ sha512 of `blueprint-external.yaml`, after the worker's mounted copy has caught up — the kubelet-lag trap). Second run = 0 changed. Fleet (ADR 0065): over a `kubectl port-forward`, probes setup state (open setup answers 404 on `/api/v1/fleet/me`, closed answers 401), stops with an error if setup is open, and verifies the global admins equal `fleetdm_expected_admins`; `make k8s-apps FLEETDM_FIRST_SETUP=1` (passes `-e fleetdm_first_setup=true`) is the only way it runs first-time setup. The internal realm is `make ansible authentik` |
| `make talos-plan` / `make talos-build` | Plan / targeted-apply one Talos cluster's VMs (`terraform/talos.tf`; nodes listed in `terraform/talos-nodes.json` with their `cluster` and `role`) and write that cluster's inventory. `CLUSTER=services` (default): the three control-plane VMs, output `talos_nodes` → `kubernetes/talos/.secrets/nodes.json`. `CLUSTER=ci` (ADR 0063): the ci control-plane node and workers, output `talos_ci_nodes` → `kubernetes/talos/.secrets/ci/nodes.json`; the ci nodes are absent from the plan (and the output is `null`) until `ci_runner` is in `vlans.yaml`. Each instance is its own `-target`, so one cluster's build never touches the other's VMs; `TALOS_TARGETS=` still overrides the list for a one-node apply. An unknown `CLUSTER` exits 2 before terraform runs |
| `make talos-secrets` / `talos-apply` / `talos-bootstrap` | `CLUSTER=services` (default) or `ci`, passed to `talos.sh` in the environment. Pull (or generate once) the cluster secrets from Infisical (`/talos` for services, `/talos-ci` for ci); render + `apply-config` every node (maintenance nodes via their DHCP lease, configured nodes in place); bootstrap etcd on the first control-plane node, fetch kubeconfig into the cluster's secrets dir, wait Ready. `talos.sh` refuses an inventory that records another cluster, before any write. The ci render is one NIC, no VIP (the endpoint is the control-plane node), no Ceph leg, no registry trust and no all-interfaces etcd metrics bind; workers render with `--output-types worker`. `kubernetes/talos/talos.sh render` renders without applying |
| `make talos-close-join CLUSTER=ci` | Waits for every inventory node to be Ready, rotates the join token in the bundle and Infisical `/talos-ci`, applies it to the control plane only, deletes every other `bootstrap-token-*` Secret and proves each deleted token gets 401. A job node otherwise keeps a token that can enrol as any node (Codex finding B). Runs on its own at the end of `talos-bootstrap` and of any ci `talos-apply` that includes a worker |
| `make talos-rebuild-worker CLUSTER=ci NODE=<worker>` | One worker from a blank disk: drain, delete the Node, replace only that VM, refresh the inventory, apply (retrying until the maintenance API answers), close the join. Refuses a control-plane node or a node of another cluster |
| `make talos-print [CLUSTER=…]` | Offline: print the terraform targets, inventory output and path, kubeconfig, Talos cluster name, Infisical folder and endpoint the selection resolves to. Runs nothing and writes nothing |
| `make flux-reconcile TREE=<tree> [CLUSTER=…]` | `CLUSTER=` picks the kubeconfig (default services). `flux reconcile kustomization <tree> --with-source` for one `kubernetes/flux/apps/<tree>.yaml` — only skips the interval; a push to `main` is the deploy. Trees: `ceph-csi` (`client.csi-rbd` key + fsid/mons are seed bindings; the `ceph-rbd` StorageClass is `Retain`), `metallb`, `cert-manager`, `zot`, `arc`, `traefik`, `infisical`, `homepage`, `external-dns`, `monitoring`, `plex-services`, `games`, `jellyfin`, `authentik-ext`, `headlamp`, `metrics`, `kiwix`. With `CLUSTER=ci` the one tree is `ci-arc` (`kubernetes/flux-ci/apps/ci-arc.yaml`) |
| `make k8s-smoke` | WP7: the smoke play (`--tags smoke`, tagged `never` so a bare run skips it) — rbd (PVC + write/read), registry (a docker.io busybox pull through Zot), nfs (the plex-services media PV as the arr uid), infisical (an `InfisicalSecret` on `/shared` syncs `pbs_backup_token`, then deleted). Each is create → wait Succeeded → assert the log marker → delete; a missing marker FAILS the play (`rbd-smoke smoke: PASS` per smoke in the output) |
| tree `traefik` / `infisical` / `homepage` | P4a (ADR 0035): Traefik on offset 65 with the Let's Encrypt wildcard as default cert (ADR 0040 P5b; a rehearsal is `issuerRef: letsencrypt-staging` in `kubernetes/traefik/certificate.yaml`; the `infisical-universal-auth` seed Secret must exist first — `make k8s-seed`); the Infisical operator (the k8s secret path; `make k8s-smoke` syncs one `/shared` key and deletes it); homepage Deployment/ConfigMap/InfisicalSecrets/Ingress on `homepage.<service domain>` + `home.<service domain>` |
| `make plex-pbs-image` | P4c (ADR 0037): `kubernetes.yml --tags pbs-image` builds + pushes the pg-backup CronJob's `proxmox-backup-client` image — root from `kubernetes/.secrets/homelab-ca.crt` (`make pki-hosts` exports it), push password from `secrets.infrastructure.zot_push_password` |
| tree `games` | P4d (ADR 0038): Valheim + PlayFab sidecar on MetalLB offset 67; a second server `valheim2` (world `Ironwood`, own PVC, offset 69, secrets `valheim2_*` in `/docker`, join-code only — no VPS/pfSense forward) since 2026-09-21. Adding a server = copy `valheim2.yaml`, a new offset, two seeded `/docker` keys, a Kuma row, **and a distinct `SERVER_PORT`** (Ironwood is 2466): PlayFab keys a crossplay lobby by advertised WAN IP:port, so two servers on 2456 behind one address are one key and a player's saved favourite resolves to whichever lobby registered last — a player of the first server was handed Ironwood and rejected with `wrong password` within hours of it going up (2026-09-21) |
| tree `monitoring` / `make monitoring-users` | P4b (ADR 0036): the monitoring stack (`kubernetes/monitoring/`, syslog LB on offset 66, five UI hostnames on the ingress); `monitoring@pve` + token → Infisical `/monitoring/proxmox_token_value` |
| trees `metallb` / `cert-manager` / `zot` / `external-dns` + `make pki-hosts` | P3b (ADR 0034): MetalLB L2 pool; cert-manager (DNS-01 self-check pinned to public resolvers) with the `homelab-ca` intermediate Secret from `make k8s-seed` (signed against the root `make pki-hosts` exports; ADR 0039) + the `letsencrypt`/`letsencrypt-staging` ClusterIssuers fed by an `InfisicalSecret` on `/infrastructure` (ADR 0040 P5b); `make talos-apply` so nodes trust the CA; Zot (`make k8s-smoke` pulls busybox through it); external-dns (RFC 2136 → BIND VIP, TSIG from `/infrastructure`): every Ingress host becomes an A record in the service zone |
| `make uptime-kuma` | Converge Uptime Kuma's monitors + ntfy channel from `ansible/playbooks/uptime-kuma.yml` via the `goodolclint.uptime_kuma` collection (localhost play, full pre_tasks for `hostvars`/`vlans.yaml`/Infisical); `CHECK=1` = `--check --diff`, the acceptance test is 0 changes. |
| tree `headlamp` | Read-only Kubernetes dashboard (Headlamp, `kubernetes-sigs/headlamp`) at `headlamp.<service domain>` behind authentik forward-auth: chart as a `HelmRelease`, image through Zot, `clusterRoleBinding.clusterRoleName: view` and `config.unsafeUseServiceAccountToken` so there is no second login — the Ingress middleware IS the gate, so never expose it without forward-auth, and never raise the ClusterRole to `cluster-admin` while that is the only control |
| tree `metrics` | The cluster metrics API: `kubelet-csr-approver` + `metrics-server` + `kube-state-metrics` in `kube-system` (Prometheus scrapes the last over its cross-namespace svc FQDN — the bare name does not resolve from `monitoring`). Talos calls `--kubelet-insecure-tls` unsuitable for production, so `talos.sh` sets `machine.kubelet.extraArgs.rotate-server-certificates` and the approver signs the resulting CSRs — **nothing built into Kubernetes approves `kubernetes.io/kubelet-serving` CSRs, so without it they sit `Pending` forever and metrics-server cannot verify the kubelet**. The approver runs `bypassDnsResolution: true` because the Talos nodes live in `talos.tf`, outside the inventory `make dns-records` reads, so they have no A records and the hostname→SAN check could never pass (`providerRegex` and the IP SANs still gate it). Installing metrics-server is also what creates the aggregated reader ClusterRole carrying `rbac.authorization.k8s.io/aggregate-to-view`, which is how the `view` role — and so Headlamp — gets `metrics.k8s.io` without any RBAC edit |
| `make k8s-update` | Cluster half of `make update` (`kubernetes.yml --tags update`): DELETES the pods of every Deployment/StatefulSet whose image tag is `:latest` (23 today) so `imagePullPolicy: Always` re-pulls through Zot, which re-checks the tag upstream — never `rollout restart`, which Flux reverts at its next reconcile so the pod bounces twice. `NS=` scopes it. **A Flux reconcile does NOT update an image** — with no pod-template change there is no new ReplicaSet and no pull, which is why this target exists. The other ~74 containers are chart images pinned to their appVersion with `IfNotPresent`; a restart cannot move them and they roll by bumping the chart version in `kubernetes/<tree>/helm.yaml` (renovate opens the PR; ADR 0016). Selecting on the tag is what keeps the deliberate pins — `openobserve` at `v0.92.0-rc2`, postgres 17 — out of the blast radius |
| tree `kiwix` | Kiwix ZIM library at `kiwix.<service domain>`, its own namespace since 2026-08-27 — it only ever shared `games` because both came off the same pre-cluster guest (ADR 0038), and `games` is `pod-security enforce=privileged` for Valheim's `SYS_NICE`. The tree sets `enforce=baseline` explicitly: an **unlabelled namespace inherits the cluster default (`privileged`)**, so a split with no label tightens nothing |
| tree `static-viewer` | Private shared static-file viewer at `viewer.<service domain>/<project>/…` ([docs/static-viewer.md](docs/static-viewer.md)): nginx-unprivileged over a read-only NFS PV of the NAS `static-viewer` export (`kubernetes/static-viewer/`, namespace `static-viewer`, `enforce=baseline`), authentik forward-auth, `noindex` headers + `robots.txt`, no public DNS record (ADR 0044 mode `none`), LAN + mobile VPN only. Projects deploy by GNU `rsync` to a per-project DSM `<project>-deploy` user, so a new project is a NAS folder and user with no cluster change; the Kuma row probes `/healthz` over in-cluster svc DNS |
| `make apt-proxy` | ADR 0021 client half on every node, worklab and guest (`apt_proxy` role, both inventories, `LIMIT=`): `/usr/local/bin/apt-proxy-detect` + `apt.conf.d/01proxy` `Proxy-Auto-Detect` — cache when `hostvars['apt-cache']` answers on 3142, else `DIRECT`; https URIs always DIRECT. Nodes also get it from `proxmox_host` (`make proxmox-hosts` now loads `vms.yaml` when present); an LXC only gets it here |
| `make pki-hosts` | ADR 0041 + 0039: creates the Infisical `homelab-pki` project + `Homelab Root CA` when absent and exports the root to `kubernetes/.secrets/homelab-ca.crt` + `ca-bundle.pem` (what every trust consumer and the Makefile's python env read); then the `fleet-hosts` policy/profile/application + ACME (DNS-01, no EAB) and API enrollments under the RSA intermediate `Homelab Hosts CA`; publishes `acme_directory_url` + ids to `/infrastructure`. Idempotent by name; second run prints the same ids |
| `make ca-trust` | ADR 0041: the root into every node's, worklab's and guest's trust store (both inventories, `LIMIT=`); steady state rides `proxmox_host` and the Phase 0 play |
| `make refresh` | `terraform apply -refresh-only` in the fleet root — settles agent-reported output drift (a docker guest's veths change on every container restart) so `make plan` reads clean |
| `make nut-clients` | Deploy NUT `upsmon` secondaries to the physical hosts (`nut_clients` group in `inventory/proxmox.yaml`; server = pfSense NUT package, `docs/pfsense-nut.md`) |
| `make validate` | The CI set (`.github/workflows/validate.yml`, issue #5): terraform fmt + validate ×3 roots, `ansible-lint` (production profile, **no ignore file** — the 2026-09-10 sweep fixed every finding; `ansible/.ansible-lint` excludes only galaxy-installed roles, the retired-guest roles #24 deletes, and the phantom `roles/*/tasks/<shared task>` paths the linter derives from `{{ playbook_dir }}/../tasks/` includes), `--syntax-check` of every playbook against a stub inventory, `flux_check.py --build-only` for both Flux roots (`--cluster ci` for `kubernetes/flux-ci/`), the public-policy validator, `test_axosyslog_routing.py`, `check_apt_proxy_probe.py` (the apt Proxy-Auto-Detect probe's two copies — role template and cloud-init snippet — render byte-identical, #39), `test_identity_paging.py` (the identity listing walks a mocked 150-identity org over two pages, #28), `test_security_guardrails.sh` (the guard's own pins in a scratch repo), an argv-secret grep (#17). CI adds the guardrails on the pushed range and the renovate validator. No credential, no cluster (ADR 0048) |
| `make setup-hooks` | Install pre-commit hooks |
| `make init` | Create venv, install deps, terraform init, galaxy install |
| tree `ci-reaper` | ADR 0062: the hourly pool-`ci` reaper on the services cluster, with its own Proxmox identity (`ci-reaper@pve`, role `CIReaper` on `/pool/ci` only). Its token is `terraform -chdir=terraform/hosts output -raw ci_reaper_api_token`: `make hosts-apply` creates it, then `make k8s-seed` writes Secret `pve-reaper-token`. `TARGET="<addr> …"` passes `-target` addresses to `hosts-plan`/`hosts-apply`, for applying while a listed node is unreachable (its bond refresh fails the whole plan). The CronJob ships `suspend: true`; cutover un-suspends it after the old `arc-runners` reaper is suspended |
