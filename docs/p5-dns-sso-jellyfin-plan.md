# P5 change plan — real DNS on a flat public zone, Let's Encrypt for the ingress, two authentik realms, Jellyfin

Decision record: [ADR 0040](decisions/0040-p5-real-dns-on-a-flat-public-domain-zone-bind-fed-by-nsupdate-external-dns-adguard-forwards-rewrites-retired-let-s-encrypt-dns-01-wildcards-as-traefik-s-default-cert-two-authentik-realms-split-by-audience-jellyfin-over-the-vps-relay-with-ldap-auth.md). Implements [ADR 0006](decisions/0006-dns-names-are-the-access-layer-static-ips-remain-iac-plumbing.md) and the wildcard half of [ADR 0007](decisions/0007-hybrid-cert-model-infisical-pki-for-the-fleet-le-wildcard-for-browser-facing.md). Status: **approved 2026-08-24**; P5a–P5d landed 2026-08-25, P5e next (optional to defer). Each phase is its own approval gate and its own small commits.

Domains are bindings: `<service domain>` and `<media domain>` below are `vlans.yaml` keys (`service_domain`, `media_domain`), never literals in tracked files. The security guardrail is extended to block both.

## Existing state (mapped 2026-08-24)

- AdGuard pair (VIP) answers every internal name from 43 rewrites (10 stale: openobserve/docker/plex-services/homepage/github-runner/squid/mcp/nvidia-* on retired guests). Upstreams are public resolvers plus `[/<vlan>.<domain_suffix>/]<bind VIP>` forwards for the seven zones.
- BIND pair (dns1 primary, dns2 AXFR secondary, VIP) serves seven per-VLAN forward zones + reverse zones, each holding only `SOA`/`NS`/`ns A`; `allow-update { key dhcp-update-key }` (hmac-sha256, Infisical `/infrastructure/bind_tsig_key_secret`), `allow-update-forwarding` on the secondary, zone files written initial-only. No PTRs anywhere; pfSense DHCP DDNS never configured.
- Cluster: Traefik on services offset 65 with a single default `Certificate` (`*.<domain>`, `*.<services zone>`, `<domain>`) from `homelab-ca`; every app Ingress is a plain host rule; hostnames become AdGuard rewrites via `make adguard-rewrite` inside each `deploy.sh`. `DOMAIN` everywhere = `nodes.json .domain` = `module.network.domain_suffix` = `vlans.yaml domain_suffix`.
- Certs: `homelab-ca` = Infisical-signed intermediate (ADR 0039); Kuma carries `ignore_tls` on six monitors because of it. Cloudflare: one zone in Terraform (`cloudflare_zone_id`, media domain: `vps`/`plex` A+AAAA), token `bootstrap.cloudflare_api_token`; a second copy of a DNS token lives in Infisical `/plex/cloudflare_dns_api_token` for `plex_certificate`.
- External paths: Cloudflare tunnel (`cloudflared` in `plex-services`, token-configured, routes hand-set in the dashboard) for tautulli/seerr; VPS relay (Vultr reserved IP → WireGuard → pfSense DNAT) for Plex 32400 and Valheim UDP.
- authentik: a previous docker-LXC attempt died on compose env quoting; the `/docker` `authentik_*` keys are dead. Nothing runs today.

## Decisions (settled with the operator 2026-08-24)

Flat naming only · additive rollout, `.internal` retired last · Jellyfin over the VPS relay on 443 · full scope (DNS, certs, both realms, Jellyfin) · two authentik instances, not brands · external realm through the tunnel · internal realm LAN/VPN only. Rationale and rejected paths in ADR 0040.

## Changes by phase

### P5a — the zone (`<service domain>` on BIND, fed by nsupdate + external-dns, AdGuard forwards)

1. `vlans.yaml`: `service_domain`, `media_domain`; `full_pre_tasks` exposes them; `terraform/modules/network` outputs `service_domain` → `talos_nodes.domain` (cluster-facing name) while `domain_suffix` keeps driving the legacy `dns_zones` until P5e. `security_guardrails.sh` blocks both new bindings.
2. `bind9` role: one flat forward zone `<service domain>` (initial-only shell, same macro, `allow-update` by the TSIG key) beside the per-VLAN zones; reverse zones unchanged.
3. `vlans.yaml` `public_records` (today: `vpn` → WAN IPv4, the WireGuard endpoint — the only record on the public zone). Terraform imports the existing Cloudflare `vpn` record and owns it from that binding; the same list feeds the internal zone (next step) so LAN clients resolve `vpn.<service domain>` identically. **Operator question at P5a start:** is the WAN address static? If it is DDNS-updated, the public record stays out of Terraform and the DDNS client also updates BIND (the TSIG path already exists).
4. New shared task `ansible/tasks/dns_records.yml` (`community.general.nsupdate`, TSIG, against the primary): for every inventory guest an `A name.<service domain> → service_ip` and its PTR; nodes from `proxmox.yaml` (mgmt), the PVE VIP, the AdGuard/BIND VIPs, the MetalLB LB names that are not Ingress-backed (registry, syslog, valheim). Runs from the `dns` play and a new `make dns-records`; idempotent by nature (nsupdate compares).
5. `kubernetes/external-dns/` (`make talos-dns`): RFC 2136 provider → BIND primary, TSIG from an `InfisicalSecret` on `/infrastructure`, `--txt-owner-id` set, sources `ingress` + `service`, domain filter `<service domain>`,`<media domain>`. Every existing Ingress gets its `A` record without change.
6. `adguard` role: conditional forwards `[/<service domain>/]<bind VIP>` and `[/<media domain>/]<bind VIP>` (the media domain's *internal* view: `jellyfin.<media domain>` must resolve to Traefik on the LAN, not the VPS); rewrite variables deleted; `make adguard-rewrite` and its `deploy.sh` callers deleted. The stale rewrites die with the config regeneration (`make build adguard`, one instance at a time per ADR 0029) — or the API in the interim.

**As built (2026-08-25):** the WAN is DDNS-updated (pfSense runs Cloudflare v4+v6 clients for `vpn`), so the plan's DDNS branch applies: Terraform owns no service-zone record; `vlans.yaml` `internal_zones` (`zone → [names]`) drives the BIND zones, the AdGuard forwards, external-dns's zone list and the inward mirror, which looks each name up on the public copy at run time. The media zone is deferred to P5d (LAN clients resolve `plex`/`tautulli`/`vps.<media domain>` today; forwarding it to an empty BIND zone would break them — P5d adds it to `internal_zones` with that mirror list). `nodes.json .domain` keeps the legacy suffix (the registry name is pinned into Talos trust); app hostnames take `SERVICE_DOMAIN` from `lib.sh` `inv_env`. Legacy `<name>.<domain_suffix>` Ingress hosts were not duplicated — one wildcard Ingress + a `redirectRegex` Middleware in `kubernetes/traefik/` 302s them to the service domain, and the `homelab-ca` wildcard Certificate covers both domains until P5b swaps the issuer. Reverse zones for VLAN 30/40 come from adding `infrastructure`/`services` to `zone_vlans`. `dns_records.yml` never prunes: a retired guest's record is removed by hand. **Operator hand step (optional, keeps the mirror live between Ansible runs):** pfSense → Services → Dynamic DNS → RFC 2136: host `vpn.<service domain>`, zone `<service domain>`, server = BIND VIP, key `dhcp-update-key` (hmac-sha256, Infisical `/infrastructure/bind_tsig_key_secret`), interface WAN, TTL 300.

### P5b — certificates (Let's Encrypt DNS-01, Traefik default cert)

1. `cloudflare_dns_api_token` re-homed: bootstrap `external_secrets` → Infisical `/infrastructure`; `plex_certificate` reads it there; the `/plex` copy deleted. Token scope: DNS edit on both zones.
2. `kubernetes/cert-manager/`: `ClusterIssuer letsencrypt` (ACME, DNS-01 Cloudflare, token via `InfisicalSecret`), staging issuer for the first run. `kubernetes/traefik/certificate.yaml` → `dnsNames: ["*.<service domain>", "*.<media domain>"]`, `issuerRef letsencrypt`; `homelab-ca` stays the issuer for nothing browser-facing (registry unchanged).
3. Every `deploy.sh` `DOMAIN` now renders `<service domain>` hostnames; the old `<domain_suffix>` Ingress hosts stay as a second rule until P5e (Traefik serves both; the LE cert covers only the new names, so old names keep the `homelab-ca` cert via a second Certificate). Kuma rows lose `ignore_tls` and move to the new names (`make uptime-kuma`).
4. Terraform: second Cloudflare zone (data source by name, both zones), `jellyfin.<media domain>` A/AAAA (unproxied) → VPS reserved IP, staged now, used in P5d.

**As built (2026-08-25):** `cloudflare_dns_api_token` lives in Infisical `/infrastructure` (bootstrap `external_secrets.infrastructure`; the `/plex` copy is deleted, `/pfsense` keeps its own reference copy) and reaches cert-manager through `kubernetes/cert-manager/secrets.yaml` (an `InfisicalSecret` on `/infrastructure` → secret `cloudflare-api-token`); `plex_certificate` reads `secrets.infrastructure.*`, and its domain/email come from the `media_domain` binding and a new `all.yml` `acme_email` (also `inv_env` `ACME_EMAIL`). `kubernetes/cert-manager/issuer.yaml` carries `letsencrypt` + `letsencrypt-staging` (ACME DNS-01 Cloudflare); the staging issuer proved the path first with a throwaway Certificate, then Traefik's `wildcard-tls` moved to `letsencrypt` with `dnsNames` `*.<service domain>`, `*.<media domain>` (no apex names — nothing serves them). The legacy names keep a second Certificate `legacy-tls` from `homelab-ca` (`*.<domain_suffix>`, `*.<services zone>`, apex) listed in the TLSStore's `certificates`, so SNI picks it for the 302 path and the LE cert stays the default. **cert-manager's DNS-01 self-check queries `1.1.1.1`/`1.0.0.1` only** (`dns01RecursiveNameservers` + `dns01RecursiveNameserversOnly`): the cluster's resolver chain is AdGuard → BIND for the service zone, and BIND never holds the `_acme-challenge` TXT, so the check could never pass through it — a scoped exception to ADR 0012 for the one component whose job is to verify public DNS. `ISSUER=letsencrypt-staging make talos-ingress` rehearses a rebuild without touching prod rate limits; `make talos-infisical` must now precede `make talos-ingress` on a fresh cluster (the issuer needs the token secret). Kuma: every `ignore_tls` is gone — the Traefik-fronted rows moved to `<name>.<service domain>`, Plex probes `http://…:32400/identity` (Plex serves plain HTTP unless secure connections are *Required*), PBS became a TCP 8007 port check (self-signed until the WP8 per-host ACME lands), and `uptime_kuma_validate_certs` returned to the collection default. Terraform: `data.cloudflare_zone.media` by name from the new `module.network.media_domain` output replaced `var.cloudflare_zone_id` (variable removed), the VPS/Plex records use the binding, and `jellyfin.<media domain>` A/AAAA (unproxied → the VPS reserved IPv4 / instance IPv6) are staged for P5d — **not applied**; the same targeted plan also shows the `vps`/`plex` AAAA contents drifted from the instance's current IPv6 (rebuild 2026-08-22), which the P5d apply corrects. No service-zone data source: nothing in Terraform owns a record there (the WAN is DDNS). Open: the operator Mac resolves through the ISP's IPv6 resolvers ahead of AdGuard on `en0` (`scutil --dns` resolver #2), so `<name>.<service domain>` NXDOMAINs on the workstation while `dig @<AdGuard VIP>` answers — a client-side RA/RDNSS matter ([ipv6.md](ipv6.md) has the check), not a P5b defect; the DoD's `curl` was proven with `--resolve` against the LB.

### P5c — authentik, both realms

1. `kubernetes/authentik/` deploys the helm chart twice from one tree with a realm parameter: namespaces `authentik` (internal) and `authentik-ext` (external); each = server + worker + Postgres + Redis, ceph-rbd PVCs, `InfisicalSecret` on `/authentik` resp. `/authentik-ext` (`secret_key`, `postgres_password`, `bootstrap_password`, `bootstrap_token` — generated by `make talos-authentik` through the API, ADR 0035 pattern), PBS `pg_dumpall` CronJob reusing `homelab/proxmox-backup-client` (ADR 0037).
2. Internal: Ingress `auth.<service domain>`; proxy outpost as a Deployment; Traefik `ForwardAuth` middleware `authentik@kubernetescrd`; apps opt in by annotation (arr stack, Homepage, Kuma, Kiwix, Tautulli). OIDC providers for Grafana (native), Portainer, MeshCentral, PDM, PVE, PBS — the last two configured through the API/Terraform where bpg supports it (`proxmox_virtual_environment_realm` is not in bpg; PVE/PBS OIDC realms are hand steps documented in the runbook).
3. External: Service only (no Ingress); a tunnel route `auth.<media domain>` → `authentik-ext-server:80` added in the Cloudflare dashboard (documented, like the existing routes); LDAP outpost Deployment + ClusterIP for Jellyfin; groups `family`, `admins`; enrollment/recovery flows with the family in mind.
4. Machine-to-machine traffic is untouched: arr↔arr, Seerr↔arr, Prometheus scrapes all use in-cluster svc DNS, never the ingress.

**As built (2026-08-25):** `kubernetes/authentik/` (`make talos-authentik`, `REALM=internal|external`) — chart 2026.8.0 through `helm_apply` for server + worker (authentik has dropped Redis, so the "Postgres + Redis" in the plan is Postgres only), an in-tree Postgres 17 Deployment on a ceph-rbd PVC, and the ADR 0037 `pg_dumpall` → PBS CronJob at 02:20 (backup-ids `authentik-postgres`, `authentik-ext-postgres`; both proven by snapshot recency). `deploy.sh` creates the realm's Infisical folder and generates its keys through the API on first run (hex values only): the four common keys plus, internally, one `<app>_oidc_client_secret` per consumer (grafana, portainer, meshcentral, pdm, pve, pbs) and, externally, `ldap_bind_password`. Every authentik object is a blueprint (`blueprint-<realm>.yaml`, mounted from a ConfigMap and applied with `ak apply_blueprint` at deploy time so a deploy is complete when it returns). Two deviations from the plan text: the internal proxy outpost is the **embedded outpost** in `forward_domain` mode (one provider, one cookie on `<service domain>`, no per-app callback routing, no extra Deployment; `config.authentik_host` must be set or the 302s target localhost), and **Uptime Kuma is not behind forward-auth** — `make uptime-kuma` drives it over socket.io from the workstation and a redirect breaks the handshake; it keeps its own login. Forward-auth consumers: the arr stack + Tautulli (the plex-services Ingress, with `seerr` split into its own un-annotated Ingress because it has its own login and is tunnelled), Homepage, Kiwix, via `traefik.ingress.kubernetes.io/router.middlewares: authentik-forward-auth@kubernetescrd` with Traefik's `kubernetesCRD.allowCrossNamespace` on. OIDC consumers wired by the repo: Grafana (env, login form disabled, `authentik Admins` → GrafanaAdmin, basic auth kept for the homepage widget, client secret via a second `InfisicalSecret` in `monitoring`; proven end-to-end with a headless flow-executor login — user created, `isGrafanaAdmin: true`), Portainer (the `control` role PUTs `OAuthSettings` once, gated on the readback), MeshCentral (`authStrategies.oidc` in its templated `config.json` — a deploy-time secret render, the one exception to the agent-env rule because MeshCentral cannot read it from the environment); PVE/PBS/PDM are hand steps in [authentik-setup.md](authentik-setup.md). External realm: `ldapsvc` + the LDAP provider + an outpost that authentik itself deploys in `authentik-ext` through a blueprint-declared `Local Kubernetes Cluster` service connection (bind + search verified from a pod), groups `family`/`admins`, invitation-only `family-enrollment`, link-based `family-recovery` set as the brand's recovery flow (no SMTP anywhere). Kuma rows for both realms (the external one on svc DNS until the tunnel route exists); Homepage's row moved to svc DNS. Operator steps pending: the tunnel route `auth.<media domain>` → `authentik-server.authentik-ext.svc.cluster.local:80`, the phone/passkey test, the PVE/PBS/PDM realms, setting the arr apps to external auth. Housekeeping: `/docker` `authentik_*` and `/homepage/authentik_token` deleted, `infisical_login.yml` loads both new folders, the Infisical operator's first resync restarts the fresh Deployments once (expected).

3. Seerr: switch auth to Jellyfin (UI, operator); Kuma row; Homepage tile.

**As built (2026-08-25):** `kubernetes/jellyfin/` (`make talos-jellyfin`) — one Deployment (uid 2009 / media gid 2000, `fsGroup` 2000) with `config` (20 Gi) and `cache` (30 Gi, transcode scratch) on ceph-rbd and the Synology plex export as its own read-only NFS PV/PVC (`jellyfin-media`; a claim cannot cross namespaces, so the plex-services PV is not shared), Service + plain Ingress `jellyfin.<media domain>` (no forward-auth), image through Zot. ## Sequencing and gates

P5a → P5b → P5c → P5d → P5e, each committed separately and each ending with its DoD evidenced before the next starts. P5c's internal realm can land before P5d; P5d needs P5b (cert) and P5c-external (LDAP). P5e is last and optional to defer.

## Risks

- **Two writers on one zone** (nsupdate + external-dns): disjoint record sets by construction; external-dns owns only names carrying its TXT. Verify by deleting an Ingress and watching only its record go.
- **AdGuard-first is now load-bearing for resolution, not only for poisoning.** ADR 0029's VIP pair covers it; a device on a public resolver simply cannot reach internal names — document, do not paper over.
- **The `.internal` dual-run** means two Certificates on Traefik for a while; the LE one must be the default store or old names win the SNI fallback.
- **Cloudflare token blast radius**: one token edits both public zones; scope it to DNS:edit on those two zones only and rotate at P5e.
- **authentik external is internet-facing 24/7**: tunnel only, Cloudflare WAF rules on `/if/admin`, admin account with passkey, no operator reuse of the family realm for infrastructure.
- **Jellyfin transcoding** is CPU on Talos VMs; direct-play first, GPU is a separate decision.
- **PVE/PBS OIDC realms are hand-configured** (bpg has no realm resource) — runbook steps, not IaC, per ADR 0005's precedent.
