## Decisions (ADR 0036 — interview settled 2026-08-23)

1. **Whole stack moves; 12 of 14 containers.** `kubernetes/monitoring/` (namespace `monitoring`): one Deployment (`Recreate`) per former container, Services named as the compose services were (`openobserve`, `prometheus`, `alertmanager`, `blackbox`, `speedtest`, `smokeping-prober`, `proxmox-exporter`, `snmp-exporter`, `unifi-poller`, `pbs-exporter`, `grafana`, `uptime-kuma`, `axosyslog`) so the configs keep their in-cluster targets unchanged. **Dropped:** node-exporter (host metrics of a host that no longer exists; the fleet reports via telegraf) and the modem-scraper cron (the modem is unreachable on every run); the `isp` rules + dashboard stay as the spec (ADR 0011 precedent). **Dropped with the guest:** portainer-agent, telegraf/rsyslog on 203, the UptimeRobot heartbeat cron (re-homed as a CronJob — one `curl` to the Infisical URL, keeps the outside-in dead-man signal).
2. **axosyslog = MetalLB LB on services offset 66**, `externalTrafficPolicy: Local`, one mixed-protocol Service (5514/udp, 5514/tcp, 5515/udp, 6514/tcp). Source IP preserved → the `netconsole` stream's `host` stays the sender. `group_vars/all.yml`: `monitoring_syslog_offset: 66`, `openobserve_listen_host: "{{ services_vlan_prefix }}{{ monitoring_syslog_offset }}"`.
3. **UIs via Traefik**: `grafana.<d>`, `openobserve.<d>`, `prometheus.<d>`, `alertmanager.<d>`, `uptime-kuma.<d>` — plain Ingresses, AdGuard rewrites to `.65` from `deploy.sh`. `GF_SERVER_ROOT_URL` = the Grafana hostname.
4. **State**: PVCs `openobserve` 60 Gi, `prometheus` 10 Gi, `grafana` 2 Gi, `uptime-kuma` 2 Gi, `alertmanager` 1 Gi (ceph-rbd, RWO, expandable); `fsGroup` 65534 / 472 where the image runs unprivileged. **Migration** = `make monitoring-migrate`: scale the stack to 0, run a throwaway `migrate` pod mounting all five PVCs with a one-off ssh key (installed into 203's `authorized_keys` for the duration), `rsync -aH --delete` each tree from `root@203:/var/lib/monitoring/<svc>/` while 203's compose is **down** (workstation-driven `docker compose down` on 203 — never from inside another ssh session), then remove the key and the pod, scale up. Holder volume idx 3 stays attached to the stopped 203; its `data_volumes` entry stays (never renumber).
5. **Secrets**: one `InfisicalSecret` `monitoring` → managed Secret `monitoring-secrets` with `template.data`: `GF_SECURITY_ADMIN_PASSWORD`, `ZO_ROOT_USER_PASSWORD`, `PVE_TOKEN_VALUE`, `UP_UNIFI_DEFAULT_PASS`, `PBS_API_TOKEN`, `openobserve_root_user_pass` (axosyslog backtick env + Prometheus `password_file` via a Secret volume item), `alert-ntfy-url` (`https://ntfy.sh/<topic>?template=alertmanager`, Alertmanager `url_file` via the same volume), `UPTIMEROBOT_HEARTBEAT_URL`. `secrets.infisical.com/auto-reload` on every Deployment that consumes it. Generators for `grafana_admin_password` / `openobserve_root_user_pass` move to the `monitoring_users` role.
6. **Images** `${REGISTRY}/…` for all 12 (`public.ecr.aws/zinclabs/openobserve:v0.92.0-rc2-amd64` pin unchanged — Zot `values.yaml` gains a `public.ecr.aws` sync entry, re-applied by `make talos-registry`); `renovate.json` custom manager repointed at `kubernetes/monitoring/app.yaml`.
7. **Configs** (`kubernetes/monitoring/config/`): `prometheus.yml`, `alert.rules.yml`, `alertmanager.yml`, `blackbox.yml`, `snmp.yml`, `axosyslog.conf` (no Jinja: user + password via backtick env), Grafana datasource/dashboards provisioning + the nine dashboard JSONs (one ConfigMap; smokeping dashboard rendered by `deploy.sh` from `smokeping_targets`). `deploy.sh` extends `inv_env` with `PVE_API_HOST` (from `vars.auto.tfvars`), `SYNOLOGY_SNMP_COMMUNITY`, `SMOKEPING_ARGS`, `BIND_VIP`, the blackbox-dns zone list and a `file_sd` JSON of every `vms.yaml` guest (+ `vps` tunnel address from `group_vars/local/all.yml`) at `:9273` → no hand-kept telegraf list. Blackbox self-checks target the ingress hostnames with `http_2xx_insecure` (homelab-ca is not in the prober's trust store). `proxmox` job → `${PVE_API_HOST}` (the VIP), fixing the standing 500.
8. **`monitoring@pve` fix**: `make monitoring-users` = `infrastructure.yml --tags monitoring-users` with `-i proxmox.yaml -i vms.yaml`, so `proxmox_host` resolves to a live node; the role creates the user, PVEAuditor ACL, token `monitoring`, and writes `/monitoring/proxmox_token_value` (operator auto-reload propagates it to proxmox-exporter and the homepage widget).
9. **Fleet follows the address**: `make ansible-infra TAGS=monitoring` (rsyslog/telegraf on infra guests), `make ansible-services` (docker/plex-services daemon.json + rsyslog), `make vps-ansible`, `host-bindings.yaml` → `make proxmox-hosts TAGS=logging` (3 nodes, rsyslog + netconsole), pfSense via `ansible pfsense -m pfsensible.core.pfsense_log_settings -a 'remoteserver=<lb66>:5514 …'` (ad hoc from `inventory/pfsense.yaml`), **UniFi remote syslog + netconsole = operator UI step** (Settings → System → Advanced → Remote logging: syslog `<lb66>:5514`, netconsole `<lb66>:5515`).
10. **Kuma**: the five monitors that targeted 203 (Grafana, OpenObserve, Prometheus, Alertmanager, AxoSyslog) get their `url`/`hostname` updated in the migrated `kuma.db` before Kuma starts (sqlite, the seeder's mechanism); `docs/uptime-kuma-monitors.md`, the example JSON and the gitignored JSON follow; `seed_uptime_kuma.py` documents its `kubectl exec` invocation. The AxoSyslog monitor targets `<lb66>:5514`.
11. **Retire 203** exactly as 211: `pct stop 203` + `onboot 0`, `terraform state rm module.vms.proxmox_virtual_environment_container.containers["openobserve"]`, drop from `vm-configs.tf` + `backup_jobs` (`make backup-jobs`), delete `roles/monitoring`, `roles/openobserve_dashboards`, the openobserve play + `openobserve` tag + Phase-2 host entry, the seven agent templates, `docker-config.yml` section, `update-all.yml`/`refresh-identity.yml` hosts, `adguard_rewrite_vms` entry, telegraf `'openobserve'` branches, `juju4.openobserve`; `test_axosyslog_routing.py` renders the k8s config.
12. **Not in scope**: kube-prometheus / Talos node metrics; PTR + `use-dns(yes)` on the netconsole source; the Infisical PKI swap; the `uptime_kuma` collection adoption (operator's gap report).

## Sequencing

1. Zot sync entry → `make talos-registry`; `kubernetes/monitoring/` written; `make talos-monitoring` deploys with **empty PVCs** first (stack comes up green against nothing) → Ingress + LB + InfisicalSecret verified. Grafana/OO/Prometheus/Kuma at the new hostnames; 203 still serves the fleet.
2. `make monitoring-migrate`: 203 compose down (from the workstation), rsync into the PVCs, Kuma rows repointed, stack up → OO history query (< 2026-08-23) returns rows; Grafana dashboards + Kuma monitors present.
3. Repoint senders: `all.yml` + fleet rollouts, `host-bindings.yaml` + `make proxmox-hosts TAGS=logging`, pfSense ad hoc, operator UniFi step → fresh syslog line from a guest + `<3>` kmsg from a node land at the new address. `make monitoring-users` → `proxmox` job UP, homepage PVE widget green.
4. Alertmanager test (`amtool`/POST to `/api/v2/alerts`) → ntfy; Kuma test notification.
5. Retire 203 + cleanup, `make plan` + `make talos-plan` clean; docs; small commits per row.

## Risks

- Mixed-protocol LB Service: GA since k8s 1.26, MetalLB honours it; if the speaker refuses, split into two Services sharing the IP (`metallb.io/allow-shared-ip`).
- `externalTrafficPolicy: Local` + L2: the IP is announced only from the node running the axosyslog pod; a pod move re-announces (gratuitous ARP) — senders see a few seconds of loss, same as a container restart today. TCP rsyslog senders retry (`resumeRetryCount=-1`).
- OpenObserve schema pin: the DB moves byte-for-byte; the pod runs the same rc2 image. Never start a different tag against the migrated PVC.
- Prometheus TSDB copied while stopped → consistent; `--storage.tsdb.path` unchanged layout.
- Kuma `kuma.db` + WAL copied while stopped; row edits before first start.
- Until each sender is re-rolled its lines are lost, not queued (UDP) — sequence 3 is one sitting.
- Homepage `${OPENOBSERVE}` breaks when the host leaves `vms.yaml` — fixed in the same commit (hostnames).
