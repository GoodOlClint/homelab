# ADR 0040 — P5: real DNS on a flat public-domain zone (BIND fed by nsupdate + external-dns, AdGuard forwards, rewrites retired), Let's Encrypt DNS-01 wildcards as Traefik's default cert, two authentik realms split by audience, Jellyfin over the VPS relay with LDAP auth

- **Status:** Accepted (operator, 2026-08-24)
- **Date:** 2026-08-24
- **Deciders:** operator + agent (session 2026-08-24)
- **Context source:** session 2026-08-24 DNS map (live AdGuard/BIND probe) · [ADR 0006](0006-dns-names-are-the-access-layer-static-ips-remain-iac-plumbing.md) · [ADR 0007](0007-hybrid-cert-model-infisical-pki-for-the-fleet-le-wildcard-for-browser-facing.md) · [docs/p5-dns-sso-jellyfin-plan.md](../p5-dns-sso-jellyfin-plan.md)

## Context

ADR 0006 decided that every guest, node and service gets a DNS record generated from the IaC inventory, served by BIND, with AdGuard forwarding the internal zones — and rejected hand-curated AdGuard rewrites as the access story. It was never implemented: the live probe found BIND's seven per-VLAN zones holding one record each (`ns`) and **all 43 internal names answered by AdGuard rewrites**, ten of them pointing at retired guests. ADR 0007 decided browser-facing UIs get a Let's Encrypt wildcard over Cloudflare DNS-01 so unmanaged devices need no root install; it was deferred behind WP8, which landed the fleet CA (ADR 0039) but left every cluster UI on `homelab-ca` with `ignore_tls` scattered through the monitors.

Two new forces: the internal suffix the `.internal` suffix (`domain_suffix`) is ICANN-reserved private space, so no public CA can ever sign it — which blocks passkeys/WebAuthn and forces the internal CA onto every browser; and the operator wants SSO (authentik) so that credentials stop being per-app, with Jellyfin for friends and family as the first external consumer. Two realms are wanted: one internet-facing for media, one LAN/VPN-only for infrastructure. The operator owns an empty public domain on Cloudflare for the internal namespace and already serves media under a second public domain through Cloudflare (tunnel) and the VPS relay.

The domain is one knob today (`vlans.yaml` `domain_suffix` → `nodes.json .domain` → every `kubernetes/*/deploy.sh`, `dns_zones` for AdGuard/BIND/`dns_config`/telegraf), so a one-shot flip is possible but not bisectable.

## Decision

1. **The internal namespace is a flat zone on an operator-owned public domain** (`<service domain>`, a `vlans.yaml` binding like `domain_suffix`; never a literal in a tracked file — the guardrail protects it the same way). `name.<service domain>` is the address of the service: for fleet guests the `service_ip`, for nodes the mgmt address, for cluster apps the Traefik LB. The per-VLAN forward zones and their `<vm>.<vlan>.` naming retire once nothing references them; the per-VLAN **reverse** zones stay and finally get PTR records.
2. **BIND is authoritative and every record is a dynamic update, never a rendered zone file:** fleet + node + VIP records pushed idempotently from the inventory by Ansible (`community.general.nsupdate`, the existing TSIG key) — ADR 0006's "generated from the IaC inventory" — and cluster hostnames pushed by **external-dns (RFC 2136)** from `Ingress`/`Service` objects. The zone file stays the initial-only SOA/NS shell the role already writes, so templates never fight the journal. AdGuard keeps filtering and gains one conditional forward per zone; its rewrite list goes to zero and `make adguard-rewrite` is deleted.
3. **Split horizon by omission, public records mirrored inward:** the public copy of `<service domain>` on Cloudflare holds only the records that must be reachable from outside (today one: `vpn` → the WAN address, the WireGuard endpoint) plus transient `_acme-challenge` TXT. Because BIND is authoritative for the whole zone internally, every public record is also pushed into the internal zone by the same `nsupdate` task from the same binding (`vlans.yaml` `public_records`), and Terraform owns the Cloudflare copy from that binding — one source, two views. Internal names resolve only through AdGuard → BIND (ADR 0012's chain); a client bypassing AdGuard gets NXDOMAIN for them, by design.
4. **Let's Encrypt via cert-manager DNS-01 (Cloudflare) issues Traefik's default certificate** — one `Certificate` with `*.<service domain>` and `*.<media domain>` — replacing `homelab-ca` for everything browser-facing (ADR 0007's wildcard, ADR 0035's single default TLS store unchanged). `homelab-ca` (ADR 0039) stays the fleet/internal CA: the registry, node/guest certs, mTLS. The Cloudflare DNS token moves to Infisical `/infrastructure` (it is a DNS credential, not a Plex one) and reaches cert-manager through an `InfisicalSecret`.
5. **Two authentik instances, split by audience, on the cluster:** `auth.<media domain>` (namespace `authentik-ext`, reached through the Cloudflare tunnel, users = family + operator, consumers = Jellyfin via the LDAP outpost + Seerr via Jellyfin accounts) and `auth.<service domain>` (namespace `authentik`, LAN/VPN only, users = operator, consumers = OIDC where native — Grafana, PVE, PBS, Portainer, MeshCentral, PDM — and Traefik forward-auth via the proxy outpost for the arr stack, Homepage, Uptime Kuma, Kiwix, Tautulli). Each has its own Postgres + Redis on ceph-rbd PVCs, its own Infisical folder, and a PBS `pg_dumpall` CronJob (ADR 0037's lane).
6. **Jellyfin rides the Plex lane, not the tunnel:** `kubernetes/jellyfin/`, media over the same kubelet-mounted NFS PV as the arr stack (ADR 0037), auth = LDAP against the external realm (works on every client, TV apps included; the SSO plugin is a web-only bonus), external path = Cloudflare unproxied A record → VPS DNAT 443 → pfSense → Traefik with the LE cert. CPU-only transcoding until a GPU decision exists.
7. **Rollout is additive:** new zone, cert and hostnames land beside the old ones; rewrites are deleted per name once the new name answers; the `.internal` suffix (`domain_suffix`) retires as the last phase by flipping `domain_suffix`. No phase requires the previous names to be gone.

## Rejected alternatives

- **Flatten under the existing suffix (`service.<domain_suffix>`) or a sub-zone of the primary public domain.** Neither fixes the password-manager grouping (Safari matches on the registrable domain, depth is irrelevant) and `.internal` cannot get a public cert. A sub-zone of a domain with public records means mirroring those records internally; the empty domain has nothing to mirror.
- **Keep AdGuard rewrites but generate them from the inventory.** Already rejected by ADR 0006; rewrites are per-resolver state with no PTR, no zone transfer, and no API contract external-dns can use.
- **Render BIND zone files from templates.** The role deliberately writes zone files initial-only because DDNS (pfSense) journals them; a templated file and a journal fight on every run. Dynamic updates for everything is the only shape where inventory records, external-dns and DHCP DDNS coexist.
- **external-dns for the fleet too (Ansible-free).** external-dns only sees cluster objects; fleet guests live in Terraform/Ansible. Two writers to one zone is fine when their record sets are disjoint (owner TXT records on the external-dns side).
- **One authentik instance with two brands.** One user DB and one admin surface behind the internet-facing door; a compromise of the media realm would grant infrastructure SSO. Two instances cost one duplicate operator account.
- **Jellyfin through the Cloudflare tunnel.** Direct-play bitrates through Cloudflare's proxy hit their non-HTML streaming limits; Plex already avoids the tunnel for the same reason.
- **Jellyfin web SSO only (OIDC plugin, no LDAP).** The plugin needs a browser flow; Roku/Android TV/Swiftfin cannot do it, and those are the family's clients.
- **One-shot `domain_suffix` flip.** Would rebuild AdGuard, BIND, Traefik and every Ingress in one window with no way to bisect a failure.
- **Retire `homelab-ca` entirely now that LE exists.** The registry's cert is pinned into Talos `machine.registries` and the fleet root distribution (ADR 0039 follow-on) is the mTLS story; LE wildcards share one key across every host (ADR 0007's reason to keep both planes).

## Consequences

- Implements ADR 0006 and ADR 0007's wildcard half; amends ADR 0035 (hostnames are DNS records, not rewrites; the default cert is LE) and ADR 0029 (AdGuard's rewrite variables and `make adguard-rewrite` go away). ADR 0012's chain is unchanged — AdGuard-first is now load-bearing for name resolution, not just poisoning.
- New tracked surfaces: `kubernetes/external-dns/`, `kubernetes/authentik/` (both realms), `kubernetes/jellyfin/`, an `nsupdate` task in the fleet plays, `vlans.yaml` `service_domain` + `media_domain` bindings, a second Cloudflare zone in Terraform (media A record for Jellyfin on the VPS, DNS-01 for both zones). Infisical folders `/authentik`, `/authentik-ext`; `cloudflare_dns_api_token` re-homed to `/infrastructure`; the dead `/docker` `authentik_*` keys deleted.
- Forbidden from now: adding an AdGuard rewrite for anything; an `ignore_tls` on a monitor of a Traefik-fronted app; a per-app local password where OIDC or forward-auth exists.
- If the WAN address is dynamic, `vpn` cannot be a static binding: the public copy then stays DDNS-owned (pfSense → Cloudflare) and the internal mirror is refreshed by the same DDNS client against BIND, or the record is excluded from Terraform. Settled at P5a from the operator's answer.
- P5e (2026-08-25) closed the amendments: ADR 0035's legacy Ingress host rule, `legacy-tls` and the 302 path are gone; ADR 0029's `dns.<vlan zone>` rewrites are gone and the resolver VIP tracks the instance's own hostname (served from `/etc/hosts` by AdGuard, so the VIP never depends on BIND — `dns.<service domain>` was rejected for that reason); the AdGuard role converges the whole upstream list and deletes every rewrite on each run. `domain_suffix` survives in `vlans.yaml` for exactly one consumer — the VM fleet's cloud-init `fqdn` (a changed snippet replaces every VM, ADR 0016) — and names no zone; it retires with the next deliberate VM roll. The registry is `registry.<service domain>`; `nodes.json .domain` is the service domain.
- Open after P5: the fleet root-distribution role and per-host ACME (WP8 leftovers), GPU transcoding for Jellyfin, pfSense DHCP `domain`/DDNS for clients (server side proven; the role now says `<service domain>` but is hand-run), AAAA records (ADR 0010's ULA is not yet in the inventory output).
- P6 (2026-08-25) retired `domain_suffix` entirely: cloud-init `fqdn` is `<name>.<service domain>` (module variable `service_domain`), the key is gone from `vlans.yaml`, the example, the network output and the guardrail (which keeps blocking the service and media domains); all six VMs answer `hostname -f` on the service domain.
