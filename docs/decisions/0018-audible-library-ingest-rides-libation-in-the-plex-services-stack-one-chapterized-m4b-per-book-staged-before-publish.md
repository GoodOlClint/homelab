# ADR 0018 — Audible library ingest rides Libation in the plex-services stack; one chapterized M4B per book, staged before publish

- **Status:** Proposed
- **Date:** 2026-08-02
- **Deciders:** operator + agent
- **Context source:** session 2026-08-02 (brownfield gate) · docs/libation-audiobook-sync-plan.md

## Context

Audiobooks purchased on an Audible subscription are not in the Plex library, and the process that used to put them there was manual: a GUI desktop app (OpenAudible) logged into the Audible account, synced and converted purchases to M4B, then the operator split each book on chapter marks and copied the result to the NAS by hand. Nothing about that pipeline is reproducible, nothing runs unattended, and the library drifts behind the account with every purchase.

The fleet already owns every part of the landing zone. `plex-services` is a docker-LXC guest running the arr stack from one compose template; the media tree is the Synology export reached at `/data/media/{TV,Movies,Music}`; SABnzbd already stages downloads on a local scratch disk precisely so half-written files never reach the library; and `plex` scans the same tree. What is missing is the ingest step — a thing that authenticates to Audible, notices new purchases, and lands finished files in the tree.

Two constraints shape the answer more than the tool choice does. Audible authentication is adversarial to automation: any client can be challenged with CAPTCHA, MFA, or device re-registration at any time, so no design can promise permanent unattended auth — only that a failure is loud rather than silent. And the fleet is mid-migration: ADRs 0003/0015/0017 move `plex-services` to a static-IP docker-LXC whose media arrives via **host bind mounts** rather than per-guest NFS Docker volumes, with durable state on a detached Ceph data volume. Anything built against the live NFS-volume model is built against a model with a known expiry date.

## Decision

**Audible ingest is Libation (`rmcrackan/libation`), running as one more service in the `plex-services` compose stack.** It is the only candidate built for headless operation: a real CLI (`LibationCli`) with `scan`/`liberate`/`login-external`, an official Docker image, a `SLEEP_TIME` poll loop, and library-state tracking that survives restarts. It joins the `plex_services` host_vars dict like every other service, taking the next free UID (2013); the role's per-service loops for config dirs and system users pick it up automatically, and the arr-specific loops skip it because they are gated on `db_user`/`config`.

**One chapterized single-file M4B per book — never per-chapter split files.** Chapters ride as embedded metadata. Splitting makes Plex treat each chapter as a separate track, which fragments matching, ordering, resume position, and cover art, and multiplies file count by roughly the chapter count for no playback gain on clients that read embedded chapters. Libation's per-chapter splitting setting stays off.

**Writes are staged, not direct.** Libation downloads and converts onto local scratch; only completed book directories are published to `/data/media/Audiobooks`. This is the existing SABnzbd `incomplete_dir` precedent applied to the same failure: Plex must never scan a partially written M4B, and a storage stall mid-conversion must not leave debris in the library.

**Libation runs as a persistent container on a `SLEEP_TIME` poll**, `restart: unless-stopped`, matching every other container in the stack rather than introducing a cron-driven one-shot idiom. Poll interval is hours, not minutes — Amazon offers no compatibility guarantee to unofficial clients and there is nothing time-critical about a book purchased today appearing tonight.

**The image is pinned via a `libation_image` role default.** This is not a new policy: [ADR 0016](0016-guest-os-images-are-pinned-and-deliberately-rolled-container-tags-stay-latest.md) already permits pinning an individual image on a demonstrated compatibility break, and `renovate.json`'s existing `customManager` auto-enrolls any `*_image:` pin in a role default under the `pin-review` label. The break here is documented upstream: a CLI-only Libation install does not run every post-upgrade migration, so an unattended `latest` roll can wedge on a migration that only the desktop GUI completes. If that caveat proves not to bite, the pin retires and the image returns to `latest` under the same ADR 0016 convention.

**Implementation is deferred to the post-MS-01 cutover (WP7).** The design lands on the ADR 0017 host-bind-mount model with Libation's config and database on the ADR 0015 data volume alongside the arr configs — not on the `plex_data` NFS Docker volume that retires at cutover. The one-time interactive Audible login is done once, against the final guest.

## Rejected alternatives

- **OpenAudible.** The app the operator already knows, and the one this replaces. Its Docker image is the desktop GUI inside a browser-accessible Linux desktop — upstream calls it experimental and it ships with no password protection by default. Automating it means driving a remote desktop, which cannot be expressed as a compose service under Ansible. Conversion and chapter splitting also sit behind a paid license.
- **`audible-cli` + ffmpeg/m4b-tool pipeline.** Maximum control over codecs, tags, naming, and validation — purchased by owning state tracking, locking, retries, dedup, alerting, and atomic publish as first-party code. That is a software project, not a service, and nothing about the requirement justifies it. Revisit only against a concrete requirement Libation demonstrably cannot meet.
- **`AAXtoMP3`.** Converts existing AAX/AAXC with per-chapter output, but does not authenticate or sync — something else still has to fetch the files — and upstream archived the repository in April 2023. Not a foundation for a new unattended system.
- **Per-chapter split files.** What the operator did by hand previously, and natively supported by Libation. Rejected on Plex behavior, not effort: split chapters become separate tracks in a Music-type library, and the file-count multiplier is real at library scale.
- **Writing direct to `/data/media/Audiobooks`.** One fewer moving part, and Libation manages its own temp files. Rejected because the failure it invites — Plex scanning a partial file, or a stalled mount stranding a half-converted book in the library — is exactly the one the stack already pays a scratch disk to avoid for SABnzbd.
- **Cron-driven one-shot runs** (`SLEEP_TIME=-1`, the image default). Cleaner run boundaries and a real exit code to alert on. Rejected as an idiom divergence: every other container in this stack is a long-running `restart: unless-stopped` service, and failure visibility is better bought with an explicit health signal than with a second scheduling mechanism.
- **A new ADR amending the container-tag rule.** ADR 0016 already decided this — blanket container pinning rejected, individual pins permitted on demonstrated break, with the OpenObserve schema pin as the worked example. Writing a second ADR would re-litigate a settled decision.
- **A standalone `AudibleSync` repo.** Duplicates the NFS/secrets/deploy plumbing this repo already has for a service whose entire definition is a compose block plus a host_vars entry.
- **Building against the live NFS-volume model now.** Working audiobooks sooner, at the cost of writing volume and mount lines with a known expiry at WP7 and doing the interactive Audible auth bootstrap twice.

## Consequences

- **Nothing is implemented until WP7.** This ADR and the plan doc are the artifact; the compose block, host_vars entry, role defaults, and Infisical wiring land with the rest of the WP4 service definitions.
- **A new Infisical secret is needed under `/plex-services`** (folder already owned by the `plex_services` role): Libation's account-database master key, delivered by the Infisical agent as an `env_file` per the no-baked-secrets rule. The encrypted account database itself is state on the data volume, not a secret in Infisical.
- **A one-time interactive bootstrap is accepted and not automatable.** `LibationCli login-external` prints a URL the operator completes in a browser, pasting the redirect back. This runs once against the final guest and is a documented step in the runbook, not a task in the role.
- **Re-authentication must fail loudly and must not retry-loop.** Amazon can demand a fresh interactive login at any time — after a password change, a device revocation, or an opaque risk challenge. The design commits to a visible alert on repeated auth failure via the existing ntfy channel ([ADR 0011](0011-two-alerting-lanes-uptime-kuma-for-reachability-alertmanager-for-metrics.md)), never to aggressive retry against an account-lockout surface.
- **A scratch/staging path must exist on the post-cutover guest.** `docs/rebuild-as-routine-design.md` assigns `plex-services` a data volume for arr postgres and app configs but does not carry the current scratch disk forward. Staging is by definition disposable and belongs on the disposable rootfs or a local path — but the path has to be named in WP4, not assumed.
- **`/data/media/Audiobooks` becomes a fleet path**, following the existing `/data/media/{TV,Movies,Music}` convention, with a new Plex library of type Music pointed at it.
- **Audnexus is a fragile dependency, deliberately taken.** It is a third-party *legacy* Plex plugin agent. **Verified 2026-08-02:** it is already installed and bound to the existing Plex Audiobooks library (section 11, type `artist`, path `/mnt/media/Audiobooks`), so WP7 repoints that section rather than creating a new library — the "can a legacy agent still be attached" risk is sidestepped rather than resolved. Metadata degrades to embedded tags and local cover art if it ever breaks; that is an acceptable floor, so Audnexus is an enhancement and never a precondition for ingest.
- **The playback client is Prologue** (iOS, free with a one-time $9.99 Premium IAP), which reads embedded chapters natively — confirming the single-file decision against a real client rather than an assumed one.
- **This ADR's choice of Plex as the playback surface is under open review.** 21 of the 228 books carry companion PDFs that a Plex Music library cannot represent at all, while Audiobookshelf handles them natively and would retire the Audnexus dependency outright. Parked for a deliberate WP7 decision and scoped in the plan doc; if it resolves toward Audiobookshelf, this ADR is partly superseded. **The ingest half — Libation, single-file chapterized M4B, staged writes, ASIN in the path — is unaffected either way, because the same archive serves both backends.**
- **Folder naming carries the ASIN** (`Author/Title [ASIN]/`), for two independent reasons: Audnexus quick-match, and Libation's own already-downloaded detection, which relies on the Audible ID being present in the path. Losing the ASIN risks re-downloading the library.
- **Storage growth is unbounded by design and must be watched.** A large library runs to hundreds of GB, and the decision of whether to retain the original encrypted AAX/AAXC alongside the liberated copy roughly doubles that. Free space on both the media export and the data volume is a monitored quantity, not an assumption.
- **Subscription-catalog titles are out of scope.** Only purchased/owned titles are archived; temporary catalog access must not silently become a permanent local library.
- **Legal boundary, recorded deliberately.** This removes access controls on the operator's own purchased content for personal archival on a private server. Files are never shared or redistributed. Anti-circumvention law is analytically separate from infringement and varies by jurisdiction; this is a recorded operator decision, not legal advice.
