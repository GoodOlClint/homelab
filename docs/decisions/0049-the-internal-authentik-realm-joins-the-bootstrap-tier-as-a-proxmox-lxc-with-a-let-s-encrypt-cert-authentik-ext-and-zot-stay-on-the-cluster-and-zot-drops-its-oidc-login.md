# ADR 0049 — The internal authentik realm joins the bootstrap tier as a Proxmox LXC with a Let's Encrypt cert; authentik-ext and Zot stay on the cluster and Zot drops its OIDC login

- **Status:** Accepted (approved 2026-09-09)
- **Date:** 2026-09-09
- **Deciders:** operator + agent
- **Context source:** brownfield gate + council round 2, 2026-09-09, [docs/kubernetes-iac-plan.md](../kubernetes-iac-plan.md); amends [ADR 0031](0031-a-three-node-talos-kubernetes-cluster-becomes-the-services-plane-and-the-bootstrap-tier-stays-on-proxmox.md) and [ADR 0040](0040-p5-real-dns-on-a-flat-public-domain-zone-bind-fed-by-nsupdate-external-dns-adguard-forwards-rewrites-retired-let-s-encrypt-dns-01-wildcards-as-traefik-s-default-cert-two-authentik-realms-split-by-audience-jellyfin-over-the-vps-relay-with-ldap-auth.md) §P5c; consequence of ADR 0043

## Context

authentik's internal realm runs on the Kubernetes services plane and is the identity provider for bootstrap-tier systems — Proxmox VE, PBS, PDM, Portainer, MeshCentral, Synology, Home Assistant today, pfSense once ADR 0043 is implemented. That points a dependency from the layer that hosts the cluster up into the disposable layer, against the rebuild-as-routine axiom. On the cluster, Zot / Traefik / authentik also form a cold-start cycle (hit twice on 2026-09-09): Zot panics at startup when its OIDC discovery against authentik fails, and Traefik and authentik pull their images through Zot. Verified while planning: Zot's `openid` block is web-UI login only (push is htpasswd, pull anonymous); Talos carries no registry mirror stanza, so Zot is not on any node's cold-start path; `plex_certificate` already runs certbot + `dns-cloudflare` for a Let's Encrypt cert on a Proxmox guest; external-dns runs `policy: sync`; the external realm (`authentik-ext`, Cloudflare tunnel, LDAP outpost for Jellyfin, family accounts) has no bootstrap-tier consumer. The operator offered to move mission-critical services onto Proxmox.

## Decision

- **The internal authentik realm becomes a Proxmox LXC in the bootstrap tier**, built by the existing pipeline: Terraform `type = "lxc"`, `name = "authentik"`, single-homed on the services VLAN (ADR 0017 — its vlan30/vlan10 consumers already reach `auth.<service domain>` on the vlan40 ingress, so no new firewall rule), `keyctl = true`, a holder data volume on the next free slot (ADR 0015/0020; `make data-volumes` before `make build`, never one apply), HA per the fleet policy of the day. An `authentik` Ansible role in the `control` pattern: compose with **Caddy on 80/443 terminating TLS** (the `infisical` role's shape) in front of server, worker, `postgres:17` and the embedded outpost; blueprints applied from a mounted `/blueprints` directory (retires the ConfigMap-hash-wait code); Infisical agent env files with hex-only values; the role **reads** `secret_key` and `postgres_password` from `/authentik` and never generates them; upstream image refs; nightly `pg_dumpall` → PBS ns `databases`. Same hostname `auth.<service domain>`, same database, same `secret_key` — no consumer's issuer or redirect configuration changes.
- **The cutover is a quiesced point-in-time move, not a nightly-dump restore.** Rehearse on worklab (pinned to the running authentik and Postgres majors), destroy the rehearsal copy; scale server + worker to 0 with Postgres running, take an on-demand final `pg_dumpall`, verify, restore into the LXC, validate against the LXC directly before any DNS change. Rollback inside the window is a **reverse dump** from the LXC into the cluster realm — the two databases diverge at the first login, so "scale the old copy back up" is not a rollback. The cluster PVC is kept a week, then deleted and the RBD image verified gone.
- **The DNS handoff must transfer external-dns ownership.** external-dns owns `auth` through its TXT registry record; an nsupdate A written beside it is overwritten every minute and deleted with the Ingress. Order: exclude the Ingress from external-dns (annotation) or suspend it → delete the Ingress → verify the ownership TXT is gone → `make dns-records` writes A + PTR (`dns_records.yml` gains an alias map: hostname `authentik`, record `auth`) → clear both AdGuard caches → resume external-dns and prove it leaves `auth` alone.
- **The `authentik-forward-auth` Middleware moves into a Flux-managed `traefik` tree before the cutover**, same qualified name (every protected Ingress references it), only its `address` changing to the public hostname. Never remove a forward-auth annotation as an outage workaround — it is the only control on Headlamp, Prometheus and Alertmanager; audit S8 (the application's policy binding) lands first.
- **Its certificate is Let's Encrypt** through a `dns-cloudflare` variant of `cert_client` (fold `plex_certificate` in, keeping its PFX-staleness re-hook — audit X4), deploy hook = Caddy reload, so unmanaged browsers and phones trust it without Traefik in front. A fleet-CA cert is not acceptable here. The target is a **dedicated Cloudflare token scoped to the service zone's ACME challenge**, because the identity box must not become a public-DNS takeover point. **Operator decision 2026-09-09: build with the shared `/infrastructure/cloudflare_dns_api_token` for now; the operator creates the dedicated token later and the role swaps to it** — tracked in the plan as owed work, the risk accepted knowingly in the interim.
- **`authentik-ext` stays on the cluster.** Its dependency direction is already correct.
- **Zot stays on the cluster and its `openid` block is deleted** — together with the `zot` OIDC provider in the internal blueprint, `zot_oidc_client_secret` and the `oidc-credentials.json` Secret item, in one commit. The machine path is unchanged; the web UI becomes a single shared htpasswd account with no MFA or per-user attribution, and anonymous read on `**` stays. With that edge gone the cold-start cycle no longer exists, so no `machine.registries` change and no registry LXC.
- **Secrets for the LXC realm are hex-only** — the Infisical agent renders docker `env_file` syntax, and a base64 `+` in a value is the bug that killed the previous compose authentik.

## Rejected alternatives

- **Zot as a Proxmox LXC** (four council advisors) — overruled on the verified facts: Zot is not on the cold-start path once its OIDC login goes, and ADR 0021 already ruled a cache is an accelerator, never a bootstrap dependency. Revisit only if a registry mirror stanza is ever added to the Talos config.
- **One LXC for authentik + Zot** — recreates a mini-cycle in one box and couples unrelated rebuild cadences.
- **Moving both realms** — the external realm has no bootstrap-tier consumer; moving it buys nothing and doubles the cutover.
- **Running both realms live and repointing consumers one at a time** — impossible at one hostname; the OIDC issuer URL is the identity, so the move is a record flip with the cluster realm scaled to 0 (never deleted until a week has passed).
- **Fronting the LXC with Traefik for the LE wildcard** — recreates the cluster dependency for every issuer callback.
- **Patching Zot with a lazy/optional OIDC option** — a structural fault kept alive by an untested knob.

## Consequences

- ADR 0031's bootstrap tier gains authentik (internal realm); ADR 0040 §P5c is amended for that realm; ADR 0043's dependency deepens no further — pfSense SSO can land safely after this.
- The cutover is the plan's single biggest failure mode: a restore with a mismatched `secret_key` or stale `authentik_host`, or a DNS handoff that leaves external-dns's TXT in place, breaks every OIDC consumer at once. Mandatory: every break-glass login proven the same hour — PVE/PBS/PDM `@pam`, Portainer internal auth, MeshCentral local admin (proven live, not inferred from config), Synology, HA; **Grafana has no login form** (`GF_AUTH_DISABLE_LOGIN_FORM` + auto-login — recovery is flipping the env and restarting, documented); forward-auth-only surfaces are simply unreachable during an outage; a `root@pam` shell open throughout. The rehearsal copy on worklab holds the production identity database for its window — treat it as production-tier and destroy it afterwards.
- Infisical `/authentik` gains an Ansible **reader** (the agent); its keys keep their existing generation and are never regenerated by the role. `kubernetes/authentik/` keeps only the external realm, whose LDAP outpost objects are created by authentik and stay outside Flux.
- Kuma row, homepage tile and Grafana OIDC issuer are unchanged (same hostname). The forward-auth Middleware's `address` moves from svc DNS to the public hostname, which puts the AdGuard VIP, the BIND pair and the LXC in the auth path of every Traefik-fronted app — accepted: those are bootstrap-tier services, which is the dependency direction this ADR exists to establish.
- `dns_records.yml` gains an alias facility (it derives names only from inventory hostnames, VIPs and MetalLB offsets today) and documents that external-dns must not own `auth`.
- Zot's web UI is htpasswd-only; `zot_oidc_client_secret` and the `zot` OIDC provider come out of the internal blueprint.
