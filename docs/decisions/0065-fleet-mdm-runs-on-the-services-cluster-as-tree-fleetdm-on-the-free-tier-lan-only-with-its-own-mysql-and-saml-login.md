# ADR 0065 — Fleet MDM runs on the services cluster as tree fleetdm on the free tier, LAN-only, with its own MySQL and SAML login

- **Status:** Accepted
- **Date:** 2026-11-23
- **Deciders:** operator + agent
- **Context source:** operator session 2026-11-23 ("add fleet to our homelab and get it ready to manage the studios … useful for Windows VM management down the road"); [plan](../fleetdm-plan.md); the Mac runner notes in [docs/ci-cluster-plan.md](../ci-cluster-plan.md#mac-runner-notes-for-its-own-plan), which named self-hosted Fleet as the first MDM candidate

## Context

The Mac Studios are managed by hand over SSH and screen sharing. The M5 Studio serves oMLX to the operator's apps; the M4 Studio is being rebuilt as a CI runner host ([ADR 0061](0061-the-m4-mac-studio-is-rebuilt-as-a-ci-runner-host-with-disposable-vms-for-pull-request-jobs-and-bare-metal-for-trusted-branch-gpu-jobs.md)), whose plan expects an MDM server to push its privacy-permission profile, VM tool and supervisor. Windows VMs may need the same later.

Fleet (fleetdm) is open source and self-hostable. Its free tier covers Apple MDM enrollment, configuration profiles, osquery inventory, scripts and SAML SSO to its UI; Premium adds Fleet-maintained apps, OS update enforcement, FileVault escrow, end-user authentication and Apple Business Manager enrollment. Basic Windows MDM through its agent needs no Microsoft Entra. Fleet stores everything in MySQL (8.0.44, 8.4 and 9.5 are tested; 9.6 is incompatible; Postgres is not supported) and uses Redis. Apple MDM needs a push certificate that a plain Apple Account can create and that expires yearly.

[ADR 0031](0031-a-three-node-talos-kubernetes-cluster-becomes-the-services-plane-and-the-bootstrap-tier-stays-on-proxmox.md) puts new services on the Talos cluster unless they are bootstrap-tier. In this repo "fleet" already means the Proxmox guest fleet.

## Decision

- **Tree `fleetdm` on the services cluster.** A Flux tree `kubernetes/fleetdm/` (namespace `fleetdm`, seeded through `k8s_seed_namespaces`) carries the Fleet server as a pinned `HelmRelease` of Fleet's chart, with its database and cache in-tree, never the chart's dev sub-charts. The component is named `fleetdm` everywhere in the repo to stay distinct from the guest fleet.
- **MySQL 8.4 LTS, pinned to the `8.4` tag.** The repo's only MySQL. 8.4 is an LTS line and 9.5 is an Innovation release, supported only until the next one, and that next one (9.6) breaks Fleet, so 9.5 would strand the database on an unpatched version. The `8.4` tag takes LTS patch releases. The pin has a reason, so it is an exception to "container tags stay latest" and is rolled deliberately. **Move to the next LTS line** when both hold: it is on Fleet's tested MySQL list, and it has had at least one patch release. Move no later than six months before 8.4 leaves Oracle's Premier Support. The move is its own change: back up by hand first, then change the tag, then run the recovery drill against the new version. Valkey on `latest` is the cache, with no persistence.
- **Free tier.** No license key. Software updates are operator-triggered Fleet scripts (`brew upgrade`, run as the Homebrew owner) from the UI or `fleetctl`; policy automations that run scripts, Fleet-maintained apps and OS update enforcement are Premium and not used.
- **LAN-only on its own address, never on the shared Traefik listener.** Fleet gets a MetalLB `LoadBalancer` at services offset 70 (`externalTrafficPolicy: Local`) and terminates TLS itself with a Let's Encrypt certificate for `fleet.<service domain>` from the `letsencrypt` ClusterIssuer. The VPS relay forwards public 443 to Traefik's address (ADR 0044), so any host on Traefik is reachable from the internet by Host header; Fleet's address is never a relay or tunnel target, and pfSense rules decide which networks reach it. The publicly trusted certificate is what lets a Mac enroll without first trusting the homelab root.
- **No open setup window.** Fleet's first-run setup grants global admin to whoever calls it first, so the `LoadBalancer` Service lands only after `k8s_apps` has completed setup over a port-forward and verified the expected admin exists; on any later run it stops if setup is open or an unexpected admin appears.
- **Login is SAML against the internal authentik realm**, a provider in `kubernetes/authentik/blueprint-internal.yaml` that asserts the user's email. Free Fleet does not create users from SSO, so `k8s_apps` creates each SSO operator account by email; one local break-glass admin is kept.
- **Secrets live in Infisical `/fleetdm`**, generated by the `k8s_apps` role (MySQL passwords, Fleet's server private key, break-glass password) and delivered by an `InfisicalSecret`. The Apple push certificate is uploaded through Fleet's UI and stored in MySQL encrypted under the server private key, so a database backup is useless without that key.
- **Backup** is a nightly `mysqldump` to PBS namespace `databases`, the same lane shape as `pg-backup`, proven by restoring a post-enrollment snapshot with the key recovered from Infisical.
- **Manual enrollment is opened per enrollment.** The downloaded enrollment profile carries a reusable challenge, so it is treated as a credential and the static challenge is disabled after each Mac enrolls.
- **Amends ADR 0061:** the M4 Studio host, not its CI guests, may reach Fleet's address on TCP 443 and nothing else internal, and the `ci` VLAN resolver gains a host override for `fleet.<service domain>`. Both are recorded in [docs/pfsense-ci-vlan.md](../pfsense-ci-vlan.md) and applied at the M4 rebuild, whose plan must show its guests cannot reach Fleet through the host's NAT.

## Rejected alternatives

- **A bootstrap-tier Proxmox guest.** MDM is not needed to bring the fleet back from cold, so ADR 0031 sends it to the cluster.
- **A plain Ingress on the shared Traefik listener.** The relay reaches that listener for every hostname; Traefik's Service uses `externalTrafficPolicy: Cluster` and the relay masquerades, so a source allowlist there cannot tell the LAN from the internet.
- **The chart's bundled MySQL and Valkey sub-charts.** Fleet marks them dev/test only.
- **A shared clustered database.** Rejected for the same reasons as in ADR 0055; Fleet also cannot use Postgres.
- **Premium now.** A paid per-host license for features the first jobs do not need; it can be added later with a key and no redeploy.
- **Reach from outside the house.** Every managed device is on the LAN; exposing device endpoints adds an internet-facing service for nothing.
- **A private-CA certificate on the Fleet endpoint.** Fleet does not document private-CA enrollment, and each Mac would need the root installed before it could enroll.
- **Leaving the M4 Studio unmanaged.** Its runner plan depends on MDM pushing the privacy profile it cannot grant from a script.

## Consequences

- One more stateful tree with a pinned image to roll: MySQL is checked against Fleet's tested list before any bump, the next-LTS trigger above is checked at each Fleet chart bump, and the backup Job runs by hand before any chart or MySQL bump, since the chart migrates the database on upgrade.
- MetalLB offset 70 is taken (`vlans.yaml` `metallb.offsets.fleetdm`).
- The Apple push certificate expires yearly and must be renewed with the same Apple Account; a lapse forces every Mac to re-enroll. The renewal date is an operator calendar item and the plan adds an expiry check.
- Enrolling a Mac is an operator step at its screen (user-approved MDM), once per Mac.
- Windows MDM later needs its own identity certificate and key in `/fleetdm`; nothing in this decision blocks it.
- `/fleetdm` joins the Infisical folder ownership table and the nested-path loop in `ansible/tasks/infisical_login.yml`.
