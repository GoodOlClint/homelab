# ADR 0052 — The agent plane is an agent-runner VM on a dedicated automation VLAN and a homelab-mcp gateway VM on the services VLAN, both on msi, outside the Talos cluster

- **Status:** Proposed (awaiting operator review of [docs/local-ai-plan.md](../local-ai-plan.md))
- **Date:** 2026-09-10
- **Deciders:** operator + agent
- **Context source:** [docs/local-ai-plan.md](../local-ai-plan.md) (two council rounds, Claude + Codex, 2026-09-10) · amends [ADR 0003](0003-decompose-services-to-static-ip-lxcs-vms-only-where-isolation-demands.md) (`mcp` moves from the LXC list to the VM list), [ADR 0030](0030-three-management-planes-vlan10-out-of-band-vlan30-hypervisor-with-pdm-pbs-apt-cache-pxe-vlan40-services.md) (one named guest → VLAN 10 API exception) and [ADR 0031](0031-a-three-node-talos-kubernetes-cluster-becomes-the-services-plane-and-the-bootstrap-tier-stays-on-proxmox.md) (agents and MCP are not services-plane workloads) · follows the isolation shape of [ADR 0032](0032-ci-runners-are-ephemeral-and-build-their-own-guests-inside-a-pve-pool-on-an-isolated-vlan-and-the-mac-studio-is-a-separate-trust-tier.md)

## Context

Two operator-designed components need rebuildable homes. **agent-runner** (`~/Source/agents`) is a config-defined A2A agent harness that invokes the Claude Code and Codex CLIs on subscription logins plus any OpenAI-compatible endpoint, per-agent `mcp_servers`, webhook and cron triggers, per-context git worktrees; its own change plan already ruled it a homelab-managed Proxmox VM, not Kubernetes. **homelab-mcp** (`~/Source/homelab-mcp`) is a FastMCP gateway composing six read-mostly servers (UniFi, Proxmox, pfSense, OpenObserve, Plex, arr) over streamable HTTP with bearer-to-principal auth, grant intersection, a single enforcement point, in-memory approval tickets, and an audit stream; it holds PVE, UniFi and pfSense API tokens, and two of its upstreams live on the out-of-band VLAN 10. Neither repo has a remote or a tag yet. The retired `mcp` guest 115 had no successor (ADR 0031).

ADR 0003 lists `mcp` as an LXC, written before the gateway's credential set existed; its own test says crown-jewel secrets force a VM. ADR 0030 says nothing on VLAN 30 or 40 initiates toward VLAN 10, and `control` is not a precedent because it lives on VLAN 10. ADR 0032 already solved "untrusted execution with reach into the fleet" for CI with an isolated VLAN, default deny and named egress. msi has 128 GB of RAM and is the GPU host; it is also the node with the shortest uptime record and a planned Ceph exit.

Both councils converged on: agents = VM (arbitrary code plus the fleet's highest-value credentials), mcp = VM (fleet-owning token bundle, serves untrusted callers), no second Kubernetes, the agents host never a PAIR member, `make update` skipping both guests, state on holder volumes, approval tickets deliberately ephemeral. The operator chose the dedicated VLAN, the narrow ADR 0030 amendment, and co-location on msi.

## Decision

- **`agents` is a VM on a new `automation` VLAN** (`vlans.yaml` binding, `make sdn-apply`, pfSense hand rules per ADR 0005): default deny; ingress only from the operator's devices and the webhook path; egress enumerated to source hosting, the approved model providers (Anthropic, OpenAI, OpenRouter), `llm.<service domain>` (ADR 0051's Caddy front door), the `mcp` gateway, DNS, NTP, the apt cache, and the vault URL for its Infisical agent. The CI VLAN is not reused. Initial size 4 vCPU / 8 GB / 60 GB per the upstream plan, resized from measurement; `/var/lib/agent-runner` on a holder slot; `/home/agent-runner` stays disposable and the subscription login stays a documented hand step after every rebuild until a separate decision verifies those credential paths.
- **`mcp` is a VM on the services VLAN**, single-homed, behind Caddy with a `fleet-hosts` cert. ADR 0003's placement table is amended: `mcp` moves to the VM list under the crown-jewel test. Bearer secrets and the token→principal map render from Infisical (folder `/mcp`); grants are reviewed configuration; tickets stay in memory (restart = fail closed); the audit stream ships to OpenObserve **and** spools to a bounded append-only file on a holder slot, replayed on acknowledgement. Upstream TLS verification must be on against the fleet root (ADR 0041/0042) before the gateway holds fleet tokens.
- **ADR 0030 gains one named exception:** `mcp → VLAN 10` to the UniFi API and the pfSense API only. Everything else in ADR 0030 stands, including laptop-only general ingress. `mcp → 30:8006` was already named there.
- **Both guests and VM 240 live on msi.** The operator accepts the shared failure domain for the RAM headroom and single-host locality; when msi leaves Ceph all three move to local storage as one unit.
- **Not on the Talos cluster, and no second Kubernetes.** ADR 0031's services-plane rule is amended to say agents and MCP are bootstrap-tier-adjacent Proxmox guests. A second Talos cluster, k3s, or co-location on VM 240 are rejected.
- **Order of build:** the `ollama` role (ADR 0051) first. The `mcp` and `agent_runner` roles are written against local checkouts as development evidence but their guests are not built until each upstream repo has a remote and an immutable tag, because the roles' install contract is `uv tool install git+…@<tag>`.

## Rejected alternatives

- **Kubernetes placement, re-reviewed after the Flux layer landed (round 3, both councils, 2026-09-10).** Flux is now the one way any Kubernetes workload in this homelab is configured (ADR 0048), but that does not make the agent plane a Kubernetes workload. *The existing services cluster* stays rejected: it runs flannel, which enforces no NetworkPolicy, so namespaced RBAC, pod-security labels and taints do not reproduce a VM + VLAN boundary for shell-capable agent execution; "Claude Code with a shell" in a pod is ARC's privileged-dind shape with standing credentials, the placement ADR 0048 refused for Flux's own credential; and pod egress is masqueraded to the node address, so a pod-hosted `mcp` would turn the narrow ADR 0030 exception into "every pod on that node → VLAN 10" while pulling its image through the Zot it audits. *A second Talos cluster for agents* stays rejected: `k8s_seed`, `talos.sh`, the Makefile, `flux_check.py`, the kubeconfig, `nodes.json`, `cluster-bindings` and the universal-auth identity are single-cluster today, and parameterising them (3–4 days, verified against the code) buys a second lifecycle in the same msi failure domain. *Guest-side GitOps reconciliation* (a pull agent on the VM) stays rejected as a third controller model beside Flux and Ansible. The Flux contract itself (public repo, strict substitution, no credential, prune) is the wrong shape for private prompts, subscription state and stateful spools.
- **K3-mcp — a dedicated MCP-only Talos node/cluster with its own Flux root (operator-raised, 2026-09-10, not yet council-reviewed):** on a node that carries only `mcp`, the node's egress address *is* the gateway's identity, so the SNAT objection above does not apply and the ADR 0030 exception stays narrow. It still costs the cluster-profile parameterisation, one more etcd on msi, local-only storage once msi leaves Ceph, and either a Zot dependency or an ADR 0022 upstream-ref exemption. **Decision: `mcp` is a VM now; K3-mcp is the named revisit** — the moment the cluster-profile parameterisation is done for the scratch/rehearsal cluster ADR 0048 wants, moving `mcp` onto a dedicated Flux-managed node is a one-tree change and this ADR gets a consequence note, not a rewrite.
- **Co-locating agents and MCP on VM 240** — puts the credential set on the model server and competes with the model for the guest's resources.
- **`mcp` as an LXC per ADR 0003's list** — the list predates the credential bundle; the ADR's rule outranks its inventory.
- **`agents` on the services VLAN with named rules** — same-L2 with every other guest; ADR 0017 spent a migration removing exactly that adjacency for untrusted workloads.
- **Reusing the CI VLAN** — CI guests are ephemeral and reaped; agents are persistent with standing credentials, a different lifecycle and rule set.
- **Dropping UniFi/pfSense from the gateway to avoid touching ADR 0030** — network tools are the first concrete use; a narrow named exception is smaller than losing them.
- **Persisting the whole `/home/agent-runner`** — preserves caches, mutable binaries and opaque session files as fleet state.
- **Persisting approval tickets to "unlock unattended T2"** — deletes the approval gate that is the plan's one blast-radius control.

## Consequences

- **Repo-side deploy gate is a tranche-1 prerequisite, not an owed item.** Under ADR 0048 a merge to `main` is a cluster deploy with `prune: true`. Verified 2026-09-10: the `main` ruleset carries only deletion / non-fast-forward / linear-history — no pull-request requirement, no required checks, no code-owner review, no signature rule — so any write-capable identity, the agent GitHub Apps included, can push straight to `main`. Before any agent identity authors PRs against this repo: a pull-request rule with code-owner review, CODEOWNERS on `kubernetes/**`, `ansible/roles/k8s_seed/**`, `.github/**`, `docs/decisions/**`, `CLAUDE.md`/`AGENTS.md`, required status checks including the guardrails and Flux checks, and no push-to-main for any agent identity; Flux `GitRepository.verify` with operator-signed commits is the strong form. Recommendations: [docs/repo-deploy-gate.md](../repo-deploy-gate.md).
- **The agents VM holds no kubeconfig and no Flux credential by default.** Anything with a cluster-scoped token reads `cluster-bindings` and every operator-managed Secret; that credential, not the VLAN, is the isolation question if an agent's task ever touches the cluster.
- Agent images and tools (`uv`, `npm`) install from upstream — an ADR 0022 stays-upstream exemption, stated here. Holder VM 900 lives on Ceph, so "all three move with msi" needs a second holder or a local-storage state model on msi; nightly-fleet membership for the agents VM is a decision (its disposable `/home` carries subscription logins).

- New: `automation` VLAN entry (binding), pfSense rule set (hand-managed, documented), `agent_runner` and `mcp` roles, Infisical folders `/agents` and `/mcp` (both added to `infisical_login.yml` and the ownership table), holder slots for `/var/lib/agent-runner` and the audit spool, Kuma rows, `make update` exclusions for both guests, nightly-fleet backup membership.
- Upstream work that gates the guests: a remote + `v0.1.0` tag on both repos; agent-runner needs a secret-indirected `headers` field so each agent presents its own bearer (until then attribution is per host, and the gateway's principal model is collapsed — say so, do not pretend); agent-runner's own endpoint and webhooks need authentication, signatures and replay protection before the VLAN's ingress rule is opened; homelab-mcp needs a deployment contract, verified upstream TLS, and the audit spool.
- Still owed before any credential-bearing agent runs against real infrastructure: an egress allowlist and OpenRouter spend cap, a kill switch, worktree reaping and disk quotas, a named approver for T2/T3 tickets, a compromised-host recovery runbook (revoke identities, rotate upstream tokens, preserve audit, rebuild), a webhook ingress mode (ADR 0044), and the first consumer's contract (the AdGuard allowlist miner: inputs, output schema, proposal/approval boundary, adversarial prompt-injection eval).
- Prompt injection through an agent's authorized egress remains the residual risk; the grant table and per-agent identity, not VLAN placement, bound the blast radius.
