# ADR 0036 — P4b: the monitoring stack moves to the cluster as one namespace, axosyslog keeps a stable address on a MetalLB LB with Local traffic policy, state rides per-service ceph-rbd PVCs rsynced from 203

- **Status:** Accepted (approved 2026-08-23)
- **Date:** 2026-08-23
- **Deciders:** operator + agent
- **Context source:** P4b brownfield gate, [docs/talos-p4b-openobserve-plan.md](../talos-p4b-openobserve-plan.md); builds [ADR 0035](0035-p4a-traefik-ingress-on-one-lb-ip-with-a-wildcard-internal-cert-the-infisical-kubernetes-operator-is-the-secret-path-and-homepage-is-the-first-zot-templated-ref.md), honours [ADR 0011](0011-two-alerting-lanes-uptime-kuma-for-reachability-alertmanager-for-metrics.md), [ADR 0020](0020-detached-data-volumes-ride-a-single-never-started-holder-vm-not-a-holder-ct.md), [ADR 0028](0028-greenfield-replace-builds-final-form-guests-beside-the-restored-copies-under-vmid-old-100-after-pruning-the-fleet-state-of-every-proxmox-resource.md), [ADR 0031](0031-a-three-node-talos-kubernetes-cluster-becomes-the-services-plane-and-the-bootstrap-tier-stays-on-proxmox.md)

## Context

openobserve is the second P4 stack: LXC 203 runs 14 compose containers (OpenObserve, Grafana, Prometheus, Alertmanager, Uptime Kuma, axosyslog, seven exporters, node-exporter) with 42 GB of history on holder volume idx 3. Unlike homepage it is consumed fleet-wide by a fixed address: every guest's rsyslog and Docker daemon, the three PVE nodes' rsyslog and netconsole, pfSense and UniFi all ship to `.40.103` on 5514/5515, and the `netconsole` stream identifies senders by source IP only (the wire format has no hostname). ADR 0031 lists the bootstrap tier that never leaves Proxmox; monitoring is not on it, and 203 already dies with Ceph, so the cluster adds no failure mode the guest did not have. The Kuma reachability lane and the Alertmanager→ntfy lane (ADR 0011) must both survive, the OpenObserve pin (`v0.92.0-rc2`, schema 46) is unchanged, and Zot does not yet proxy `public.ecr.aws`.

## Decision

- **The whole stack moves** to `kubernetes/monitoring/` (namespace `monitoring`) — one Deployment per former container, `Recreate` strategy, in-cluster Service names equal to the old compose names so the configs keep `http://openobserve:5080`, `alertmanager:9093`, `blackbox:9115`. **node-exporter and the ISP modem scraper are dropped** (the fleet reports through telegraf; the modem has answered "not reachable" on every run) — the `isp` rules and dashboard stay as the spec, per the ADR 0011 precedent for rules over absent metrics. UIs (`grafana`, `openobserve`, `prometheus`, `alertmanager`, `uptime-kuma`, each `.<domain_suffix>`) are plain Ingresses on Traefik with AdGuard rewrites to the ingress IP.
- **axosyslog gets a stable L4 address: one MetalLB `LoadBalancer` Service at services offset 66** (5514 udp+tcp, 5515 udp, 6514 tcp, mixed-protocol) with `externalTrafficPolicy: Local`, so the netconsole stream still records the sender's source IP and the address follows the pod. The fleet's `openobserve_listen_host` is re-derived as the services prefix + `monitoring_syslog_offset` (66) in `group_vars/all.yml` — no longer a `hostvars` lookup of a guest that no longer exists.
- **State = per-service ceph-rbd PVCs** (openobserve 60 Gi, prometheus 10 Gi, grafana 2 Gi, uptime-kuma 2 Gi, alertmanager 1 Gi; RWO, expandable). **History migrates by rsync from a throwaway pod over ssh to 203** while 203's stack is stopped, with a one-off key that is removed afterwards; holder volume idx 3 stays attached to the stopped 203 and its `data_volumes` entry is never renumbered or removed while 203 exists.
- **Secrets:** one `InfisicalSecret` on `/monitoring` whose `template.data` renames keys to the env names each workload expects and renders the two bare files (Prometheus `password_file`, Alertmanager `url_file`) as keys mounted from the same managed Secret. The two generators the `monitoring` role owned (`grafana_admin_password`, `openobserve_root_user_pass`) move to `monitoring_users`, which already generates in `/monitoring`; the folder table row becomes `monitoring_users, proxmox_backup`.
- **Images** are `${REGISTRY}/<upstream>/<repo>` (ADR 0022/0035); Zot gains a `public.ecr.aws` sync entry for the pinned OpenObserve ref; renovate's pin manager is repointed at the manifest.
- **Configs** are the role templates translated to `${VAR}` placeholders; the Prometheus telegraf target list is generated by `deploy.sh` from `vms.yaml` (+ the VPS tunnel address) into a `file_sd` JSON, so a new guest is scraped without editing a manifest; the `proxmox` job targets the PVE API endpoint host from `vars.auto.tfvars`. `monitoring@pve` + its token are recreated on the new cluster by the existing `monitoring_users` role through a `make monitoring-users` target that carries the `proxmox.yaml` inventory.
- **Retirement:** 203 stopped + `onboot 0` (ADR 0028), state-removed, out of `vm-configs.tf`/`backup_jobs`; the `monitoring` and `openobserve_dashboards` roles, the openobserve play/tag, the seven agent templates and every repo reference go. pfSense's remote-syslog target is repointed with one ad-hoc `pfsensible.core.pfsense_log_settings` call; UniFi's remote syslog + netconsole are an operator UI step.

## Rejected alternatives

- **axosyslog stays on Proxmox as a bootstrap-tier LXC** — a guest and a role to keep for a forwarder that still needs OpenObserve reachable; it only preserves an address, and MetalLB does that.
- **hostNetwork axosyslog pinned to one node (the ARC shape)** — the address becomes a node's, not a service's; dies with that node and cannot move.
- **`externalTrafficPolicy: Cluster`** — SNATs every datagram to a node address, so every netconsole line would carry a Talos node as `host` and the stream would be useless for telling nodes apart.
- **Static PV over the holder RBD image (zero copy)** — the image would be owned by both the holder VM config and the cluster; any holder re-apply can destroy it, and it breaks ADR 0020's single-owner model.
- **One shared PVC** — RBD is RWO, so every stateful pod would have to share one node (or one pod); per-service volumes also expand independently.
- **Keep node-exporter + the modem scraper as a sidecar** — carries a host-metrics exporter for a host that no longer exists and a scraper that has not produced a real sample in weeks.
- **`kubectl cp` through the workstation for the history** — 42 GB twice over the LAN through a laptop; the pod-to-203 rsync stays on the services VLAN.
- **Repoint UniFi via the controller API with the poller credentials** — a write with a read-only account, and CLAUDE.md already forbids credentialed probing of the controller.

## Consequences

- `kubernetes/monitoring/` + `make talos-monitoring`, `make monitoring-migrate`, `make monitoring-users`; offset **66** is the syslog LB (65 Traefik, 64 Zot). `openobserve_listen_host` is prefix + offset in `all.yml`; `host-bindings.yaml` `cluster.openobserve_syslog_target` and pfSense/UniFi/Kuma point at the same address.
- Every rsyslog/telegraf/docker-logging consumer needs one fleet rollout after the move (`make ansible-infra TAGS=monitoring`, `make ansible-services`, `make vps-ansible`, `make proxmox-hosts TAGS=logging`); until each runs, that sender's lines go to the stopped 203 and are lost — the DoD checks a fresh line from a guest and a node.
- `/monitoring` owner column: `monitoring_users, proxmox_backup`; `openobserve_dashboards` and `juju4.openobserve` are gone; `scripts/test_axosyslog_routing.py` renders `kubernetes/monitoring/config/axosyslog.conf` (no Jinja left in it); `scripts/seed_uptime_kuma.py` runs inside the Kuma pod via `kubectl exec` (the image ships python3 + sqlite3).
- Kuma's monitor rows for the moved services are edited in the migrated `kuma.db` (the seeder's own mechanism) — ADR 0011's "hand-managed" stays true; the doc and the gitignored JSON follow.
- The `isp` alert group and `dashboard-isp-quality` reference metrics nothing produces; reviving the lane means a real exporter, not the textfile cron.
- CLAUDE.md: Canonical pipelines (monitoring is `kubernetes/monitoring/`), make targets, tags (`openobserve` gone), folder table, the `openobserve_listen_host` rule. Holder volume idx 3 is dead weight until the decommission sweep retires 203.
