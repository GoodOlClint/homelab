# Homelab Repo Audit — 2026-07-07

Full-repo review across security, coverage/completeness, VM utilization, and maintainability. Four independent review passes; the highest-impact claims (minio non-use, lancache DNS wiring, missing docker handler) were re-verified by hand. Each finding has file references so it can be actioned directly.

**Overall:** The architecture is sound — two-tier secrets hold up (no `{{ secrets.* }}` in any compose template, SOPS hygiene clean, VPS hardening strong). The real problems are: security controls applied to one VM instead of the fleet, a monitoring stack that collects everything but alerts on nothing, backup gaps for several stateful services, two VMs doing nothing, and documentation that has drifted from the code.

## 1. Security findings

### High

**S-H1. Postgres superuser password baked into world-readable scripts.**
`ansible/roles/plex_services/templates/postgres_backup.sh.j2:21`, `postgres_restore.sh.j2:19`, `postgres_pbs_backup.sh.j2:20` embed `{{ secrets.plex_services.postgres_password }}` as a shell default; all three deployed `mode: '0755'` (`plex_services/tasks/main.yml:249,263,277`).
Fix: `mode: '0700'`, owner root, and source the password from the existing Infisical agent env_file instead of baking it (the `pbs_env.j2` pattern).

**S-H2. `hardening` role applied to exactly one VM.**
Only the infisical play (`infrastructure.yml:102`) and bootstrap apply it. All other VMs miss: `PasswordAuthentication no`, unattended-upgrades, auditd, sysctl hardening, UFW. Cloud-init user has `NOPASSWD` sudo (`terraform/modules/proxmox-vm/templates/user-data.yaml.tmpl:9`), widening blast radius.
Fix: add `hardening` to the common role list in every play (exclude the Alpine VPS, which has `vps_hardening`). Also add `PermitRootLogin no` to the internal role — the VPS variant sets it, the internal one doesn't. Fix S-H4 (UFW reset) first or every deploy opens a firewall-down window fleet-wide.

**S-H3. AdGuard admin UI unauthenticated on all interfaces.**
`adguard/templates/adguardhome.yaml.j2:9` binds `0.0.0.0:3000` with `users: []` — fresh deploys expose the unauthenticated setup wizard on every attached VLAN. No host firewall (see S-H2). DNS hijack pivot for the whole network.
Fix: bind web UI to `{{ ansible_host }}:3000`; provision the admin user via `generate_secret.yml` (bcrypt into `users:`). Keep `bind_hosts: 0.0.0.0` for DNS itself.

### Medium

**S-M1. Squid accepts any upstream TLS error for bumped clients.** `squid/templates/squid.conf.j2:111` `sslproxy_cert_error allow all` — bumped clients see a valid CA-signed cert even when upstream is expired/self-signed/MITM'd. Remove the directive or scope it to a narrow ACL.

**S-M2. Plex PFX password baked into script + passed on openssl argv.** `plex_certificate/templates/plex-cert-deploy.sh.j2:15,23` — visible in `ps` during renewals; script is 0750. Source from Infisical env_file, use `-passout env:PFX_PASS`, tighten to 0700.

**S-M3. Guardrails regexes point at pre-consolidation paths.** `scripts/security_guardrails.sh` protected-path regexes still match `terraform/(infrastructure|services)/…`, so the block never fires for the real `terraform/terraform.tfstate` / `vars.auto.tfvars`. Update both regexes. (Mitigated by .gitignore + gitleaks, but the defense layer is dead.)

**S-M4. `infisical_write_secret.yml` lacks `no_log`.** Create/update/read tasks (`:22,39,52`) print secret values (including the VPS WireGuard private key) under `-v` or on API failure. Add `no_log: true`.

**S-M5. WireGuard private key echoed via `debug` on first deploy.** `vps_wireguard/tasks/main.yml:213-229` prints the relay's private key to stdout. Replace with a "retrieve from Infisical" instruction.

### Low

- **S-L1.** MemPalace binds `0.0.0.0:8765` (`mcp/defaults/main.yml:11`) with no host firewall and unverified auth — bind to service VLAN IP or add UFW allow-list.
- **S-L2.** `validate_certs: false` on UniFi/Synology admin-credential POSTs (`monitoring_users/tasks/unifi.yml`, `synology.yml:9`) — consider trusting the internal CA instead.
- **S-L3.** Archived Packer image has known-password hash + NOPASSWD sudo (`archive/packer-20260216/ubuntu-24.04/http/user-data:19,27`) — rotate/parameterize if ever revived.
- **S-L4.** `generate_secret.yml:35-51` `set_fact` lacks `no_log` (value shown at `-v`).

**Verified clean:** no plaintext secrets in tracked files; compose templates contain zero `{{ secrets.* }}`/`bootstrap.*`; sensitive rendered files (cloudflare.ini, pbs_env, docker-env, runner key) are 0600; VPS sshd/nftables baseline is strong; `.sops.yaml` exposes only a public age recipient.

### Ranked gaps

1. **No alert delivery.** 12 Prometheus alert rules exist (`monitoring/templates/alert.rules.yml.j2` — HostDown, PBSBackupStale, TLSCertExpiringSoon…) but there is no Alertmanager anywhere. Only external signal is the UptimeRobot heartbeat for the openobserve VM itself. Uptime Kuma is deployed but its monitors/notifications are hand-configured (lost on rebuild). Fix: add Alertmanager to `monitoring/templates/docker-compose.yml.j2` + `alerting:` block in `prometheus.yml.j2`, or use OpenObserve/Uptime Kuma alerting via API.
2. **PVE vzdump backup jobs are not IaC-managed.** No backup-job resource in Terraform or any role — VM-image DR depends on UI-clicked config that won't survive a host rebuild. Fix: manage `/etc/pve/jobs.cfg` via a small `proxmox_host` role or the Terraform provider's backup resource.
3. **Postgres PBS restore gap** (confirmed): `plex_services/templates/postgres_restore.sh.j2` supports local/SMB only; rebuild auto-restore finds nothing from PBS. Port the `plex_config_pbs_restore.sh.j2` pattern.
4. **Proxmox host and pfSense nearly unmanaged.** Proxmox host: apt updates only — no rsyslog/telegraf/hardening. pfSense: DHCP/RFC2136 only — no config.xml export, no metrics, absent from `update-all.yml`. Fix: `proxmox_host` play; pfSense config-export cron + SNMP scrape target.
5. **Stateful data with zero backup:** MemPalace data dir (mcp), OpenObserve history, nvidia-licensing DB/cert, BIND dynamic zones, pfSense config.xml. MinIO data is delegated to the NAS — document that explicitly or retire (see §3). Most of these VMs already run `pbs_client` doing nothing — reuse the cron+script pattern.
6. **`backup-clients.yml` stale** — targets `plex,plex-services,docker` (`:4`) while `pbs_client` is applied to 9 VMs. Retarget or delete (site.yml covers it).
7. **Health-check blind spots:** blackbox probes cover only AdGuard, OpenObserve, Grafana, Plex (`monitoring/templates/prometheus.yml.j2:64-125`). No probe for infisical (the hard-fail dependency of every deploy), PBS, unifi, homepage, minio, squid, mcp, VPS tunnel. Extend target lists from `hostvars`/groups instead of hardcoding.
8. **`openobserve_dashboards` role orphaned** — referenced by no playbook; its PBS dashboards never deploy. Wire into the openobserve play or delete.
9. **github-runner agent misconfigured** — play sets `infisical_secret_paths` but defines no `infisical_agent_templates`; agent runs rendering nothing. Remove or configure.
10. **lancache play missing `telegraf`** (`services.yml:236-248`) — moot if retired.

## 4. Maintainability findings

### High

**M-H1. Missing `restart docker` handler → deploy failure on fresh builds.**
`ansible/tasks/configure_docker_logging.yml:41` notifies `restart docker`; verified: docker's handler listens only for `restart docker services`, minio's only `restart minio`. Any run where `/etc/docker/daemon.json` changes (every fresh build) aborts with "handler not found". The uncommitted github_runner diff fixes exactly this class for github_runner only — commit it together with docker/minio fixes: add `listen: "restart docker"` to docker's `Restart Docker daemon` handler; add the handler to minio (copy `lancache/handlers/main.yml:2-6`).

**M-H2. `ansible/tasks/deploy_compose.yml` is dead code; CLAUDE.md documents it as canonical.**
Zero references repo-wide, while the deploy+restart pattern is copy-pasted with drifting variants: `homepage/tasks/main.yml:55-106`, `lancache/tasks/main.yml:76-94` (notify **and** immediate apply → double restart), `minio/tasks/main.yml:86-92`, `monitoring/tasks/main.yml:326-330`, plus 8 per-host restart blocks in `docker-config.yml`. Adopt it everywhere or delete it and amend CLAUDE.md Resolved #6.

**M-H3. plex_certificate restarts Plex on every run.**
`plex_certificate/tasks/main.yml:109` — unconditional `xmlstarlet ed --inplace` with no `changed_when`, notifying `restart plex`. Every deploy bounces Plex mid-stream. Fix: `xmlstarlet sel` first, gate the edit on actual difference.

**M-H4. hardening role resets UFW on every run.**
`hardening/tasks/main.yml:15-23` — `state: reset` always fires, leaving a firewall-down window on every deploy and breaking idempotency. Gate reset behind a templated ruleset marker. **Must fix before rolling hardening fleet-wide (S-H2).**

**M-H5. `*_base_dir` variables exist but are bypassed.**
`lancache_base_dir`, `monitoring_base_dir`, `plex_services_base_dir` are never referenced; tasks/handlers hardcode `/opt/lancache`, `/opt/monitoring`, `/opt/plex-services` (~15 sites incl. `services.yml:103-119` post_commands, `homepage/handlers/main.yml:9`, `minio/handlers/main.yml:4`). Overriding the documented var would half-work. Use the vars everywhere or delete them and amend CLAUDE.md.

### Medium

- **M-M1. Hardcoded IPs in tracked files** (violates repo rule + leaks addressing scheme): `prometheus.yml.j2:201` (VPS tunnel IP), `telegraf-openobserve.conf.j2:101` (pfSense tunnel IP), `homepage/templates/services.yaml.j2:198` (pfSense mgmt fallback), `lancache/defaults/main.yml:6` (AdGuard services IP), `squid/defaults/main.yml:61,63`, `unifi/defaults/main.yml:13-15`. Derive from VLAN prefix facts or move to gitignored group_vars. *(Resolved by the WP6 scrub — literals replaced with derived vars.)*
- **M-M2. Makefile footguns:** bare `make` runs full `apply` (add `help` + `.DEFAULT_GOAL := help`); `make clean` destroys VMs with no confirmation (rename `destroy` or prompt); `plex-token` runs the whole plex play; mixed positional/`VAR=` argument styles; typo'd VM name in `make ansible <typo>` exits successfully; `vps-rebuild` breaks under `make -j`.
- **M-M3. github_runner dead handler:** `Restart github-runner` interpolates removed var `github_runner_name` — errors if ever fired. Delete it (systemd/svc.sh tasks manage services); remove empty `templates/` dir. Rest of the uncommitted diff is correct.
- **M-M4. Stale template code:** `prometheus.yml.j2:188-191` still carries a multicast-relay scrape stanza (VM retired). Delete.

### Low

- Unused role defaults (dead config surface): `infisical_agent_org_id`, `unifi_monitoring_name`, `synology_snmp_*` (5 vars), `dls_lease_expire_days`, `pbs_server_port`, `pbs_root_password`, `squid_cache_dir_size_mb`, `unifi_firewall_allowed_ips`.
- `plex_services/tasks/main.yml` is 2,488 lines (next largest: 776) — split into subtask files per the repo's own convention.
- `github_runner_repo: "goodolclint/PSProxmoxVE"` — personal binding baked into a tracked default.
