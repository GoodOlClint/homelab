# Kubernetes layer → proper IaC (brownfield gate, 2026-09-09)

**Status:** APPROVED 2026-09-09 (v3). Cloudflare token: build with the shared token now; the operator creates a dedicated scoped token later and the role swaps to it (owed). History: round-1 council recommended a Terraform cluster root; the operator lifted the "Terraform or Ansible" constraint and offered to move mission-critical services to Proxmox; round-2 council recommended Flux + authentik relocation (v2); the standard Codex + subagent review loop (Codex design review, architecture reviewer, security reviewer) then found three blockers and a dozen defects in v2 — all folded into this v3. ADR 0048 (Flux) and ADR 0049 (authentik relocation) are Accepted and match v3.

## Why

`kubernetes/` is 20 shell scripts (~760 non-comment lines) plus a Python renderer driving `kubectl`/`helm template`/`talosctl`/`curl` behind `make talos-*`. The operator wants no shell layer to maintain. The deeper defect (council round 2): the cluster violates rebuild-as-routine twice — registry/identity/ingress form a cold-start cycle, and identity for the bootstrap tier (PVE, PBS, PDM, Portainer, MeshCentral; pfSense SAML half already built in the blueprint, package + SP config still manual per ADR 0043) points up into the disposable tier.

**Verified facts:** Flux replaces an *undefined* `${var}` with an empty string; opt-out per resource is `kustomize.toolkit.fluxcd.io/substitute: disabled`; escape is `$${`; bare `$name` is untouched. **Foreign `${…}` lives in two ConfigMap payloads**: `monitoring/config/axosyslog.conf` (syslog-ng macros) and `games/valheim-playfab-status.mjs` (JS template literals) — the v2 claim of "only axosyslog" was wrong because the scan covered one tree; the real gate is a scan of every ConfigMap-sourced file (`grep -rn '\${[A-Za-z_]'` over the non-`.sh` tree, 48 files) and today's per-script *allowlist* becomes Flux's *opt-out*, which is the structural risk. Zot's `values.yaml` `openid` block is web-UI login only (push htpasswd, pull anonymous). external-dns runs `policy: sync`, `txtOwnerId: talos`, `interval: 1m`, and **owns a name through its TXT registry record**, not by who wrote the A. `plex_certificate` runs certbot + `dns-cloudflare` on a Proxmox guest with the `/infrastructure` Cloudflare token (DNS:edit on both public zones) in a 0600 ini. Two authentik realms; only the internal one has bootstrap-tier consumers; the external realm's LDAP outpost Deployment/Service are **created by authentik itself** through its Kubernetes service connection. PVCs are ceph-rbd with reclaim `Delete`. `/authentik`, `/authentik-ext`, `/jellyfin` are already in `infisical_login.yml`'s folder loop. Fleet compose roles use upstream image refs. No `.github/` exists — there is no CI; branch protection exists as prose in `docs/github-agent-identity.md`. Live cluster observations (re-verify as WP6 pre-flight, not premises): chart objects are SSA-managed by `kubectl` with Helm labels and no release record; `helm ls -A` answers from the Mac.

## Decisions (v3)

| # | Decision | Record |
|---|---|---|
| 1 | **Flux owns every Kubernetes object it applies.** `HelmRelease` per chart (pinned), `Kustomization` per tree, `postBuild.substituteFrom` the `cluster-bindings` ConfigMap, `substitute: disabled` on the two foreign-syntax ConfigMaps, `configMapGenerator` name-hashing replaces `checksum/config` (limitation accepted: a binding-only change does not roll a pod — bindings change rarely and no post-substitution hash exists). Objects authentik creates (the external realm's outpost) are outside Flux by design; Flux prunes only what it labelled. | ADR 0048 |
| 2 | **Flux reads the public repo with no credential.** The bootstrap commit (`flux install` output + the sync manifests) is an **operator-local `git push`** — never `flux bootstrap github --token-auth`, never the `goodolclint-claude` App (Contents RW on every installed repo; its PEM would sit one privileged-dind hop from every workload). Each `Kustomization` runs under a namespaced ServiceAccount, kustomize-controller with `--no-cross-namespace-refs`; no notification-controller GitHub provider (post-substitution error text would reach a public status API). Branch protection is made **real** (verified rulesets, not prose) before Flux tracks `main`. | ADR 0048 |
| 3 | **Ansible owns the cluster's seed objects and its in-app state; there is no Terraform for the cluster.** `ansible/playbooks/kubernetes.yml` (localhost, `full_pre_tasks` — it already has sops, the `secrets` fact, both inventories, `vlans.yaml`, `generate_secret.yml`) creates an **allowlisted** set of objects and nothing else: `cluster-bindings` ConfigMap (every `inv_env` value + `REGISTRY` + PVE endpoint host + ceph fsid/mons read from the proxmox inventory), the generated ConfigMaps `render.py` produces today (telegraf targets, blackbox-dns, smokeping dashboard — separate ConfigMaps Flux never manages), the `homelab-root-ca` ConfigMaps, the `homelab-ca` intermediate TLS Secret (CSR on the workstation, signed through the Infisical API — the `api_certificate.yml` pattern), `infisical-universal-auth`, `csi-rbd-secret`, the two ARC Secrets. First-run secrets stay on `generate_secret.yml` (create-if-absent, regeneration-guarded, the CLAUDE.md owner-role definition). In-app tail as before: Jellyfin, arr auth, SAB whitelist, smokes. A pre-commit check asserts the play's Kubernetes objects ⊆ the allowlist. v2's `terraform/cluster-seed/` root is **dropped** — it re-created the secret-bearing state ADR 0048 rejects, duplicated `generate_secret.yml`, and had no source for the ceph values. | ADR 0048 |
| 4 | **The root CA export joins the fleet PKI pipeline** (`scripts/pki_hosts.sh` / `make pki-hosts`, ADR 0041): Infisical `homelab-pki` project + root lookup/create, export to `kubernetes/.secrets/homelab-ca.crt`, `ca-bundle.pem`. `make talos-certs` becomes `make pki-hosts` + the Ansible seed (intermediate) and is **not** a `flux reconcile` wrapper. | ADR 0048 |
| 5 | **authentik's internal realm moves to a Proxmox LXC** — full contract below. **`authentik-ext` stays.** | ADR 0049 |
| 6 | **Zot stays; its `openid` block, the `zot` OIDC provider in the internal blueprint, `zot_oidc_client_secret` and the `oidc-credentials.json` item go in one commit.** UI becomes a single shared htpasswd account (no MFA, no attribution; anonymous read on `**` unchanged) — accepted to break the cold-start cycle. | ADR 0049 |
| 7 | **`talos.sh` stays now; retirement is a deliberate later tranche** paired with the cluster rebuild-from-zero work, proven on a worklab scratch cluster, then live nodes one at a time. | ADR 0048 |
| 8 | **`make talos-update` (the `:latest` rollout restart) is an explicit non-idempotent operator action**, batched, outside the convergence play's zero-change DoD. | ADR 0048 |
| 9 | **PVC `Retain` + a static-PV restore lane land before any `prune: true`** (folds the operator's open question 3 in). With reclaim `Delete`, a pruned PVC deletes the Ceph image; prune over `Delete` PVCs is a one-commit data-loss event. | ADR 0048 |

## The authentik LXC contract (ADR 0049)

- **Terraform:** `type = "lxc"`, `name = "authentik"`, VMID next free, `node_name` pinned, `vlans = ["vlan40"]` (single-homed on services per ADR 0017 — its consumers on vlan30/vlan10 already reach `auth.<service domain>` on Traefik's vlan40 LB today, so **no new firewall rule**; Traefik forward-auth → LXC is vlan40→vlan40), `keyctl = true`, `data_volume = { name = "authentik", path = "/opt/authentik" }` on **holder slot 7** (next free; never renumber), `ha` per the fleet HA policy of the day. `make data-volumes` first, `make build authentik` second — never one apply.
- **Role `authentik`** (pattern: `control`): compose with **Caddy on 80/443 terminating TLS** (the `infisical` role's shape) → `authentik-server` (+ `worker`, `postgres:17`, embedded outpost); `AUTHENTIK_HOST`/trusted-proxy set; blueprints mounted at `/blueprints` (auto-applied, no hash wait); Infisical agent env files with **hex-only** values (the base64 `+` bug); the role **reads** `secret_key`/`postgres_password` from `/authentik` and never generates them (regeneration = undecryptable database); no secret on argv (audit S6); upstream image refs (no Zot dependency — verified fleet pattern); nightly `pg_dumpall` → PBS ns `databases`, backup-id `authentik-postgres`.
- **Certificate:** Let's Encrypt via the `cert_client` LE + `dns-cloudflare` variant (fold `plex_certificate`, keep its PFX-staleness re-hook, audit X4/S10), deploy hook = `docker compose exec caddy caddy reload`. **Token scoping:** target = a dedicated Cloudflare token for the identity box scoped to the service zone's `_acme-challenge`; **interim (operator decision): the shared `/infrastructure` token**, swapped when the operator creates the dedicated one (security M7, accepted knowingly).
- **Cutover (the critical path):** (1) rehearse the dump restore on worklab's `wl-resolute` pinned to authentik 2026.8 + Postgres 17, then **destroy the rehearsal copy**; (2) land audit S8 (forward-auth application policy binding) first — today every internal-realm user reaches Headlamp/Prometheus/Alertmanager; (3) move the `authentik-forward-auth` Middleware into a Flux-managed `traefik` tree with the same qualified name (every protected Ingress references it) — only its `address` changes, to the public hostname; (4) test every break-glass path **that hour**: PVE/PBS/PDM `@pam`, Portainer internal, MeshCentral local admin (prove, don't infer), Synology, HA — and **Grafana has none** (`GF_AUTH_DISABLE_LOGIN_FORM` + auto-login; recovery = flip the env + restart, documented); forward-auth-only surfaces are unreachable during an outage, not degraded; a `root@pam` shell stays open; (5) **quiesce**: scale `authentik-server` + `worker` to 0 with Postgres running, take an **on-demand final `pg_dumpall`**, verify it, restore into the LXC, validate against the LXC directly by IP/hosts override **before** any DNS change; (6) **DNS handoff, atomically**: annotate the Ingress `external-dns.alpha.kubernetes.io/exclude: "true"` (or suspend external-dns), delete the Ingress, **verify the ownership TXT is gone** (`dig TXT`), `make dns-records` writes A + PTR (`dns_records.yml` gains an alias map — it has none today; the LXC hostname is `authentik`, the record is `auth`), `POST /control/cache_clear` on both AdGuards + `dscacheutil -flushcache`, resume external-dns and prove it leaves `auth` alone; (7) verify one OIDC login per consumer + forward-auth + Grafana + Jellyfin-via-ext untouched. **Rollback** within the window = reverse dump from the LXC into the cluster realm (tested in step 1), not "scale back up" — the two databases diverge the moment a user logs in. The cluster realm's PVC is kept a week, then deleted **and the RBD image verified gone**.
- **Never remove a forward-auth annotation as an outage workaround** — it is the only control on Headlamp, Prometheus and Alertmanager.

## Biggest failure mode

The authentik cutover — a restore with a mismatched `secret_key`/stale `authentik_host`, or a DNS handoff that leaves external-dns's TXT in place so the record is reverted or deleted a minute later. Every OIDC consumer 302s into a wall while the operator is logged in through the thing that broke. Mitigations are in the contract and are not optional.
