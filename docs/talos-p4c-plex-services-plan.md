## Decisions (ADR 0037 — interview settled 2026-08-24)

1. **Whole stack moves; namespace `plex-services`**, `kubernetes/plex-services/`: one Deployment (`Recreate`, `enableServiceLinks: false`) per compose service, Services keeping the compose names (`postgres`, `sonarr`, `radarr`, `lidarr`, `prowlarr`, `bazarr`, `sabnzbd`, `tautulli`, `seerr`) so in-config targets and the Cloudflare routes keep resolving. recyclarr, cloudflared, libation get no Service. **Dropped with the guest:** portainer_agent, telegraf/rsyslog on 206, the pbs_client + `docker_pbs_backup.sh` lane (superseded by decision 6 for postgres; container configs are on PVCs), the systemd pg_dump timer (re-homed as the CronJob). Containers keep their PUID/PGID envs (hotio s6) so NFS file ownership stays in the 2000-range uids.
2. **Media = a kubelet-mounted NFS PV** (operator decision): one PV/PVC `media` (Synology `/volume1/plex`, `mountOptions: [nfsvers=4.1, hard, noatime, rsize=1048576, wsize=1048576, nconnect=4]`), mounted `subPath: data` at `/data` in sonarr, radarr, lidarr, bazarr, sabnzbd; libation mounts `subPath: data/media/Audiobooks` → `/data` and `subPath: data/media/.libation-inprogress` → `/tmp` (ADR 0018 publish-is-a-rename preserved). The mount happens in the kubelet on the node's existing vlan20 leg — the node-level-mount shape ADR 0017 mandates, with kubelet instead of `pct` doing the bind; NFS still never terminates inside a workload. Server/path enter via `envsubst` placeholders (`${SYNOLOGY_STORAGE}`), never a tracked literal. **Smoke-test the PV with a throwaway pod before migrating** (Talos kubelet NFS is expected to work; if it does not, fall back to the Talos machine-mount alternative before any data moves).
3. **SABnzbd scratch = ceph-rbd PVC 60 Gi** (operator decision) at `/scratch`; `download_dir` stays `/scratch` in the migrated ini. Bounded so a queue cannot pressure a Talos node; expandable. The NFS-incomplete-dir trap (DIR_LOCK) stays avoided.
4. **State**: per-service ceph-rbd PVCs — postgres 10 Gi, radarr 10 Gi, sonarr 5 Gi, tautulli 2 Gi, lidarr 2 Gi, prowlarr 1 Gi, bazarr 1 Gi, sabnzbd 1 Gi, seerr 1 Gi, recyclarr 1 Gi, libation 1 Gi, backups 5 Gi (pg_dump staging + the 225 MB history), sab-scratch 60 Gi. **Migration** = `deploy.sh migrate <206 address>`, the P4b mechanism verbatim: scale to 0, workstation-driven `docker compose down` on 206, one-off ssh key, migrate pod mounting every PVC, `rsync -a --delete` per tree, key removed, scale up. Holder volume idx 2 stays attached to the stopped 206; its `data_volumes` entry stays (never renumber).
5. **Secrets**: one `InfisicalSecret` on `/plex-services` → managed Secret `plex-services-secrets` with `template.data`: `POSTGRES_PASSWORD` (postgres_password), `BAZARR_POSTGRES_PASSWORD` (bazarr_db_password), `SEERR_DB_PASS` (seerr_db_password), `LIBATION_MASTER_KEY`, `TUNNEL_TOKEN` (cloudflared_tunnel_token), and `secrets.yml` (the recyclarr file: sonarr/radarr api keys, mounted as a file item). A second `InfisicalSecret` on `/shared` → `pbs-secrets` (`PBS_PASSWORD` = pbs_backup_token, `PBS_FINGERPRINT` = pbs_fingerprint) for the backup CronJob; `PBS_REPOSITORY` is composed by `deploy.sh` from `inv_env` (`backup@pbs!backup-token@${PBS}:synology`) — the internal hostname never enters a tracked file. `secrets.infisical.com/auto-reload` on the consumers. **No generator re-home**: every `/plex-services` value already exists in Infisical; the arr configs and the postgres data dir carry the working copies; DR for total Infisical loss stays `make infisical-seed`. The folder-table owner becomes the k8s tree.
6. **Postgres PBS lane survives as a literal PBS push** (operator decision): a nightly CronJob (02:00) runs `pg_dumpall` against the `postgres` Service (initContainer, `postgres:17` image) into the `backups` PVC with a 30-day prune, then a `proxmox-backup-client backup` container pushes the dump dir as `plex-services-postgres.pxar`, ns `databases`, backup-id `plex-services-postgres`. **The client image is built in-tree** (`kubernetes/plex-services/pbs-client/Dockerfile`: Debian trixie slim + the proxmox trixie no-subscription client repo, `install_recommends`-equivalent off) and pushed to Zot as `registry.<domain>/homelab/proxmox-backup-client` by `make plex-pbs-image` from the workstation — Zot is a full registry, the sync overlay only covers upstream prefixes. `imagePullPolicy: IfNotPresent` on both containers (the Docker-Hub-quota-through-Zot rule). Backups are verified by **snapshot recency on the datastore**, never by job exit codes.
7. **UIs via Traefik**: `sonarr|radarr|lidarr|prowlarr|bazarr|sabnzbd|tautulli|seerr.<domain>` — plain Ingresses, AdGuard rewrites from `deploy.sh`. Public access unchanged (Cloudflare tunnel). Arr auth config (Forms, DisabledForLocalAddresses) migrates in the configs — note the ingress origin is non-local to the pod, so the login page appears for browser access via hostname; API-key access (widgets, Kuma svc-DNS probes... which are also non-local) is unaffected.
8. **Configs**: `kubernetes/plex-services/config/recyclarr.yml` — the Jinja template flattened once into static YAML (host_vars profile data inlined; it references only `!secret` keys); mounted as a ConfigMap item over the recyclarr PVC via `subPath`. Libation's `Settings.json`/`AccountsSettings.json` migrate as data on its PVC (login state intact — nothing regenerates them).
9. **Placement**: every Deployment gets `preferredDuringScheduling` node affinity away from `talos-cp-w` (the RMA-window seat, ADR 0031).
10. **Images** `${REGISTRY}/…` for all: `ghcr.io/hotio/{sonarr,radarr,lidarr,prowlarr,bazarr}:latest`, `ghcr.io/hotio/sabnzbd:testing`, `ghcr.io/seerr-team/seerr:latest`, `ghcr.io/recyclarr/recyclarr:8`, `docker.io/library/postgres:17`, `docker.io/cloudflare/cloudflared:latest`, `docker.io/rmcrackan/libation:13.7.10` (ADR 0016 latest-tags rule; the postgres major and Libation pins keep their existing demonstrated reasons).
11. **Retire 206 exactly as 203**: `pct stop 206` + `onboot 0`, `terraform state rm 'module.vms.proxmox_virtual_environment_container.containers["plex-services"]'`, out of `vm-configs.tf` + `backup_jobs` vmid list (`make backup-jobs`), delete `roles/plex_services`, the services.yml play + `plex-services` tag, the `docker-config.yml` section, `backup-clients.yml` host, the 7 agent templates, `host_vars/plex-services.yml` + example, `adguard_rewrite_vms` entry, telegraf template plex-services branches, `postgres_restore.sh` (restore is now `gunzip -c dump.sql.gz | kubectl -n plex-services exec -i deploy/postgres -- psql -U qstick`, recorded here). `make inventory` drops it from `vms.yaml`; then `make talos-monitoring` re-renders the telegraf targets.
12. **Not in scope**: Plex 208 (stays on Proxmox, iGPU, reads the same NAS tree), any media move, the Infisical PKI swap, arr auth changes, Lidarr/streamer additions.

## Sequencing

1. `make plex-pbs-image` (build + push the client image); `kubernetes/plex-services/` written; NFS PV smoke pod (write + read a file under `/data/usenet`, delete it). Abort here if kubelet NFS fails.
2. `make talos-plex-services` deploys against empty PVCs (db-backed pods may crashloop until data lands — expected); Ingress + InfisicalSecrets verified.
3. `make plex-services-migrate FROM=<206 address>`: compose down on 206 (workstation-driven), rsync all trees into the PVCs, scale up → arr UIs show existing library, postgres has pre-migration rows, Libation logged in.
4. Kuma rows repointed (uptime-kuma scaled 0, sqlite, scale up); homepage config updated + `make talos-homepage`; Cloudflare tunnel checked at `tautulli.<media domain>`.
5. SABnzbd test download → lands under the NAS path Plex 208 reads; trigger the backup CronJob once → new snapshot on the PBS datastore.
6. Retire 206 + cleanup; `make inventory`; `make talos-monitoring` (telegraf target re-render); `make plan` + `make talos-plan` clean; docs; small commits per row.

## Test bar / Definition of Done

- `curl https://<svc>.<d>/ping --cacert kubernetes/.secrets/homelab-ca.crt` → 200 via `.65` for sonarr/radarr/lidarr/prowlarr/bazarr; equivalent status endpoints for sabnzbd (`/api?mode=version`), tautulli (`/status`), seerr (`/api/v1/status`).
- Sonarr/Radarr series/movie counts match pre-migration; `select count(*)` on a sonarr table shows pre-2026-08-23 rows; Libation still authenticated (its next scheduled scan runs clean, `AccountsSettings.json` untouched).
- SABnzbd test download completes to `/data/usenet/complete/...` and the file is visible on the NAS path Plex 208 mounts.
- homepage arr widgets green at the new URLs; the 5 Kuma rows green; `https://tautulli.<media domain>` answers through the tunnel.
- `kubectl -n plex-services describe pods | grep Image:` → all `registry.<d>/…`; both InfisicalSecrets Ready.
- The backup CronJob triggered once → `proxmox-backup-client snapshot list --ns databases` shows a fresh `plex-services-postgres` snapshot (recency, not exit code).
- `pct status 206` stopped, `onboot: 0`; absent from `vm-configs.tf`, `vms.yaml`, `backup_jobs`; `make plan` + `make talos-plan` show no plex-services drift.
- Rollback: 206 intact — `pct start 206`, `docker compose up -d`, revert homepage/Kuma edits.

## Risks

- **Talos kubelet NFS**: expected to work (kubelet mounts NFS in its own mount namespace); gated by the step-1 smoke pod before anything is migrated.
- **NFS uid semantics**: pods write with the same 2000-range uids the CT wrote with (no idmap layer at all now); verified by the SABnzbd test download's ownership on the NAS.
- **Custom PBS client image**: locally built, so it needs a rebuild when the PBS server major rolls; recorded in the Dockerfile header. If Zot refuses a push (auth), fall back to enabling anonymous push on the `homelab/` prefix in Zot's config — resolved at build.
- **Crashloops between deploy and migrate**: seerr/bazarr need their DB users; harmless, bounded by running the migrate immediately after.
- **hotio `:latest` images against migrated configs**: same images/tags the guest pulled; a schema-migrating arr upgrade at first k8s start is the same risk `make update` carries today.
- **Cloudflare bare-name routes**: rely on the namespace search domain; verified via the tunnel hostname in step 4 before retirement.
