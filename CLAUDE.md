# Claude Code Guidelines — Homelab Ansible/Terraform Repo

## Repo Overview

This repo automates a Proxmox-based homelab with Terraform (VM provisioning, SDN, Vultr VPS, Cloudflare DNS) and Ansible (software configuration, Docker stacks, monitoring, secrets management). Key VMs: AdGuard (DNS filtering), BIND9 (authoritative DNS), Infisical (secrets vault), OpenObserve (monitoring stack), Proxmox Backup Server, UniFi, Plex, plex-services (arr stack), Docker (legacy services), Homepage, NVIDIA licensing. A Vultr VPS acts as a WireGuard relay for external access.

**Architectural decisions** live in `docs/decisions/` (ADRs) — read them before proposing architecture changes. In flight: the MS-01 3-node cluster migration ([plan](docs/ms01-cluster-iac-plan.md), ADRs 0001–0009 + 0014) — 3-node PVE 9 + Ceph, Terraform-managed hosts, static-IP LXCs, greenfield rebuild. Cluster create/join is API-module orchestrated, strictly serial with membership gates ([ADR 0023](docs/decisions/0023-proxmox-cluster-create-and-join-use-the-community-proxmox-api-module-not-pvecm-over-ssh.md)); cutover runs a restore-bridge — old fleet restored from PBS onto the 2-node cluster so pve is wiped/rejoined early, greenfield replacement follows at leisure ([ADR 0024](docs/decisions/0024-cutover-rides-a-restore-bridge-restore-the-old-fleet-onto-the-2-node-pve-9-cluster-rebuild-pve-early.md); mixed 8/9 clustering rejected as unsupported). Post-bridge, guests are **greenfield-replaced one at a time** beside the restored copies — fleet state pruned of every `proxmox_*` resource, new VMID = old+100, restored copy stopped never destroyed, targeted `make build` only ([ADR 0028](docs/decisions/0028-greenfield-replace-builds-final-form-guests-beside-the-restored-copies-under-vmid-old-100-after-pruning-the-fleet-state-of-every-proxmox-resource.md), [runbook](docs/ms01-cluster-iac-plan.md#greenfield-replace-runbook-day-3-adr-0028)). Ceph cluster network is switched 25G on the Pro-Aggregation's SFP28 ports, VLAN 21 (ADR 0014, renumbered from 33 — the FRR mesh is superseded). Corosync VLANs 31/32 live on the shared 48-port access switch, not a dedicated one ([ADR 0019](docs/decisions/0019-corosync-moves-onto-the-shared-48-port-access-switch-trading-physical-isolation-for-consolidation.md), superseding [ADR 0008](docs/decisions/0008-corosync-on-a-dedicated-switch-local-vlan-vlan-30-stays-infrastructure.md)'s dedicated-switch model — VLAN isolation itself is unchanged, only the physical switch). **Physical re-plan (PROPOSED 2026-09-15, ADRs 0056–0058):** ms-01c joins; msi leaves Ceph but stays a cluster member and Ceph client as the GPU host (2× B70 in PCI_E1/E2, its existing ConnectX-4 Lx in PCI_E3 becomes a 2×25G bond (~31 Gb/s, Gen3 x4) into the Pro-Agg carrying all its VLANs, 82599ES out; amended 2026-09-25), drained only when ms-01c is healthy **and** ms-01a's core-8 fault is resolved — always 3 OSD hosts ([ADR 0056](docs/decisions/0056-msi-leaves-ceph-but-stays-a-non-ceph-cluster-member-as-the-gpu-host-and-its-drain-waits-for-three-healthy-osd-hosts.md)); VLAN 21 moves to a MikroTik CRS518 island (bought 2026-09-25; ADR 0057 originally named the CRS510), 2×25G LACP per OSD host, VLAN 21 never leaves it (management uplink only) ([ADR 0057](docs/decisions/0057-ceph-replication-moves-to-a-dedicated-mikrotik-switch-island-with-2x25g-lacp-per-node-and-vlan-21-never-leaves-it.md), amends 0014); ring1 moves to a USW-Flex-2.5G-8 with STP off, token 5000 ms, msi via an Intel I226-V M.2 card in M2_4, which gates the ring1 move for every member ([ADR 0058](docs/decisions/0058-corosync-ring1-moves-to-a-usw-flex-2-5g-8-with-spanning-tree-disabled.md), amends 0019). End-state rebuild model ([design](docs/rebuild-as-routine-design.md)): durable state on detached Ceph data volumes, guest rootfs disposable ([ADR 0015](docs/decisions/0015-durable-state-rides-detached-ceph-data-volumes-the-guest-rootfs-is-disposable.md); holder is a single never-started **VM** whose raw disks get a one-time format+chown before first consumer start — appendable in-place, never a CT, [ADR 0020](docs/decisions/0020-detached-data-volumes-ride-a-single-never-started-holder-vm-not-a-holder-ct.md)); guest OS images pinned + deliberately rolled ([ADR 0016](docs/decisions/0016-guest-os-images-are-pinned-and-deliberately-rolled-container-tags-stay-latest.md)); guests single-homed on the services VLAN with storage via host bind mounts, squid retired ([ADR 0017](docs/decisions/0017-guests-are-single-homed-on-the-services-vlan-storage-reaches-containers-via-host-bind-mounts.md)). The dual-homed vlan10/vlan40 conventions below (SSH via vlan10, prefix translation) describe the live fleet and are amended at cutover (WP7).

**Post-migration program (decided 2026-08-22):** three management planes — **vlan10 out-of-band** (KVM/AMT/UniFi/switches + a `control` VM with MeshCentral; laptop-only ingress), **vlan30 hypervisor** (nodes, VIP, PDM, PBS, apt-cache, pxe; named guest rules only), **vlan40 services** (Talos + the client-reachable guests); AMT ports go native-10 with the host mgmt tagged 30; this amends ADR 0017's zero-guests-on-VLAN-10 ([ADR 0030](docs/decisions/0030-three-management-planes-vlan10-out-of-band-vlan30-hypervisor-with-pdm-pbs-apt-cache-pxe-vlan40-services.md)). A **3-node Talos Kubernetes cluster is the services plane** (registry + ARC runners first, then the docker-LXC stacks one at a time); the bootstrap tier — DNS, Infisical, PBS, apt-cache, pxe, unifi, plex, LLM, PDM — stays on Proxmox forever; **no further greenfield-replaces for k8s-bound guests** (github-runner 113 → ARC, ADR 0034; mcp 115 was never built out and was retired 2026-08-24 without a k8s successor); control-plane VMs pinned one per node, no HA, third etcd member on worklab until the msi RMA ([ADR 0031](docs/decisions/0031-a-three-node-talos-kubernetes-cluster-becomes-the-services-plane-and-the-bootstrap-tier-stays-on-proxmox.md)). **CI** is ephemeral ARC pods that build their own guests inside PVE pool `ci` (scoped token, VMIDs 5000–5999, isolated `ci` VLAN, reaper; ISO/import uploads land on **`ci-isos`**, a quota-capped cephfs-subdir datastore from `proxmox_host` storage.yml — never the cephfs root, where CI's upstream-named cloud images would collide with and delete the fleet's pinned images; CI guest DNS lives in **`ci.<service domain>`**, a BIND child zone whose `ci-update-key` TSIG (`/infrastructure/ci_tsig_key_secret`, bind9 role) is granted `zonesub` in that zone only — REFUSED anywhere else, so CI never needs and must never hold the fleet's `dhcp-update-key`); the Mac Studio runner is a separate persistent trust tier ([ADR 0032](docs/decisions/0032-ci-runners-are-ephemeral-and-build-their-own-guests-inside-a-pve-pool-on-an-isolated-vlan-and-the-mac-studio-is-a-separate-trust-tier.md)). Phased change plan: [plan doc](docs/ms01-cluster-iac-plan.md#post-migration-change-plan-decided-2026-08-22). **Portainer was retired from `control` 2026-09-13 ([ADR 0053](docs/decisions/0053-portainer-is-retired-from-the-control-lxc-meshcentral-stays.md), amends ADR 0030):** its four agent environments were VMs 203/204/206/211, all retired at P4a–P4d, so it managed nothing; the compose service, role tasks, OIDC provider, homepage tile and the three secrets are gone. Container management is the guest's own Ansible role on the bootstrap tier and Headlamp on the cluster.

**Talos services plane — P3a built 2026-08-23 ([ADR 0033](docs/decisions/0033-talos-p3a-rides-talosctl-from-a-kubernetes-tree-with-the-factory-image-pinned-in-cloud-images-the-worklab-member-via-a-second-bpg-provider-alias-flannel-and-cluster-secrets-in-infisical.md), [plan](docs/talos-p3a-plan.md)):** `talos-cp-a/b/c` (VMIDs 230/231/232, pinned to ms-01a / ms-01b / msi, **never an HA resource**) are plain resources in `terraform/talos.tf` — not the VM module. The temporary worklab member `talos-cp-w` (ADR 0031) retired 2026-09-08 when msi rejoined post-RMA; the `proxmox.worklab` provider alias (`bootstrap.worklab_password`) stays for future worklab-hosted resources. Each node has a services leg (kubelet/etcd/API, Talos L2 VIP at services offset 60) and a Ceph-public VLAN 20 leg for CSI only. Image = factory v1.13.10 nocloud qcow2 pinned in `cloud_images.talos`; running nodes roll with `talosctl upgrade`, not a rebuild — the VMs `ignore_changes` their disk `file_id`, so a pin bump replaces only the downloaded image (before 2026-09-29 it planned a replace of all three control planes). **The talos VMs are OOM-exempt** (2026-08-31: a PSProxmoxVE CI provision spike OOM-killed talos-cp-a's kvm after the 08-27 8→16 GB bump): a `hook_script_file_id` snippet in `talos.tf` (one copy per node on `local:snippets/` — never cephfs, which pvestatd mounts *after* pve-guests has already tried the autostart, 2026-09-09) writes `oom_score_adj -1000` at post-start, so host memory pressure kills the aggressor guest, never a services-plane node — the hookscript fires on the next VM start only, so a hand-started talos VM needs the echo once. See Canonical pipelines.

## Canonical pipelines

- **PKI (ADR 0039 + 0041):** the root is `Homelab Root CA` in Infisical project `homelab-pki` (`make pki-hosts` exports it to `kubernetes/.secrets/homelab-ca.crt`); the fleet-host issuer is the `fleet-hosts` profile (`scripts/pki_hosts.sh`, idempotent by name — a profile under the wrong CA is recreated, which makes every native client re-register). Per-host certs: native ACME (PBS, PDM); `cert_client` (certbot, `cert_client_issuer: fleet` or `letsencrypt`); `ansible/tasks/api_certificate.yml` for a CN or an IP SAN; acme.sh on the Synology ([docs/synology-acme.md](docs/synology-acme.md)). **Every enrolling host holds its own TSIG key `acme-<host>` (`bind9_acme_hosts`), granted only its own `_acme-challenge` name — no wildcard, no shared key (ADR 0050). A new ACME host = a name in that list + a run of the `dns` play (twice on a new key) before its first enrollment.** No hand-written cert on a fleet host; no `insecure = true` on a cluster provider; no fingerprint pin on a PBS consumer or a PDM remote ([docs/pdm-remotes.md](docs/pdm-remotes.md)). Trust: `make ca-trust`, Talos via `make talos-apply`, workstation python via `kubernetes/.secrets/ca-bundle.pem`, pods via the `homelab-root-ca` ConfigMap. The vault's machine URL is one binding, `bootstrap_config.infisical_url` (ADR 0042).
- **Kubernetes / Talos ([ADR 0048](docs/decisions/0048-flux-reconciles-the-kubernetes-services-plane-from-the-repo-replacing-the-kubernetes-shell-deploy-layer-in-app-configuration-is-ansible-and-the-talos-lifecycle-stays-on-talos-sh.md)):** three owners, no fourth. **Talos lifecycle** = `kubernetes/talos/talos.sh` (configs from the `talos_nodes` terraform output + Infisical `/talos`; `make talos-secrets|apply|bootstrap`; `make talos-apply` is also how nodes pick up a changed root CA or kubelet arg) — **Ansible never touches a Talos node**, no second tool may render machine configs, `kubeconfig`/`talosconfig` live in `kubernetes/talos/.secrets/` (gitignored; `make talos-secrets` re-pulls). **Workloads** = Flux reconciling this public repo with no credential: one `Kustomization` per tree in `kubernetes/flux/apps/<tree>.yaml` (`postBuild.substituteFrom` the `cluster-bindings` ConfigMap), charts as pinned `HelmRelease`s in `kubernetes/<tree>/helm.yaml`; **a push to `main` is the deploy** — `make flux-reconcile TREE=<tree>` only skips the interval, and `make flux-check` refuses a tree whose `${VAR}` has no binding or whose pod-template container lacks a cpu+memory request (#31). Substitution is **strict** (an unset `${VAR}` fails the Kustomization); `axosyslog.conf` and `valheim-playfab-status.mjs` carry foreign `${…}` and are `kustomize.toolkit.fluxcd.io/substitute: disabled`; a binding-only change does not roll a pod. **Seed + in-app tail** = `ansible/playbooks/kubernetes.yml`: `make k8s-seed` (an allowlist, nothing else; needs `make pki-hosts` first), `make k8s-apps`, `make k8s-smoke` (fail-loud), `make k8s-update` (deletes the pods of `:latest` workloads so they re-pull through Zot — never `rollout restart`, Flux reverts the annotation and it bounces twice), `make plex-pbs-image`. Second run of seed and apps = 0 changed. **P3b add-ons (ADR 0034):** MetalLB L2 owns services offsets **64–79** (tree `metallb`; speakers need `ignoreExcludeLB` because every node is a control plane). cert-manager's `homelab-ca` ClusterIssuer is a **`ca` issuer over an intermediate signed by the Infisical internal root `Homelab Root CA`** (ADR 0039): `make k8s-seed` signs a fresh intermediate whenever the cluster's `tls.crt` does not verify against the root; the intermediate is disposable (never exported). Infisical's ACME server is HTTP-01 only; the cluster never uses it. The CA's DR path is the nightly `infisical_pbs_backup.sh` Postgres dump to PBS ns `databases` — verify by snapshot recency, `make infisical-backup` cannot carry PKI keys. Zot is `registry.<service domain>`, blobs on a ceph-rbd PVC; the name is pinned into `machine.registries`, so a rename is push the `zot` tree → restart the statefulset (Zot does not reload a renewed TLS secret) → `make talos-apply` → `make k8s-update` for every image-ref consumer. ARC scale sets (`psproxmoxve`, `pbs-collection`) are **hostNetwork dind pods pinned to talos-cp-a** sharing one RWO cache PVC; `runs-on:` must be the scale-set *name*. The ci-reaper CronJob destroys pool-`ci` guests older than 6 h. pfSense CI VLAN rules are hand-managed: [docs/pfsense-ci-vlan.md](docs/pfsense-ci-vlan.md). **P4a (ADR 0035):** HTTP apps publish a plain `Ingress` (`ingressClassName: traefik`, no `tls:` block) on `<name>.<service domain>` — Traefik sits on offset **65** with the Let's Encrypt wildcard as its default TLS store, and **external-dns publishes every Ingress host into BIND**. **Runtime secrets reach a pod only through an `InfisicalSecret` in the component's tree**; the single `kubectl create secret` in the cluster is `infisical-universal-auth` (a `make k8s-seed` object) — never add one-off create paths (ARC's two are grandfathered). The literal `${REGISTRY}` stays in every tracked image ref (renovate's image regex keys on it); a `kubernetes/<app>/` tree never contains a private address. **P4b (ADR 0036):** monitoring is tree `monitoring` (one `InfisicalSecret` on `/monitoring`, telegraf targets rendered from `vms.yaml` into a seed ConfigMap by `make k8s-seed`); **axosyslog is a MetalLB `LoadBalancer` at services offset 66 with `externalTrafficPolicy: Local`** (Cluster policy would SNAT every node to the same name) — `openobserve_listen_host` is the services prefix + `monitoring_syslog_offset`, never a `hostvars` lookup; pfSense's and UniFi's syslog targets are hand-set in their UIs. The OpenObserve image stays pinned (`v0.92.0-rc2`, schema 46). Node collectors: `make proxmox-hosts TAGS=node-exporter`. `make monitoring-users` recreates `monitoring@pve` + its token. ConfigMaps go through server-side apply (the dashboards exceed the last-applied annotation cap). **P4c (ADR 0037):** tree `plex-services` (tail `make k8s-apps`; Services keep the compose names so the Cloudflare tunnel routes resolve unchanged); the media tree is a **kubelet-mounted NFS PV**; SABnzbd scratch is a **node-local `local-zfs` disk on every Talos VM, mounted at `/var/mnt/scratch` and used as a hostPath**, never NFS and never Ceph; every tree with an in-tree Postgres includes **`kubernetes/pg-backup/`** as `../pg-backup`, parameterized through its `postBuild.substitute` (`NS PG_USER PG_SECRET BACKUP_ID SCHEDULE`, #37), whose `proxmox-backup-client` image is the registry's one local push (`make plex-pbs-image`, rebuild when the PBS major rolls). Kuma rows are in `ansible/playbooks/uptime-kuma.yml`. Non-root pods (seerr/recyclarr/libation) need `fsGroup: 2000`; postgres mounts `subPath: data/data`. **P4d (ADR 0038):** tree `games`: the `valheim` pod = the server + the `valheim-status` PlayFab sidecar keyed by server name (never re-pin an entity ID, it rotates on every recreate); **UDP 2456–2458 are a MetalLB `LoadBalancer` at services offset 67 with `externalTrafficPolicy: Local`** (the pfSense WG_VPS forward targets it). MetalLB offsets live in `vlans.yaml` `metallb.offsets` — a new pinned LoadBalancer is one entry there plus `metallb.io/loadBalancerIPs: ${<NAME>_IP}` in its tree, never a literal (#33). MeshCentral stays on `control` (ADR 0030 stands).

**P5 — DNS, certs, SSO, Jellyfin (APPROVED 2026-08-24, [ADR 0040](docs/decisions/0040-p5-real-dns-on-a-flat-public-domain-zone-bind-fed-by-nsupdate-external-dns-adguard-forwards-rewrites-retired-let-s-encrypt-dns-01-wildcards-as-traefik-s-default-cert-two-authentik-realms-split-by-audience-jellyfin-over-the-vps-relay-with-ldap-auth.md), [plan](docs/p5-dns-sso-jellyfin-plan.md)):** the internal namespace is a flat zone on an operator-owned public domain (`vlans.yaml` `service_domain`, `media_domain`, `internal_zones`), BIND authoritative with every record a dynamic update, AdGuard forwards. **P5a:** `make dns-records` (`ansible/tasks/dns_records.yml`, also the tail of the `dns` play) pushes guests/nodes, VIPs, MetalLB names and mirrored public records over `community.general.nsupdate` — nothing prunes, retired names come out by hand (`nsupdate`); `kubernetes/external-dns/` owns the Ingress hosts (`txtOwnerId: talos`, `policy: sync`). `vpn` is looked up on the public copy at run time, never a static binding. AdGuard forwards each internal zone to BIND (`adguard_zone_forwards`, converged through `/control/dns_config` because the config template is initial-only); the resolver VIP never depends on BIND. **P5b:** Traefik's default cert is a **Let's Encrypt DNS-01 wildcard** (`kubernetes/traefik/certificate.yaml` `wildcard-tls`; a rehearsal is `issuerRef: letsencrypt-staging` in that file, pushed) with the Cloudflare token from **`/infrastructure/cloudflare_dns_api_token`** — **the `infisical-universal-auth` seed Secret must exist before the `traefik` tree's Certificate can issue on a fresh cluster** (`make k8s-seed` first). cert-manager's DNS-01 self-check is pinned to `1.1.1.1`/`1.0.0.1` because the AdGuard → BIND chain never sees the `_acme-challenge` TXT (scoped ADR 0012 exception). `homelab-ca` stays the issuer for the registry and everything non-browser. Kuma carries **zero `ignore_tls`** rows. No tracked file carries a media-domain literal (`${MEDIA_DOMAIN}`, `module.network.media_domain`). **P5c:** the internal realm is LXC 213 (ADR 0049); the external is tree `authentik-ext` (tail `make k8s-apps`, `auth.<media domain>`, the tunnel route is a dashboard step); each realm has a Postgres 17, a nightly `pg_dumpall` → PBS ns `databases`, and an `InfisicalSecret` on its folder (hex only, so nothing downstream quotes). **All configuration is a blueprint**: the embedded outpost needs `config.authentik_host` set (unset, every 302 targets `http://localhost`) and `grant_types` must be explicit (the blueprint default is `[]` = "Invalid grant_type"). **Forward-auth is gated to the `authentik Admins` group** — a new operator account must be added to that group or every forward-auth surface denies it. An Ingress opts in with `traefik.ingress.kubernetes.io/router.middlewares: traefik-forward-auth@kubernetescrd`; **Uptime Kuma stays outside forward-auth** (the 302 kills the socket.io handshake); machine paths use svc DNS and never see forward-auth. MeshCentral requires the userid in `meshcentral_manage_all_device_groups` **in addition to** full siteadmin; PVE/PBS/PDM realms are hand steps in [docs/authentik-setup.md](docs/authentik-setup.md). **pfSense is SAML2, not OIDC** (ADR 0043): `sign_assertion: true` (a signing keypair with neither sign flag is rejected as invalid), the application bound to a `pfsense-admins` group, package (removed by a pfSense upgrade) and SP settings are operator hand steps. **The firewall's admin auth depends on the services plane**, and a break-glass username must never collide with an authentik username (pfSense silently grants a same-named local account's privileges). The Infisical operator restarts every auto-reload Deployment once at its first resync after a fresh deploy — expected, not a loop. **Passkey login:** `default-authentication-flow-passwordless` is the identification stage's `passwordless_flow`; password + passkey-as-second-factor stays the fallback; pointing the brand's `flow_authentication` at it locks out every account with no passkey — deliberately not done. **P5d:** tree `jellyfin` (tail `make k8s-apps`) at `jellyfin.<media domain>`, media via its **own read-only NFS PV/PVC** (claims cannot cross namespaces), no forward-auth (TV apps); auth is the **LDAP-Auth plugin against `ak-outpost-ldap.authentik-ext.svc:389`** (username attribute `cn` — authentik's `uid` is a hash); the `k8s_apps` role drives setup through the API from inside the pod. External path ends **pfSense WG_VPS pass + port-forward 443 → Traefik LB .65 (hand step, [docs/pfsense-wireguard-vps-peer.md](docs/pfsense-wireguard-vps-peer.md))**; Jellyfin never touches the Cloudflare tunnel. **P5e:** BIND serves only the `internal_zones` forward zones plus the per-VLAN reverse zones; AdGuard's role converges the **whole** upstream list and deletes every rewrite on each run. The AdGuard play cannot run `--limit` to one instance (the pair shares its seeded secrets through `hostvars`); run both. pfSense's DHCP domain/DDNS role is hand-run (password-gated sudo).

**P6 — the deliberate VM roll landed 2026-08-25 ([plan](docs/p6-vm-roll-plan.md); no new ADR — consequence notes on ADRs 0016/0021/0039/0040):** the VM snippet (`terraform/modules/proxmox-vm/templates/user-data.yaml.tmpl`) sets `fqdn` = `<name>.<service domain>` and writes the ADR 0021 `Proxy-Auto-Detect` probe, byte-identical to the `apt_proxy` role's copy. Infisical rolls by **restoring the PBS dump** (`make rebuild-infisical` → `make infisical-restore`), never by re-bootstrapping; unifi is restored through the setup wizard from an operator-downloaded `.unifi` backup; pdm's remotes + authentik realm are re-added by hand. Cloudflare AAAA records are canonicalized with `cidrhost(<v6>/128, 0)`. A bare `terraform plan` outside `make` hangs on a variable prompt while holding the state lock.

**P7 — per-host PKI landed 2026-08-25 ([ADR 0041](docs/decisions/0041-p7-per-host-certs-are-acme-dns-01-against-infisical-through-bind-s-dynamic-update-path-on-a-scoped-tsig-key-pbs-fingerprint-pins-retire-infisical-s-own-cert-is-api-issued-behind-caddy.md), [plan](docs/p7-per-host-pki-plan.md)):** every fleet host serves and trusts `Homelab Root CA` certs. The issuer sits under an **RSA 4096 intermediate `Homelab Hosts CA`** because Infisical only signs a CSR whose key family matches the CA's. Challenge TXTs ride BIND's dynamic-update path; Infisical resolves them at the BIND VIP (`ACME_DNS_RESOLVER_SERVERS`). **PBS + PDM** use their native ACME clients (the nsupdate plugin runs as `nobody`, so the key is `/etc/proxmox-acme/tsig.key` root:nogroup 0640; PDM's domain list lives in `acme/certificate.cfg`, not `node.cfg`). **PVE nodes** use certbot `dns-rfc2136` (`cert_client`, deploy hook `pvenode cert set`) — PVE's own ACME client rejects the CRLF-terminated PEM Infisical serves. **Infisical** and **control** get API-issued certs through `ansible/tasks/api_certificate.yml`. Terraform providers run `insecure = false` (`TF_VAR_insecure=true` exists for a hosts apply against self-signed nodes). Renewal proof: `certbot renew --force-renewal --no-random-sleep-on-renew --cert-name <fqdn>` on a node (**`--dry-run` goes to Let's Encrypt staging, never the private directory**), `proxmox-backup-manager acme cert order --force` on PBS.

**P8 — the vault's machine URL is https landed 2026-08-25 ([ADR 0042](docs/decisions/0042-p8-the-vault-s-machine-url-is-https-on-the-service-domain-python-clients-trust-a-certifi-root-bundle-the-operator-and-probes-mount-the-root-8080-binds-to-localhost-the-vault-s-tls-material-rides-the-pbs-dump.md), [plan](docs/p8-vault-https-plan.md)):** `bootstrap_config.infisical_url` = `https://infisical.<service domain>` and every consumer derives from it. The compose publishes 8080 on `127.0.0.1` whenever the binding is https. The nightly `infisical_pbs_backup.sh` pxar carries `tls/key.pem` + `tls/cert.pem`, so `make rebuild-infisical` logs in over https right after the restore. Escape hatch for a pre-P8 dump restored into a fresh VM (no `tls/`): `sops --set` the binding back to `http://<services ip>:8080`, `make ansible infisical` twice, flip back, once more. The `infisical.vault` reads use `url` + `token_auth` (`login_data` is a no_log argument).

## Before You Start Any Task

1. **Read before writing.** Always read the files you intend to modify and their related files (defaults, templates, tasks) before making changes. Understand the existing patterns.
2. **Check the inventory.** VM names, IPs, and group membership are in `ansible/inventory/vms.yaml` (Terraform-generated). Do not hardcode IPs.
3. **Check `group_vars/all.yml`** for existing variables before adding new ones to role defaults — `all.yml` overrides role defaults and causes silent variable collisions.

## Greenfield Philosophy

- **No migration tasks.** Do not write version-check conditionals, one-time migration logic, or upgrade paths. Every role should work correctly on a fresh VM and be idempotent on re-run.
- **No version pinning without reason.** Use `latest` tags for Docker images unless there's a specific compatibility constraint. Guest **OS images** are the exception with a reason: pinned by version + checksum and deliberately rolled ([ADR 0016](docs/decisions/0016-guest-os-images-are-pinned-and-deliberately-rolled-container-tags-stay-latest.md)) — `latest` OS images made plan output unreadable and `make apply` a fleet-replacement foot-gun.
- **Idempotent everything.** Every task must be safe to run repeatedly. Use `creates:`, `when:`, registered variables, and `changed_when:` to prevent unnecessary changes.
- **REPLACE_ME sentinel.** Secrets that haven't been generated yet use the string `REPLACE_ME`. The `generate_secret.yml` task checks for this value to decide whether to generate.

## Secrets Handling

### Two-Tier Architecture
- **Tier 1 (Bootstrap):** `ansible/group_vars/bootstrap.sops.yml` — SOPS-encrypted. Contains only provider credentials (Proxmox, Vultr, Cloudflare), Infisical auth (client_id, client_secret, admin creds), and external secrets (user-provided API keys, passwords). Referenced as `bootstrap.key_name` or `bootstrap_config.key_name`.
- **Tier 2 (Runtime):** Infisical VM — stores ALL runtime secrets, organized into the folders listed in the Infisical Folder Ownership table below (one owner role per folder; no second list is kept here).
  Root `/` is **empty** — all secrets live in named subfolders.
- **No SOPS fallback.** If Infisical is unreachable, the deploy fails with a clear error. `secrets.sops.yml` is a DR artifact only (produced by `make infisical-backup`), never used at runtime.

### The `secrets` Fact
All secrets are loaded into a single `secrets` fact that matches the `secrets.sops.yml` structure:
- Root and `/shared` Infisical paths → flat keys: `secrets.key_name`
- Nested paths → nested dicts: `secrets.monitoring.key_name`, `secrets.plex_services.key_name`
- Key names are lowercased with hyphens converted to underscores

### Secret Delivery to Containers
All runtime secrets flow through **Infisical Agent env_files**. The agent polls Infisical, renders Go templates to `.env` files on disk, and containers read them via `env_file:` directives.

- Agent env_file path: `/etc/infisical/secrets/<name>.env`
- Go templates: `ansible/roles/infisical_client/templates/secrets/*.tpl.j2`
- Special case: Recyclarr uses `secrets.yml` with `!secret` YAML tags instead of env vars (on the cluster it is an item of the `plex-services-secrets` managed Secret, mounted at `/config/secrets.yml`).
- Agent exec hooks: When a rendered file changes, the agent runs the configured `post_command` to restart the affected container (see `infisical_agent_templates` in playbook vars).
- **No baked secrets.** No `{{ secrets.xxx }}` appears in any docker-compose template.

### `generate_secret.yml` Calling Convention
Required variables:
```yaml
- ansible.builtin.include_tasks: "{{ playbook_dir }}/../tasks/generate_secret.yml"
  vars:
    secret_key: "my_password"                # lowercase key name (REQUIRED)
    secret_gen_cmd: "openssl rand -hex 32"   # shell command that prints value (REQUIRED)
    secret_comment: "Description for Infisical" # human-readable comment (REQUIRED)
    secret_infisical_path: "/monitoring"      # Infisical folder (REQUIRED — no default)
    secret_dict_path: "monitoring"            # nested dict key in secrets fact (REQUIRED)
    # Optional:
    secret_run_on: "{{ inventory_hostname }}" # host to run command on (default: "localhost")
```

### Rules
- **Never put secrets in `vars.auto.tfvars`** — enforced by pre-commit hook.
- **Never commit unencrypted secrets** — SOPS files only. The `homelab-security-guardrails` pre-commit hook (`scripts/security_guardrails.sh --staged`) runs `gitleaks protect --staged` plus the private-address guard; `detect-private-key` and `no-tfvars-secrets` cover keys and tfvars.
- **Always use `{{ secrets.key_name }}`** — never reference bootstrap-tier secrets in templates (except the Infisical role itself which needs bootstrap creds before Infisical exists).
- **Resolve `secret_comment` to a fact** before passing to `infisical_write_secret.yml` to avoid recursive template loops. The `generate_secret.yml` task handles this automatically.
- **Use `printf '%s' value`** not `echo -n value` in generation commands — some shells output `-n` literally.
- **All secret key names must be lowercase with underscores** — no UPPERCASE keys in Infisical. Convention: `{component}_{secret_type}` (e.g., `pbs_admin_password`, `grafana_admin_password`).

**Key rules:**
- The `ansible-admin` identity's universal auth trusts `0.0.0.0/0` with a non-expiring client secret — deliberately, not by omission: Infisical's IP allowlist is a paid-plan feature and the self-hosted free instance answers any other value with a 400 (#21, 2026-09-10). The compensating control is the vault's reach: the services VLAN and pfSense's rules, not the identity.
- "Owner Role" is the Ansible role whose tasks write secrets to this folder via `generate_secret.yml` or `infisical_write_secret.yml`.
- "Agent Readers" are VMs whose Infisical Agent templates include `with secret` blocks reading from this folder, or cluster namespaces with an `InfisicalSecret` on it (ADR 0035).
- VMs without agents (vps, pfsense, pbs, infrastructure) consume secrets at Ansible deploy time via the `secrets` fact — not via agent.
- `/homepage` has no owner role that generates secrets — it contains only user-provided external credentials seeded from `bootstrap.sops.yml`.
- **A new folder must also be added to the nested-path loop in `ansible/tasks/infisical_login.yml`** — the `secrets` fact only loads the folders listed there, so an unlisted folder's secrets look absent to `generate_secret.yml` and get REGENERATED on every run (Portainer admin password rotated out from under the live instance, 2026-08-22). The loop is consumer-driven: `docker`, `plex-services`, `pfsense` and `talos` are cluster/hand-owned and were dropped from it 2026-09-10 (#27) — `jellyfin` stays because `k8s_apps` generates into it. Before dropping a folder, `git grep secret_dict_path` as well as `secrets.<folder>`.
- When adding a new secret, find the correct owner folder first. If no existing folder fits, consider whether the secret truly needs a new folder or should be added to an existing one.

## Ansible Conventions

### Playbook Structure
- Playbooks import `full_pre_tasks.yml` which loads: local overrides → bootstrap SOPS → secrets (Infisical, hard fail if unreachable) → VLAN definitions → VLAN prefix computation → dns_zones. **Infisical is read once per run (#27, 2026-09-10):** the first play through the loader logs in, reads the folders and publishes `secrets` + `infisical_login` to localhost (`load_secrets.yml`); every later play copies them from `hostvars['localhost']` — `infrastructure.yml`'s pre-flight play is tagged `always` so a `--tags` run loads there, and a `--limit <vm>` run (which excludes localhost) loads in the limited play. `generate_secret.yml` republishes the fact after a write so a later play sees the new key. The admin-API token is the same session: `tasks/infisical_admin_token.yml` sets `_admin_token` from it and only logs in from a play with no loader (#28). Facts are cached an hour under `.ansible-facts/` (`gathering = smart`; `make clean-ssh`, and so every `make inventory`/`build`/`rebuild`, drops the cache — a rebuilt guest must never read hour-old `ansible_distribution`).
- Playbooks are role-based — inline tasks only in bootstrap (`docker-config.yml` was deleted 2026-09-10, #25: its last caller was infisical, and `make ansible infisical` is idempotent and covers it).
- Each play targets specific hosts via `hosts:` and runs the appropriate roles.
- `site.yml` imports `infrastructure.yml` then `services.yml`.

### VLAN Prefix Facts
Pre_tasks compute these facts from `network-data/vlans.yaml`:
- `mgmt_vlan_prefix`, `services_vlan_prefix`, `storage_vlan_prefix`, `core_vlan_prefix`
- Cross-VLAN IP translation: `{{ ansible_host | replace(mgmt_vlan_prefix, services_vlan_prefix) }}`
- `internal_network_cidr`: the `/12` covering all VLANs
- **SSH uses vlan10 (management) IPs by default.** `ansible_host` resolves to the management VLAN IP. When running ad-hoc SSH commands, use the vlan10 IP (i.e., `ansible_host` or the address from `vms.yaml`).

### Role Structure
- `tasks/main.yml` — entry point, may include subtask files
- `defaults/main.yml` — default variables (use `| default('')` for secrets that may not be set)
- `templates/` — Jinja2 templates (`.j2` extension)
- `handlers/main.yml` — handlers (restart services, etc.)
- `meta/main.yml` — dependencies (rare)
- No `vars/main.yml` unless truly constant (prefer defaults for overridability)

### Template Conventions
- Docker-compose templates live at `roles/<role>/templates/docker-compose.yml.j2`
- Templates are deployed to `/opt/<service>/` on the target VM
- Use `mode: '0600'` for files containing secrets, `'0644'` for non-sensitive configs
- Use `replace()` for literal string substitutions — do NOT use `regex_replace` with backslash escaping across YAML/Jinja2 layers

### Task Conventions
- Use FQCNs: `ansible.builtin.template`, `community.docker.docker_compose_v2`, etc.
- Use `run_once: true` for tasks that should only execute on one host in a play
- Use `delegate_to: localhost` + `become: false` for local/API operations
- `is succeeded` returns TRUE for skipped tasks — always add `is not skipped` when gating on a registered variable from a conditionally-skipped task
- `docker_compose_v2`: `restarted` is a `state` value, not a separate parameter

### Tags Strategy
Both `infrastructure.yml` and `services.yml` have play-level tags for targeted deploys:

**infrastructure.yml tags:** `phase1`, `phase2`, `phase3`, `timezone`, `ca-trust`, `bindings`, `dns`, `bind9`, `adguard`, `infisical`, `proxmox-backup`, `unifi`, `apt-cache`, `pxe`, `control`, `pdm`, `authentik`, `telegraf`, `monitoring`, `monitoring-users`, `users` (the play-level `tags:` in `ansible/playbooks/infrastructure.yml` are the source of truth)

**services.yml tags:** `plex`, `llm`, `mcp`, `scratch`, `telegraf` (homepage, plex-services and the games host are Flux trees `homepage`, `plex-services`, `games`, not plays)

**How tags work with pre_tasks:**
- All `pre_tasks` blocks have `tags: [always]`, so secrets/VLANs/facts always load regardless of `--tags` filter.
- The `infisical_client` role's "Enable and start infisical-agent" task is tagged `always` — even when filtering by tags within a play, the agent is guaranteed to be running.
- Tags filter at the **play** level: `--tags docker` runs only the docker play (and its pre_tasks).

**Usage via Makefile:** Pass `TAGS=` to any ansible target:
```bash
make ansible plex TAGS=plex              # only the plex play
make ansible-infra TAGS=phase1           # infrastructure phase 1 only
make ansible-services TAGS=plex,llm      # plex + llm plays
```

### Variable Sourcing Priority
1. `ansible/group_vars/local/all.yml` — local overrides (gitignored)
2. `ansible/group_vars/all.yml` — global vars (overrides role defaults!)
3. `ansible/roles/<role>/defaults/main.yml` — role defaults

## Docker Conventions

- **Compose file location:** `/opt/<service>/docker-compose.yml` on the VM (e.g., `/opt/infisical/`, `/opt/control/`). Each role defines a `*_base_dir` default variable for its path.
- **Restart policy:** `restart: unless-stopped` for all containers
- **Logging:** Docker daemon configured for syslog to OpenObserve (`configure_docker_logging.yml`)
- **NFS on the remaining compose hosts (authentik, control, infisical):** none. Storage reaches containers through host bind mounts (ADR 0017); the cluster's media trees are kubelet-mounted NFS PVs (ADR 0037).
- **NFS tuning:** `nfsvers=4.1,hard,intr,noatime,rsize=1048576,wsize=1048576,nconnect=4` (Synology negotiates down to 128KB rsize/wsize)
- **Restart on change:** Register template results, restart containers only `when: <registered_var> is changed`
- **env_file for Infisical agent secrets:** Path is `/etc/infisical/secrets/<name>.env`, rendered by the Infisical agent from Go templates in `infisical_client/templates/secrets/`

## Terraform Conventions

### Structure
- Single fleet project at `terraform/` with `main.tf`, `vm-configs.tf`, `variables.tf`, `outputs.tf`, `provider.tf`
- **`terraform/hosts/`** is a SEPARATE root (own local state) for the host/cluster plane — host networking (bpg `network_linux_bond/bridge/vlan`), and later cluster options / Ceph pool / SDN / ACME (ADR-0002, WP1). Two-stage apply ordering: `hosts/` (rare) before `terraform/` (routine). Answer-file install → `make node-iso` (bake) → `make node-bootstrap` (token) → `make hosts-apply ENDPOINT=…` → `make proxmox-hosts` (WP2 Ansible cluster plane: mgmt re-home, corosync rings, Ceph with the ADR-0009 public/cluster split, keepalived VIP — needs `inventory/proxmox.yaml` + the WP2 fields in `host-bindings.yaml`). It manages the X710/82599ES bond→`vmbr0`→VLAN 20/40 and never touches the VLAN 30 install link, the ConnectX 25G port (switched Ceph VLAN 21 — [ADR 0014](docs/decisions/0014-ceph-cluster-network-rides-switched-25g-sfp28-ports-not-a-switchless-mesh.md)), or ring1. Baked `answer-*.toml` + `nodes.auto.tfvars` + `network-data/local/host-bindings.yaml` are gitignored (carry MAC/IP/root-hash); templates + `*.example` are tracked. See `terraform/hosts/README.md`.
- `vm-configs.tf` defines all VMs in `local.infrastructure_vms` and `local.services_vms`
- **Storage entries vs backup jobs (boundary amended 2026-08-11, B3):** PVE *storage entries* are cluster-plane and Ansible-owned — bpg has no storage-definition resource, so Ceph storage defs come from the WP2 `proxmox_host` role and the PBS entry from `make backup-finalize` (once per cluster, after PBS provisioning). PVE *backup jobs* (`backup_jobs` var → `backup-jobs.tf`) live in the fleet root because they select fleet VMIDs and change with fleet composition; `backup-finalize` is their one-time prerequisite. Putting jobs in `terraform/hosts/` would couple the rare-apply host root to every fleet change.
- `vars.auto.tfvars` for non-sensitive config only

### Secrets Flow
- Makefile reads `bootstrap.sops.yml` via `sops -d --extract` and exports as `TF_VAR_*` env vars
- The five `TF_VAR_*` secrets are target-specific exports on `TF_TARGETS` (the terraform-reaching targets), recursively expanded through the memoized `_secret` helper — a plain `export X := …` at top level decrypts for every target (`make clean-ssh` used to hand the PVE root password to kubectl), and a target-specific `:=` expands once per listed target at parse time (150 sops calls). A new terraform-invoking target must be added to `TF_TARGETS` or its variables prompt (#12, 2026-09-10)
- `terraform refresh` updates state but NOT outputs — use `terraform apply -refresh-only -auto-approve`
- Targeted applies (`-target`) don't recompute `ansible_inventory_yaml` either — a brand-new guest never lands in `vms.yaml` from the targeted apply alone; `make build` runs a refresh-only apply before `inventory` for exactly this reason (found building apt-cache, 2026-08-11)

### VM Configuration Patterns
- Each VM: `name`, `vm_id`, `vlans` (list), `ip_offset`, `cores`, `memory`, `disk_size`; `node_name` pins placement; `pci_devices = [{ id = "<BDF>" }]` passes a host PCI device through (VM only, q35 — a bare `0000:01:00` takes every function)
- `protected = true` for critical VMs (currently: infisical). Override with `var.unprotect`
- `lifecycle.ignore_changes` on cloud-init file IDs to prevent VM recreation on template changes
- Management VLAN is always first interface; `vm_id` → static IP, no `vm_id` → DHCP
- MAC addresses: `52:54:00:{random}:{vlan_id/256}:{vlan_id%256}`
- Use `coalesce()` carefully — not short-circuit. Use `try()` for fallbacks referencing resources that may not exist during `-target` operations

### Inventory Generation
- `make inventory` runs `terraform output -raw ansible_inventory_yaml > ansible/inventory/vms.yaml`
- Always runs `clean-ssh` first to remove stale SSH keys

## Change Discipline

1. **Read the role and its templates** before modifying anything
2. **Check the `generate_secret.yml` pattern** when adding new secrets — follow the existing convention exactly
3. **Test idempotency** — running the same playbook twice should produce zero changes on the second run
4. **Never modify Terraform-generated files** — `ansible/inventory/vms.yaml` is generated by `make inventory`
5. **Pre-commit hooks run automatically** — trailing-whitespace and end-of-file-fixer modify staged files; re-stage after hook failures

## Documentation Discipline

### README
- Update `README.md` any time you change: make targets, prerequisites, first-time setup
  steps, supported VMs, or the overall architecture
- Do NOT update README for internal refactors that don't affect how a user operates the repo
- If you're unsure whether a change warrants a README update, err on the side of updating it

  resolve one of the Known Inconsistencies

## Git Discipline

### When to commit
This section is the operator's durable pre-authorization to commit in this repo (global rule "Git & delivery discipline"): sessions commit at these checkpoints without asking. Pushing stays gated.
- After each logical unit of work is complete and verified — not mid-task
- After any change that touches more than one file
- Before running destructive operations (`make rebuild`, `make clean`, terraform destroy)
- After updating CLAUDE.md or README.md
- Never commit in the middle of a multi-phase task — complete the phase first

### Commit message format
- Use imperative present tense: "Add homepage Infisical agent templates" not "Added..."
- First line: 50 chars max, no period
- If the change warrants explanation, add a blank line then a body
- Reference the affected role/component: "ansible/roles/homepage: add agent env_file support"

### Deploy gate
- Under ADR 0048 a merge to `main` is a cluster deploy. The `main` ruleset today has no pull-request or review rule; the required protection (PR + code-owner review, narrow CODEOWNERS on `kubernetes/**` + `k8s_seed` + governance paths, `validate` as a required check, no App bypass, Apps never merge or push `main`) is specified in [docs/repo-deploy-gate.md](docs/repo-deploy-gate.md) and is a prerequisite before any agent identity authors PRs here (ADR 0052).

### What never to commit
- Any file matching `*.sops.yml` that hasn't been encrypted with `sops --encrypt` first
- `vlans.yaml`, `private_bindings.yaml`, `infisical-backup.yml` (gitignored — if git
  somehow picks them up, stop immediately)
- Generated files: `ansible/inventory/vms.yaml`
- Anything with a raw secret value — pre-commit hooks should catch this but don't rely on them

### Before committing
- Run `make setup-hooks` if hooks aren't installed
- Pre-commit hooks will auto-fix whitespace/EOF — re-stage modified files after hook runs
- If gitleaks (inside `security_guardrails.sh`), `detect-private-key` or `no-tfvars-secrets` fires, do NOT use `--no-verify` to bypass — fix the leak first


## What Never To Do

One rule per bullet: the reason and the tell that proves it. The incident behind each rule (dates, what was tried, false leads) is in [docs/LESSONS.md](docs/LESSONS.md) under the same heading.

- **Never hardcode IPs in templates** — derive from `ansible_host`, VLAN prefix replacement, or `hostvars`
- **Never put a specific RFC 1918 address or the internal domain in a tracked file** — the repo is public, so IPs/subnets/domains are bindings (gitignored or derived from `network_data.*` facts). The `security_guardrails.sh` pre-commit hook blocks added lines containing them.
- **Never leave a node armed for PXE install, and never assume PXE is wipe-safe without the arm gate** — the answer server serves an install answer (→ unattended disk wipe) while `answers/armed/<node>` is present and unexpired (`make node-arm`). Arm right before an install and let it auto-expire; if you arm and don't install, `make node-disarm`.
- **Never flip `tf-node-install`'s native VLAN — worklab's untagged mgmt (`.30.75` on `vmbr0`/`nic0`, Pro-Max p46) rides that shared profile** — AMT on the vlan10 OOB plane is the separate `tf-node-oob` profile bound per port (`unifi-ports.yaml`). Per node, re-IP AMT over the old path first (it goes dark), then `unifi-apply` the port, and verify from a vlan10 host (control 212) — the operator Mac cannot reach vlan10 by policy.
- **Never enable Secure Boot on a node whose ESP is still systemd-boot — convert it to shim+grub first.** `proxmox-boot-tool` gives an SB-off install unsigned **systemd-boot**, and enabling SB in BIOS then makes the firmware reject the loader. Booted SB-off, run `proxmox-boot-tool init /dev/<esp> grub` on each ESP, verify `efibootmgr -v` shows `\EFI\proxmox\shimx64.efi`, then enable SB in BIOS.
- **Never reconfigure host networking over the interface carrying the PVE API session** — `terraform/hosts/` applies run over the stable VLAN 30 mgmt link and never touch it; a re-apply must never drop the link Terraform is talking over (ADR-0002)
- **Never DHCP an LXC** — static IPs only, so plan-time inventory is deterministic (ADR-0003)
- **Never put secrets in `vars.auto.tfvars`** — pre-commit hook blocks this
- **Never set `vlan_id` on SDN VNETs** — only for physical bridges (`vmbr*`)
- **Never use `regex_replace` for literal string substitution** — use `replace()` instead
- **Never write a source-based `routing-policy` rule with the interface prefix** — it must be `/32`: a `from: <ip>/24` rule matches every host in the subnet, so any *forwarded* packet from a neighbour on that VLAN is looked up in the per-VLAN table, which has no bridge route, and is sent back out the gateway. Symptom: containers reach the internet fine but hang on every connection to a host on that interface's own subnet
- **The AdGuard config template is `when: not _adguard_config.stat.exists` — "initial only"** — AdGuardHome rewrites its own YAML at runtime, so editing `adguardhome.yaml.j2` affects fresh VMs only. On a running host edit the live config (stop service → edit → start) or use the AdGuard API (`/control/dns_config`), and verify the edit survived a service restart.
- **Never write a bare `$` in a docker-compose `environment:` value that must expand inside the container** — compose interpolates `${...}` at parse time on the Ansible host and silently substitutes empty. Escape as `$$`.
- **Never point a container running as a non-root user at a bare `/etc/infisical/secrets/<file>` via a `*_file` directive without declaring `mode:` on the agent template** — the Infisical agent writes `0600 root` and has no permission option, so `prom/*` images (which run as `nobody`) get `permission denied`. Declare `mode: '0644'` in `infisical_agent_templates` and re-apply it in the template's `post_command`, since a rotation rewrites the file
- **Never put a literal comment line in an Infisical agent template that renders a *bare value*** — the comment becomes part of the value. Use `{{- /* ... */ -}}` Go-template comments with whitespace trimming (see `openobserve-password.tpl.j2` and `alert-ntfy-url.tpl.j2`)
- **Never enable netconsole without also raising `console_loglevel`** — netconsole is a *console* driver, so it only transmits what passes console-level filtering, and the PVE default `kernel.printk` console level 1–3 drops the KERN_ERR (3) NVMe/`EXT4-fs error` messages. Set **`kernel.printk = 5 4 1 7`** via an `/etc/sysctl.d/` drop-in alongside the module. Verify with `<3>`/`<4>`/`<5>`-prefixed `/dev/kmsg` writes: the first two must arrive, the third must not
- **Never assume an RFC 3164 sender's clock agrees with the collector's timezone** — RFC 3164 timestamps carry no zone, so syslog-ng interprets them as *receiver-local* and a UTC device lands every message in the future, where `end_time=now` queries silently exclude it. Fix at the source (`/etc/TZ` + `TZ=` on the syslogd process), and widen the query window into the **future** before blaming the network.
- **Never point a device's ordinary syslog at the netconsole port (5515)** — 5515 is deliberately parser-free and dumps straight into the `netconsole` stream, while on 5514 `syslog-parser()` parses unframed printk as RFC 3164 and eats the first token. Ordinary syslog belongs on 5514; keep UniFi's two destinations (`unifi_setting.syslog.netconsole_*` vs `.ip`/`.port`) separate.
- **Never expect netconsole to carry a hostname, and never reach for `userdata` to add one** — netconsole's wire format has no hostname field, so the `netconsole` stream's `host` is the *source IP*, and with `extended=0` (the default) configfs `userdata` is silently dropped. Names belong at the collector: `use-dns(yes)` on the `s_netconsole` source once PTR zones exist
- **Never leave syslog-ng's default `max-connections(10)` on a fleet-wide syslog source** — each Docker daemon holds one TCP connection per logging container, so the fleet blows past 10 and every new sender is rejected with ingestion silently stalling
- **Never conclude a stalled `make update` is fixed because a hand-run `apt-get upgrade` succeeded** — `update-all.yml` uses `upgrade: dist`, and plain `upgrade` holds back exactly the packages that cause the stall. apt has no minimum-rate abort, so a crawling transfer is indistinguishable from a hang: the growing partial in `/var/cache/apt/archives/partial/` (size vs. mtime) gives the actual rate
- **Never probe the UniFi controller with credentials from a monitor** — its `/status` gate passes on port 11443, so authenticating risks locking the admin account. TCP port check only, and do not run the `monitoring_users` role
- **Never use `iif`/`oif` in nftables rules for interfaces created after boot (wg0)** — they resolve interface indexes at ruleset load, so the whole ruleset fails to load when the interface doesn't exist yet, leaving the box unfiltered. Use `iifname`/`oifname`
- **Never synchronously restart WireGuard over the tunnel it carries** — the service task dies between `down` and `up` when its own SSH session severs, and the box is unreachable (VPS sshd binds tunnel IPs only). The `vps_wireguard` restart handler is `async: 60 / poll: 0` fire-and-forget; keep it that way.
- **Never trust computed tunnel MTU arithmetic — measure with DF-set probes** — an IPv6 tunnel endpoint costs 80 bytes of encapsulation, not IPv4's 60, and the IPv6 relay path drops WG UDP outers ≥ 1458 even though raw ICMPv6 passes at 1462. The procedure is in docs/pfsense-wireguard-vps-peer.md.
- **Never debug a dead VPS tunnel past the pf state table** — after a VPS rebuild pfSense can keep sending handshake initiations into a stale inbound `if-bound`/`reply-to` UDP state for `:51821`, which its own keepalives refresh forever while nothing is logged. `pfctl -k <vps_ip>` brings the tunnel up in seconds.
- **Never peer WireGuard against the VPS instance IPv6, and never set narrow AllowedIPs** — the SLAAC address dies on every rebuild (new MAC), and AllowedIPs narrower than the internal supernets makes cryptokey routing silently drop LAN-sourced SSH/pings while breaking VPS-originated telegraf/rsyslog (ADR 0013)
- **Never `source` an Infisical agent env file in a shell script** — values are rendered unquoted for docker's `env_file:` parser (which does no shell expansion), so any `$` in any secret aborts the whole script under `set -u`. `grep` the specific key instead, and verify periodic backups by SNAPSHOT RECENCY on the datastore, never by the job exiting 0
- **Never assume a VLAN has a router at `.1`, and never let a gateway-less VLAN own a guest's default route** — the storage VLAN has no router, so a default route there means no internet → cloud-init's `packages:` install dies → `qemu-guest-agent` never starts → bpg blocks indefinitely at "Still creating…". VLANs declare `gateway:` in `vlans.yaml`, and **that `gateway: null` lives in a gitignored file** — regenerating `vlans.yaml` without it re-arms the trap
- **Never read a role default through `hostvars[other_host]`** — role defaults/vars are per-host template context, not hostvars, so the lookup hard-fails (`HostVarsVars has no attribute`). Anything an orchestrating `run_once` task needs from *other* hosts must be `set_fact`'d first (see `proxmox_host/tasks/cluster.yml` "Publish per-node addresses as facts")
- **Never pass the master's ring0 IP as `proxmox_cluster` `master_ip`** — the module's re-run idempotency key is compared to `/cluster/status` node `ip` fields, which PVE derives from `/etc/hosts` = the **mgmt** IP, so ring0 makes every second `make proxmox-hosts` fail "Node is already part of a cluster". Rings go in `link0`/`link1`
- **Never tag ring1 on a NIC that sits on an access port** — the `corosync_ring1` profile is access (native 32) and UniFi drops tagged frames matching the native VLAN, so `nic0.32` carries an address and no traffic. Dedicated ring1 NIC = untagged address on the NIC; only a bond-carried ring1 (`ring1_nic: vmbr0`) is a VLAN 32 sub-if
- **Never shell `pvecm qdevice setup` without pre-trusting the qnetd host key and pre-authorizing the node keys** — it runs `ssh-copy-id` interactively, so under Ansible (no tty) an unknown host key hangs the task forever, not fails. `qdevice.yml` does both on the qnetd host via `delegate_to`
- **Never assume a VM-shaped network task works in an LXC** — `dns_config`'s drop-in targets `10-netplan-<iface>`, which netplan emits **only on VMs**, and `netplan apply` *hard-fails* in a container, so it is guarded with `when: ansible_virtualization_type != 'lxc'`. A container's `/etc/resolv.conf` is a static file PVE writes from `dns { servers = var.dns_servers }`, so **skipping is not solving**
- **Never let a role write DNS config and defer the apply to a handler** — handlers run at end-of-play while every task in between depends on DNS, so one bad resolver latches: the next run dies at the first network-touching task and never reaches the handler. Apply in-role, gated on a `/run` pending-marker rather than on this run's file changes; recovery needs a hand-run `netplan apply`
- **Never assume `community.docker` modules work on an LXC just because they work on the VM fleet** — the Ubuntu cloud image ships `python3-requests`; the 26.04 LXC template does not, so `docker_container_info`/`docker_compose_v2` fail with "Failed to import the required Python library (requests)" on a fresh CT. Install `python3-docker` in the role (plex_services does)
- **A Proxmox apt repo on a guest is `ansible/tasks/proxmox_apt_repo.yml`** — `get_url` + size guard into `/etc/apt/keyrings/proxmox-release-<suite>.gpg`, deb822, cache refreshed in the same role; the per-guest suite derivation stays in each role's defaults. The nodes keep the installer's `proxmox-archive-keyring`; never delete a package-owned key under `/etc/apt/trusted.gpg.d`
- **Never switch a role from `apt_repository` to `deb822_repository` without `install_python_debian: true`** — deb822 needs `python3-debian`, which the *cloud images* ship and the *LXC templates* do not. The role then fails on containers with "python3-debian is not installed"
- **Never assume `get_url` is offline in steady state — it is not without `checksum:`** — `get_url.py` takes its "file already exists" early exit only with a checksum, so an unguarded fetch makes the remote host a hard per-run dependency. Keep a `stat` guard (`when: not <key>.stat.exists or <key>.stat.size == 0`) for vendor keys, and for `gpg --dearmor -o` remove `creates:`, which skips whenever the path exists — zero-byte included
- **Never use `meta: flush_handlers` to sequence one role's apply** — it flushes EVERY pending handler, including other roles', so flushing in `dns_config` fires `restart infisical-agent` before the service role has written its compose file, and the agent's `post_command` restarts hit a nonexistent path. Apply in-role with a direct command gated on a registered change
- **Never pass `deb822_repository` a URL for `signed_by`** — given a URL it re-fetches on EVERY run and raises an unhandled `RuntimeError` when the fetch fails, so one upstream blip aborts the role on every host. Fetch the key with `get_url` to a path and pass the path, never `shell: wget -O <dest>`, which leaves a **zero-byte keyring** on failure that any `stat.exists` guard treats as present forever
- **Never let a role change an apt source without refreshing the cache in the same role** — `update_cache` riding an install task that is gated on the package being absent means the swap is never validated on hosts that already have it. The role exits green and the malformed source surfaces later at an unrelated apt call on a different play, which is the hardest class of failure to attribute
- **Never use `ansible.builtin.apt_repository` against a Debian 13 guest** — trixie removed `apt-key` and the genericcloud image ships no `gpg`, so the module aborts at startup *before* it reads the repo line. Use `ansible.builtin.deb822_repository` (don't install gpg just to keep a deprecated path alive)
- **Never model an OS-dependent value as a global scalar when guests roll one at a time** — `make rebuild <guest>` means the fleet is MIXED for the whole image roll, so a single fleet-wide `pbs_client_repo_suite` is wrong in both directions at once: `bookworm` breaks the first resolute guest, `trixie` breaks every host still on noble. Derive it from the guest's own `ansible_distribution` facts
- **Never turn `pbs_repo_suite` / `pbs_client_repo_suite` back into a fixed value** — the suite tracks the GUEST OS, not the PBS version: the bookworm client needs `libfuse3-3`, the trixie client `libfuse3-4`; noble has only the former, 26.04 (resolute) only the latter. They DERIVE from each guest's own `ansible_distribution` facts, and `pbs_client` runs on **every** fleet guest, so a fixed value breaks in-guest backups fleet-wide
- **Never define an SDN VNET for a VLAN the host itself uses on the same bridge** — a VLAN zone on `vmbr0` renders each VNET as `bridge_ports vmbr0.<tag>`, so VNETs for VLAN 30 (mgmt) and 20 (Ceph public/NAS) **enslave the host's own `vmbr0.30`/`vmbr0.20` and strip their addresses** on `ifreload`. `vlans.yaml` carries `sdn_zone: null` for storage/infrastructure and the module never renders a VNET without a zone. Before any SDN apply on a new bridge layout, diff the rendered `/etc/network/interfaces.d/sdn` ports against `ip -br addr` on a node
- **Never hand `pveceph osd create` a partition whose GPT type is still ZFS (`BF01`)** — PVE's Diskmanage flags any ZFS-typed partition as "in use" from the type GUID alone, so a wiped, zapped, pool-destroyed `-part4` still fails with `device is already in use`. `sgdisk -t 4:8300 <disk>` + `partprobe` first (metadata only); the role's wipefs guard cannot catch it
- **Never `terraform destroy -target` a per-instance resource that other guests share a resource block with** — `-target` on destroy takes the target AND every dependent, and dependencies are tracked per *resource*, not per *instance*. Retire a scratch guest with `terraform state rm` + `qm destroy` by hand, or `make rebuild`/`make clean`, and always read the `will be destroyed` list before `-auto-approve` on any destroy
- **Never hand a freshly formatted data volume to a CT with `lost+found` still on it** — mkfs.ext4 creates it host-root owned, which is unmapped (nobody) inside an unprivileged CT, so any package postinst that `chown -R`s the mount (Plex does) fails, and the half-configured package then needs a purge because its postinst depends on a preinst-written `/tmp` log. `playbooks/data-volumes.yml` removes it after the chown; do not re-add it
- **Never start a VIP's keepalived while the guest it replaces still holds the address** — keepalived does no conflict detection. Name the packages (globs are fine: `mesa-* lib*mesa* libgbm*`) and verify with `apt-cache policy <pkg>` showing the pinned version at `1001`, never by reading the preferences file
- **Never rely on an Infisical agent `post_command` to pick up a change the play made.** A template change restarts the agent, and the agent's first render after its own start never runs the exec hook; `post_command` only covers in-place rotations. Watch the rendered files with a systemd `.path` unit (`PathChanged=`, as the `mcp` role's `homelab-gateway-reload.path` does) that restarts the service.
- **Never name a tracked file `secrets.yml`.** `.gitignore` excludes that name anywhere in the tree, so `git add` silently skips it; local `make validate` passes because the file is on disk, and CI fails with `Could not find specified file in role: tasks/secrets`. Check new files with `git ls-files` before pushing.
- **Never install a locked Python app with `uv tool install`.** It resolves fresh and ignores the project's `uv.lock`, and a crash-looping `Restart=on-failure` unit in `activating` still satisfies `state: started`, so the play reports 0 changed. Clone at the tag and `uv sync --frozen`.
- **Never generate an OpenObserve password with `openssl rand -hex`, and never ask OSS OpenObserve for a non-`admin` role.** Its user API rejects a password without upper case, lower case, a digit and a special character, and it answers any other role with `Custom roles not allowed` (both 400, both censored by `no_log`). The `mcp` role generates `Mcp-0<hex>`.
- **Never leave a hostless line in `~/.ssh/known_hosts` on the workstation.** A bare `ssh-ed25519 AAAA…` with no host field is ignored by OpenSSH but kills bpg's SSH client (`knownhosts: missing key type pattern`), so every file resource and every `make build` fails before creating anything. `awk 'NF>=3 || /^#/ || NF==0'` over a backup strips them.
- **Never install a DNS-only cert as UniFi OS Server's `unifi-core.crt`** — the host-side update supervisor reads that file as its trust anchor and dials `wss://127.0.0.1:11084`, so without `IP:127.0.0.1` every update fails `No connection to UOS Server Manager` while the UI and the container stay healthy. ACME cannot issue an IP SAN; the pair is API-issued (`api_cert_ip`). The tell is `certificate not valid for name "127.0.0.1"` in `/var/lib/uosserver/logs/uosserver-service.log`
- **Never enable the virtio balloon on fleet VMs to fix Proxmox's memory graph** — a balloon device, even at min = max, gets `free-page-reporting=on` unconditionally, so the node's free RAM overstates real headroom and placing guests against it overcommits the nodes that hold the OSDs and Talos. Every VM runs `balloon: 0` deliberately; guest usage comes from telegraf/Grafana, host headroom from node `MemAvailable`
- **Never size VM 240 from process RSS, and never let an embedder load with a bigger micro-batch than its inputs need** — the xe driver places GPU buffers that miss VRAM in GTT, guest RAM visible only as `drm-total-gtt` in `/proc/<pid>/fdinfo/*`, and beside vLLM at 0.90 a bigger micro-batch's flash-attention scratch cannot be reserved and llama-server aborts. `-ub 2048` and `--cache-ram 0` are the rule and `vllm.service` gates on `systemctl is-active llama-embed`
- **Never move containerd's content store and restart only docker** — the store is containerd's, and `data-root` in `daemon.json` does not cover it, so relocating it takes a `/var/lib/containerd` symlink *and* a containerd restart (`containerd` then `docker`). Restart docker alone and every pull dies `failed to lease content: ... blob not found`.
- **Never treat vLLM's `/health` as proof the engine is working** — it is the API server's liveness, not the engine core's: a wedged engine keeps answering 200 while no request completes, and the hung request is never logged. `vllm-liveness.timer` is the real check, restarting the engine after **two** consecutive failures; do not run `make ansible llm` against 240 while an index build is in flight
- **Never gate a post-restart probe of VM 240's engines on `/health`** — `vllm.service` answers `/health` while `ExecStartPost=vllm-warmup` is still compiling batch shapes (`activating (start-post)` for ~90 s), so a probe that starts on `/health` reads the warmup as a hang. Wait for `systemctl is-active vllm` to return `active`; the same trap applies to `llama-embed`'s `ExecStartPost` warm-up
- **Never assume an Infisical agent is still polling because its service is `active` and its logs look normal** — an agent can silently stop rendering while its service stays `active` with no journal error, and it logs a render only when content changes, so no log line proves render liveness. If the rendered file's fingerprint has not changed within ~2 poll intervals, hash `/etc/infisical/secrets/*`, `systemctl restart infisical-agent`, re-hash
- **Never raise VM 240's vLLM budget to `--gpu-memory-utilization 0.88 --max-num-seqs 64`, and never start a second XPU process while one is initialising** — the first OOM-kills `VLLM::EngineCore` during init through host memory pinned by GPU-mapped buffers, which `xpu-smi` folds into its *device* figure, and a second XPU process fails an engine init through the shared triton/NEO compile cache. The served budget is `0.90 / 8 / 4096`, and `vllm.service` gates on `llama-embed`'s `/health`
- **Never let a WAN outage reach AdGuard's worker pool** — AdGuard Home has one `max_goroutines` semaphore for every query, internal zones included, and dnsproxy holds a failing public upstream for `upstream_timeout` twice over, so dead public lookups starve BIND-bound names. The `adguard` role holds `adguard_upstream_timeout_s: 3` and `adguard_max_goroutines: 3000`; do not put BIND in front of AdGuard
- **Never expect a non-HA guest with a `cephfs:snippets/` cloud-init file to survive a node reboot without the `pve-guests` wait** — `startall` runs ~8 s after boot, before pvestatd has mounted cephfs (`mount error: no mds is up`), so the `qmstart` fails and is never retried. `make proxmox-hosts TAGS=autostart` drops a non-fatal `ExecStartPre=` on `pve-guests.service` that waits up to 300 s for the mountpoint
- **Never let Plex's `LanNetworksBandwidth` cover the VPS tunnel subnet** — the relay masquerades every remote viewer behind the tunnel address, so a LAN range covering it makes every relayed client *local* and `WanPerStreamMaxUploadRate` never applies. The `plex` role converges `plex_prefs` with `plex_lan_networks` = the fleet VLAN /24s; raise `WanPerStreamMaxUploadRate` by adding it to `plex_prefs`, not in the UI
- **Never put `update_cache: true` only on a `check_mode: true` apt task** — the module skips `cache.update()` under check mode (`apt.py`, `if not module.check_mode`), so the dry run plans against whatever apt-daily last fetched and a real upgrade task without `update_cache` installs that. Refresh the lists in a separate non-check task first
- **Never join a node while its Ceph repo differs from what the cluster runs** — `pveceph install` takes the newest point release in the node's repo, and a mon on a newer point release than the quorum never finishes its store sync while the quorum mon serving it grows to tens of GB and is OOM-killed. Stop and mask the new mon first; upgrade the cluster (mons → mgrs → OSDs → MDS) before any new node's mon is created
- **Never let HA place guests on a new node before the SDN zone includes it** — the `Homelab` zone carries an explicit `nodes` list from `proxmox_nodes`, so a new node has no VNET bridges, and without `TAGS=mounts` it lacks the NAS host mounts. Put the new node in HA maintenance at join, add it to `proxmox_nodes`, `make sdn-apply`, check its VNETs, `make proxmox-hosts TAGS=mounts LIMIT=<node>`, then release maintenance
- **Never move `virtual_environment_node` or migrate a guest between nodes without re-reading the fleet plan** — the default node is also the node of every download file and cephfs snippet, so changing it replaces the LXC template, which forces **every container** to be replaced. A migrated VM needs an explicit `node_name` or it plans a replace; a migrated **container** plans as "will be created", and `terraform import` does not fix it
- **Never write an absence alert as `sum(increase(<series>)) == 0`** — over a missing series it returns nothing and never fires. Use `absent()`, and confirm the series exists on the live Prometheus before trusting the rule
- **Never tighten the VLAN 30 firewall without keeping services→nodes TCP 9100 and services→pdm/pxe/worklab telegraf and node_exporter ports open, or move those scrapes** — worklab, pdm and pxe have only a VLAN 30 address (worklab 9100, pdm/pxe telegraf 9273), so a named-guest-rules-only VLAN 30 silently blinds the disk and temperature alerts for them
- **Never write a cron hour or a CronJob `schedule` assuming it is local time without checking the zone** — the LXC templates ship UTC and bpg's container resource has no timezone, while the VMs (cloud-init) run America/Chicago. `make ansible-infra TAGS=timezone` sets `{{ timezone }}` on every guest and restarts cron; Kubernetes CronJobs use the controller's UTC unless they carry `timeZone: "${TZ}"`
- **Never use `echo -n`** in secret generation commands — use `printf '%s'`
- **Never use `is succeeded` alone** to gate on a registered variable — add `is not skipped`
- **Never use `git add -i` or `git rebase -i`** — interactive mode not supported
- **Never commit `vlans.yaml`, `private_bindings.yaml`, or `infisical-backup.yml`** — these are gitignored
- **Never add migration/upgrade logic** — roles must work on fresh VMs
- **Never skip pre-commit hooks** with `--no-verify`
- **Never reference `bootstrap.*` secrets in templates** outside the bootstrap/infisical roles
- **Never use `define`/`$(eval export)` in the Makefile for secret propagation, and never a top-level `export X :=` for a secret** — target-specific `export X = $(call _secret,…)` on `TF_TARGETS`
- **Never bake secrets into docker-compose templates** via `{{ secrets.xxx }}` — use Infisical agent `env_file` exclusively
- **Never write to Infisical root `/`** — all secrets live in named subfolders. Root must remain empty.
- **Never reference `secrets.sops.yml` in operational context** — it is a DR artifact only, produced by `make infisical-backup`
- **Never write copies of secrets to consumer folders** — consumers read from the source folder via multi-folder agent templates. Secrets belong to the VM/role that generates them.
