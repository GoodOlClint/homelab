# Proxmox, Ceph and Terraform guests

Loaded when a matching path is read or edited. The repo-wide rules are in `CLAUDE.md`; the incident behind each rule is in [docs/LESSONS.md](docs/LESSONS.md) under the same heading.

## Canonical pipelines

**P6 — the deliberate VM roll landed 2026-08-25 ([plan](docs/p6-vm-roll-plan.md); no new ADR — consequence notes on ADRs 0016/0021/0039/0040):** the VM snippet (`terraform/modules/proxmox-vm/templates/user-data.yaml.tmpl`) sets `fqdn` = `<name>.<service domain>` and writes the ADR 0021 `Proxy-Auto-Detect` probe, byte-identical to the `apt_proxy` role's copy. Infisical rolls by **restoring the PBS dump** (`make rebuild-infisical` → `make infisical-restore`), never by re-bootstrapping; unifi is restored through the setup wizard from an operator-downloaded `.unifi` backup; pdm's remotes + authentik realm are re-added by hand. Cloudflare AAAA records are canonicalized with `cidrhost(<v6>/128, 0)`. A bare `terraform plan` outside `make` hangs on a variable prompt while holding the state lock.

**Disk encryption — PROPOSED, blocked on the msi RMA ([ADR 0047](docs/decisions/0047-fleet-disks-are-encrypted-with-luks-chained-to-the-tpm-and-ceph-osd-encryption-lands-first.md)):** nothing is encrypted at rest today. The blocker is not Secure Boot but `proxmox-auto-install`'s `[disk-setup]`, which has **no encryption option at all**. Decided: **LUKS, not ZFS native**, **Ceph OSD encryption first** (`pveceph osd create --encrypted`, one OSD at a time), TPM enrolment **after** the SB conversion, a recovery passphrase **always** enrolled. **OSD-only encryption protects drive disposal, not node theft**, and **TPM auto-unlock does not stop a thief who simply boots the machine** — TPM-only vs TPM+PIN vs Clevis/Tang is open. A GRUB password is required (PCR7-only unlocks for `init=/bin/bash`). **Nothing starts while the cluster is `HEALTH_WARN` with msi out.**

**Scratch guests ([ADR 0054](docs/decisions/0054-scratch-guests-live-in-the-fleet-root-as-their-own-list-and-get-their-secrets-pushed-at-deploy-time-never-a-vault-credential.md), 2026-09-14):** requested via the *Scratch device request* issue form, they live in `local.scratch_vms` (services VLAN, offsets 80–99, VMID = 200 + offset, no HA/backup/data volume) with the `scratch` role. **No Infisical agent on a scratch guest** (every `infisical_client` identity is project-wide): the role writes `/scratch/<name>` to `/etc/scratch-secrets/<key>` 0400; rotation is a re-run. Retire with `terraform state rm` + `pct destroy`.

**Bare-metal node installs** boot over **PXE/iPXE from the `pxe` guest** with per-node answer files keyed by install-NIC MAC; Secure Boot stays off on PVE nodes; AMT/JetKVM are power/console only; `make node-iso` is the network-down fallback (ADR 0026).

**PBS version** PBS is VM 201 on a pinned **Debian 13 generic cloud image** — the role reuses the LUN's datastore via `--reuse-datastore`, and `make backup-finalize` re-points the cluster entry after every PBS rebuild. A PBS major move is a **guest rebuild, not an `apt dist-upgrade`**. Do not propose the PBS installer ISO, and do not propose a second PBS for host-failure redundancy (no HA in 4.x; the gap is a second *copy* of the data).

Landing dates, measurements and "found en route" notes for each pipeline: [docs/LESSONS.md](docs/LESSONS.md), same headings.

## What Never To Do

- **Never leave a node armed for PXE install, and never assume PXE is wipe-safe without the arm gate** — the answer server serves an install answer (→ unattended disk wipe) while `answers/armed/<node>` is present and unexpired (`make node-arm`). Arm right before an install and let it auto-expire; if you arm and don't install, `make node-disarm`.
- **Never flip `tf-node-install`'s native VLAN — worklab's untagged mgmt (`.30.75` on `vmbr0`/`nic0`, Pro-Max p46) rides that shared profile** — AMT on the vlan10 OOB plane is the separate `tf-node-oob` profile bound per port (`unifi-ports.yaml`). Per node, re-IP AMT over the old path first (it goes dark), then `unifi-apply` the port, and verify from a vlan10 host (control 212) — the operator Mac cannot reach vlan10 by policy.
- **Never enable Secure Boot on a node whose ESP is still systemd-boot — convert it to shim+grub first.** `proxmox-boot-tool` gives an SB-off install unsigned **systemd-boot**, and enabling SB in BIOS then makes the firmware reject the loader. Booted SB-off, run `proxmox-boot-tool init /dev/<esp> grub` on each ESP, verify `efibootmgr -v` shows `\EFI\proxmox\shimx64.efi`, then enable SB in BIOS.
- **Never reconfigure host networking over the interface carrying the PVE API session** — `terraform/hosts/` applies run over the stable VLAN 30 mgmt link and never touch it; a re-apply must never drop the link Terraform is talking over (ADR-0002)
- **Never DHCP an LXC** — static IPs only, so plan-time inventory is deterministic (ADR-0003)
- **Never set `vlan_id` on SDN VNETs** — only for physical bridges (`vmbr*`)
- **Never write a source-based `routing-policy` rule with the interface prefix** — it must be `/32`: a `from: <ip>/24` rule matches every host in the subnet, so any *forwarded* packet from a neighbour on that VLAN is looked up in the per-VLAN table, which has no bridge route, and is sent back out the gateway. Symptom: containers reach the internet fine but hang on every connection to a host on that interface's own subnet
- **Never assume a VLAN has a router at `.1`, and never let a gateway-less VLAN own a guest's default route** — the storage VLAN has no router, so a default route there means no internet → cloud-init's `packages:` install dies → `qemu-guest-agent` never starts → bpg blocks indefinitely at "Still creating…". VLANs declare `gateway:` in `vlans.yaml`, and **that `gateway: null` lives in a gitignored file** — regenerating `vlans.yaml` without it re-arms the trap
- **Never pass the master's ring0 IP as `proxmox_cluster` `master_ip`** — the module's re-run idempotency key is compared to `/cluster/status` node `ip` fields, which PVE derives from `/etc/hosts` = the **mgmt** IP, so ring0 makes every second `make proxmox-hosts` fail "Node is already part of a cluster". Rings go in `link0`/`link1`
- **Never tag ring1 on a NIC that sits on an access port** — the `corosync_ring1` profile is access (native 32) and UniFi drops tagged frames matching the native VLAN, so `nic0.32` carries an address and no traffic. Dedicated ring1 NIC = untagged address on the NIC; only a bond-carried ring1 (`ring1_nic: vmbr0`) is a VLAN 32 sub-if
- **Never shell `pvecm qdevice setup` without pre-trusting the qnetd host key and pre-authorizing the node keys** — it runs `ssh-copy-id` interactively, so under Ansible (no tty) an unknown host key hangs the task forever, not fails. `qdevice.yml` does both on the qnetd host via `delegate_to`
- **Never define an SDN VNET for a VLAN the host itself uses on the same bridge** — a VLAN zone on `vmbr0` renders each VNET as `bridge_ports vmbr0.<tag>`, so VNETs for VLAN 30 (mgmt) and 20 (Ceph public/NAS) **enslave the host's own `vmbr0.30`/`vmbr0.20` and strip their addresses** on `ifreload`. `vlans.yaml` carries `sdn_zone: null` for storage/infrastructure and the module never renders a VNET without a zone. Before any SDN apply on a new bridge layout, diff the rendered `/etc/network/interfaces.d/sdn` ports against `ip -br addr` on a node
- **Never hand `pveceph osd create` a partition whose GPT type is still ZFS (`BF01`)** — PVE's Diskmanage flags any ZFS-typed partition as "in use" from the type GUID alone, so a wiped, zapped, pool-destroyed `-part4` still fails with `device is already in use`. `sgdisk -t 4:8300 <disk>` + `partprobe` first (metadata only); the role's wipefs guard cannot catch it
- **Never `terraform destroy -target` a per-instance resource that other guests share a resource block with** — `-target` on destroy takes the target AND every dependent, and dependencies are tracked per *resource*, not per *instance*. Retire a scratch guest with `terraform state rm` + `qm destroy` by hand, or `make rebuild`/`make clean`, and always read the `will be destroyed` list before `-auto-approve` on any destroy
- **Never hand a freshly formatted data volume to a CT with `lost+found` still on it** — mkfs.ext4 creates it host-root owned, which is unmapped (nobody) inside an unprivileged CT, so any package postinst that `chown -R`s the mount (Plex does) fails, and the half-configured package then needs a purge because its postinst depends on a preinst-written `/tmp` log. `playbooks/data-volumes.yml` removes it after the chown; do not re-add it
- **Never trust `mount | grep cephfs` as proof cephfs is usable on a node** — a blocklisted kernel client (`dmesg`: `mds0 session blocklisted`) keeps the mount entry and returns `Permission denied` on every access, so every `vzcreate` on that node fails. `umount -f /mnt/pve/cephfs` and let pvestatd remount, and check `pvesm status` on EVERY node after any host-network incident
- **Never rsync out of a Docker *named-volume* mountpoint (`/var/lib/docker/volumes/<v>/_data`) after `docker compose down`** — for NFS-backed volumes docker unmounts the export when the last container goes, so the path is an EMPTY directory and `rsync --delete` from it wipes the destination. Source the delta from the export itself (the node's `/mnt/nas/...` bind) or from the still-running container
- **Never expect an unprivileged CT's root to `chown` on an NFS bind mount** — CT root is host uid 100000, an ordinary uid to the NFS server, so any image entrypoint that "fixes volume ownership" as root before dropping privileges dies with `Permission denied`. `chown -R 100000+<uid>` the tree from the node once, and run the container as that uid (`user: "999:999"`) so the root branch is skipped
- **Never remove or reorder an LXC `mount_point` expecting an in-place update** — bpg recreates the container (plan shows `1 to add, 1 to destroy` inside one `make build`), so the rootfs and anything loaded only there (a `docker load`ed local image) is gone; the holder data volume survives because it is attach-only. Read the plan line before `make build` on a CT whose binds changed
- **Never let a Proxmox appliance package pull its `*-meta` Recommends onto a cloud-image guest** — `proxmox-datacenter-manager` *Recommends* `proxmox-datacenter-manager-meta`, which drags in `grub-pc`, whose postinst has no install device on a cloud image, so dpkg fails mid-transaction. Install the real packages with `install_recommends: false`, and delete the `*-enterprise.sources` file the package drops (401, kills every later `apt update`)
- **Never assume a PVE backup job survives `make rebuild` of its only member** — PVE deletes a job when its last VMID is destroyed, and bpg then fails every refresh with `Unable to Read Backup Job`, which breaks `make inventory`. Recovery: `terraform state rm 'proxmox_backup_job.jobs["<job>"]'`, `make inventory`, `make ansible proxmox-backup` and `make backup-finalize` if PBS itself was rebuilt, then `make backup-jobs`
- **Never leave a stopped/retired guest in `vm-configs.tf` when running a multi-host play** — an unreachable host makes its play end with "NO MORE HOSTS LEFT", and Ansible then aborts the *entire* playbook, silently skipping every later play. Retired guests come out of `vm-configs.tf` the day they stop; `make inventory` then drops them
- **Never leave UniFi auto-firmware-updates enabled on the fabric switches while HA watchdogs are armed** — an update reboot of the Pro-Aggregation (fabric root) stalls every VLAN past corosync's token timeout during STP reconvergence and the watchdog-armed nodes fence. Fabric firmware rolls are deliberate maintenance: park HA or expect a fleet-wide fence. The talos hookscript snippet lives on each node's `local` datastore (tell: `hookscript error: … does not exist`); a missing one is `terraform apply -replace='proxmox_virtual_environment_file.talos_oom_hook["<node>"]'`
- **Never run a semi-passive/ECO PSU mode on a fleet host in the closet** — in semi-passive fan mode the supply runs fanless and hot at the box's 400–500 W and its protections trip on load steps: the host hard-resets with no MCE and the kernel silent. Check that switch before any hardware bisection
- **Never edit `user-data.yaml.tmpl` (or anything the VM module feeds it) outside a deliberate VM roll** — a changed snippet shows every VM (infisical, PBS, unifi, pdm, pxe, apt-cache) as `must be replaced` (ADR 0016); the six roll one at a time in the P6 order (apt-cache → pxe → pdm → unifi → proxmox-backup → infisical) with the [P6 plan](docs/p6-vm-roll-plan.md) as the runbook
- **Never write into `/etc/pve` with a plain `copy`, and never give the file a `mode`** — pmxcfs refuses the temp-file rename Ansible uses (`Operation not permitted` on `.ansible_tmp…`) and refuses chmod, and nothing PVE runs as `nobody` can read `/etc/pve/priv`. Use `unsafe_writes: true` and no `mode:`; the ACME DNS plugins need their key at `/etc/proxmox-acme/tsig.key` root:nogroup 0640
- **Never assume a `proxmox-backup-manager` subcommand exists because a task for it runs green** — there is no `gc-job` in PBS 4 (GC is a datastore property: `datastore update --gc-schedule`). Grep `proxmox-backup-manager help` before trusting a job task, and never `failed_when: false` a create — `'already exists' not in stderr` is the idempotency guard
- **Never let `proxmox-backup-client` prompt from a play** — with an untrusted cert and no pin it reads the TTY, gets `SIGTTIN`, and *stops* (state `T`) taking `timeout` with it: redirect stdin (`</dev/null`) and use `timeout -s KILL`. `pbs_client`'s verify does both
- **Never leave PVE HA resources registered while a cluster node is out of service** — quorum is a majority of *configured* nodes, and a node whose LRM is active with HA services and has lost quorum cannot renew its watchdog, so it **hard-resets itself after ~60 s**. Either park HA (`ha-manager remove <sid>`, guests keep running) or restore a real majority first (`pvecm delnode <node>` + a QDevice)
- **Never expect a node `reboot` to fail HA services over under the default `shutdown_policy`** — `conditional` (the default, and what a `datacenter.cfg` with no `ha:` line means) *freezes* HA services on a reboot: they sit on the node and restart there when it returns. `ha: shutdown_policy=migrate` live-migrates VMs off before the node goes down; CTs cannot live-migrate and get a restart-migration instead
- **Never reboot a PVE node without draining its Talos guest first** — the control-plane VMs carry no HA resource and every cluster workload is a single replica on an RWO ceph-rbd PVC, so a node loss costs the 300 s unreachable toleration plus the RBD detach (~6 min). `kubectl drain talos-cp-<n> --ignore-daemonsets --delete-emptydir-data` moves the pods in seconds; `kubectl uncordon` after
- **Never enable the virtio balloon on fleet VMs to fix Proxmox's memory graph** — a balloon device, even at min = max, gets `free-page-reporting=on` unconditionally, so the node's free RAM overstates real headroom and placing guests against it overcommits the nodes that hold the OSDs and Talos. Every VM runs `balloon: 0` deliberately; guest usage comes from telegraf/Grafana, host headroom from node `MemAvailable`
- **Never expect a non-HA guest with a `cephfs:snippets/` cloud-init file to survive a node reboot without the `pve-guests` wait** — `startall` runs ~8 s after boot, before pvestatd has mounted cephfs (`mount error: no mds is up`), so the `qmstart` fails and is never retried. `make proxmox-hosts TAGS=autostart` drops a non-fatal `ExecStartPre=` on `pve-guests.service` that waits up to 300 s for the mountpoint
- **Never join a node while its Ceph repo differs from what the cluster runs** — `pveceph install` takes the newest point release in the node's repo, and a mon on a newer point release than the quorum never finishes its store sync while the quorum mon serving it grows to tens of GB and is OOM-killed. Stop and mask the new mon first; upgrade the cluster (mons → mgrs → OSDs → MDS) before any new node's mon is created
- **Never let HA place guests on a new node before the SDN zone includes it** — the `Homelab` zone carries an explicit `nodes` list from `proxmox_nodes`, so a new node has no VNET bridges, and without `TAGS=mounts` it lacks the NAS host mounts. Put the new node in HA maintenance at join, add it to `proxmox_nodes`, `make sdn-apply`, check its VNETs, `make proxmox-hosts TAGS=mounts LIMIT=<node>`, then release maintenance
- **Never move `virtual_environment_node` or migrate a guest between nodes without re-reading the fleet plan** — the default node is also the node of every download file and cephfs snippet, so changing it replaces the LXC template, which forces **every container** to be replaced. A migrated VM needs an explicit `node_name` or it plans a replace; a migrated **container** plans as "will be created", and `terraform import` does not fix it
