# Identity and PKI

Loaded when a matching path is read or edited. The repo-wide rules are in `CLAUDE.md`; the incident behind each rule is in [docs/LESSONS.md](docs/LESSONS.md) under the same heading.

## Canonical pipelines

- **PKI (ADR 0039 + 0041):** the root is `Homelab Root CA` in Infisical project `homelab-pki` (`make pki-hosts` exports it to `kubernetes/.secrets/homelab-ca.crt`); the fleet-host issuer is the `fleet-hosts` profile (`scripts/pki_hosts.sh`, idempotent by name — a profile under the wrong CA is recreated, which makes every native client re-register). Per-host certs: native ACME (PBS, PDM); `cert_client` (certbot, `cert_client_issuer: fleet` or `letsencrypt`); `ansible/tasks/api_certificate.yml` for a CN or an IP SAN; acme.sh on the Synology ([docs/synology-acme.md](docs/synology-acme.md)). **Every enrolling host holds its own TSIG key `acme-<host>` (`bind9_acme_hosts`), granted only its own `_acme-challenge` name — no wildcard, no shared key (ADR 0050). A new ACME host = a name in that list + a run of the `dns` play (twice on a new key) before its first enrollment.** No hand-written cert on a fleet host; no `insecure = true` on a cluster provider; no fingerprint pin on a PBS consumer or a PDM remote ([docs/pdm-remotes.md](docs/pdm-remotes.md)). Trust: `make ca-trust`, Talos via `make talos-apply`, workstation python via `kubernetes/.secrets/ca-bundle.pem`, pods via the `homelab-root-ca` ConfigMap. The vault's machine URL is one binding, `bootstrap_config.infisical_url` (ADR 0042).

**P5 — DNS, certs, SSO, Jellyfin (APPROVED 2026-08-24, [ADR 0040](docs/decisions/0040-p5-real-dns-on-a-flat-public-domain-zone-bind-fed-by-nsupdate-external-dns-adguard-forwards-rewrites-retired-let-s-encrypt-dns-01-wildcards-as-traefik-s-default-cert-two-authentik-realms-split-by-audience-jellyfin-over-the-vps-relay-with-ldap-auth.md), [plan](docs/p5-dns-sso-jellyfin-plan.md)):** the internal namespace is a flat zone on an operator-owned public domain (`vlans.yaml` `service_domain`, `media_domain`, `internal_zones`), BIND authoritative with every record a dynamic update, AdGuard forwards. **P5a:** `make dns-records` (`ansible/tasks/dns_records.yml`, also the tail of the `dns` play) pushes guests/nodes, VIPs, MetalLB names and mirrored public records over `community.general.nsupdate` — nothing prunes, retired names come out by hand (`nsupdate`); `kubernetes/external-dns/` owns the Ingress hosts (`txtOwnerId: talos`, `policy: sync`). `vpn` is looked up on the public copy at run time, never a static binding. AdGuard forwards each internal zone to BIND (`adguard_zone_forwards`, converged through `/control/dns_config` because the config template is initial-only); the resolver VIP never depends on BIND. **P5b:** Traefik's default cert is a **Let's Encrypt DNS-01 wildcard** (`kubernetes/traefik/certificate.yaml` `wildcard-tls`; a rehearsal is `issuerRef: letsencrypt-staging` in that file, pushed) with the Cloudflare token from **`/infrastructure/cloudflare_dns_api_token`** — **the `infisical-universal-auth` seed Secret must exist before the `traefik` tree's Certificate can issue on a fresh cluster** (`make k8s-seed` first). cert-manager's DNS-01 self-check is pinned to `1.1.1.1`/`1.0.0.1` because the AdGuard → BIND chain never sees the `_acme-challenge` TXT (scoped ADR 0012 exception). `homelab-ca` stays the issuer for the registry and everything non-browser. Kuma carries **zero `ignore_tls`** rows. No tracked file carries a media-domain literal (`${MEDIA_DOMAIN}`, `module.network.media_domain`). **P5c:** the internal realm is LXC 213 (ADR 0049); the external is tree `authentik-ext` (tail `make k8s-apps`, `auth.<media domain>`, the tunnel route is a dashboard step); each realm has a Postgres 17, a nightly `pg_dumpall` → PBS ns `databases`, and an `InfisicalSecret` on its folder (hex only, so nothing downstream quotes). **All configuration is a blueprint**: the embedded outpost needs `config.authentik_host` set (unset, every 302 targets `http://localhost`) and `grant_types` must be explicit (the blueprint default is `[]` = "Invalid grant_type"). **Forward-auth is gated to the `authentik Admins` group** — a new operator account must be added to that group or every forward-auth surface denies it. An Ingress opts in with `traefik.ingress.kubernetes.io/router.middlewares: traefik-forward-auth@kubernetescrd`; **Uptime Kuma stays outside forward-auth** (the 302 kills the socket.io handshake); machine paths use svc DNS and never see forward-auth. MeshCentral requires the userid in `meshcentral_manage_all_device_groups` **in addition to** full siteadmin; PVE/PBS/PDM realms are hand steps in [docs/authentik-setup.md](docs/authentik-setup.md). **pfSense is SAML2, not OIDC** (ADR 0043): `sign_assertion: true` (a signing keypair with neither sign flag is rejected as invalid), the application bound to a `pfsense-admins` group, package (removed by a pfSense upgrade) and SP settings are operator hand steps. **The firewall's admin auth depends on the services plane**, and a break-glass username must never collide with an authentik username (pfSense silently grants a same-named local account's privileges). The Infisical operator restarts every auto-reload Deployment once at its first resync after a fresh deploy — expected, not a loop. **Passkey login:** `default-authentication-flow-passwordless` is the identification stage's `passwordless_flow`; password + passkey-as-second-factor stays the fallback; pointing the brand's `flow_authentication` at it locks out every account with no passkey — deliberately not done. **P5d:** tree `jellyfin` (tail `make k8s-apps`) at `jellyfin.<media domain>`, media via its **own read-only NFS PV/PVC** (claims cannot cross namespaces), no forward-auth (TV apps); auth is the **LDAP-Auth plugin against `ak-outpost-ldap.authentik-ext.svc:389`** (username attribute `cn` — authentik's `uid` is a hash); the `k8s_apps` role drives setup through the API from inside the pod. External path ends **pfSense WG_VPS pass + port-forward 443 → Traefik LB .65 (hand step, [docs/pfsense-wireguard-vps-peer.md](docs/pfsense-wireguard-vps-peer.md))**; Jellyfin never touches the Cloudflare tunnel. **P5e:** BIND serves only the `internal_zones` forward zones plus the per-VLAN reverse zones; AdGuard's role converges the **whole** upstream list and deletes every rewrite on each run. The AdGuard play cannot run `--limit` to one instance (the pair shares its seeded secrets through `hostvars`); run both. pfSense's DHCP domain/DDNS role is hand-run (password-gated sudo).

**P7 — per-host PKI landed 2026-08-25 ([ADR 0041](docs/decisions/0041-p7-per-host-certs-are-acme-dns-01-against-infisical-through-bind-s-dynamic-update-path-on-a-scoped-tsig-key-pbs-fingerprint-pins-retire-infisical-s-own-cert-is-api-issued-behind-caddy.md), [plan](docs/p7-per-host-pki-plan.md)):** every fleet host serves and trusts `Homelab Root CA` certs. The issuer sits under an **RSA 4096 intermediate `Homelab Hosts CA`** because Infisical only signs a CSR whose key family matches the CA's. Challenge TXTs ride BIND's dynamic-update path; Infisical resolves them at the BIND VIP (`ACME_DNS_RESOLVER_SERVERS`). **PBS + PDM** use their native ACME clients (the nsupdate plugin runs as `nobody`, so the key is `/etc/proxmox-acme/tsig.key` root:nogroup 0640; PDM's domain list lives in `acme/certificate.cfg`, not `node.cfg`). **PVE nodes** use certbot `dns-rfc2136` (`cert_client`, deploy hook `pvenode cert set`) — PVE's own ACME client rejects the CRLF-terminated PEM Infisical serves. **Infisical** and **control** get API-issued certs through `ansible/tasks/api_certificate.yml`. Terraform providers run `insecure = false` (`TF_VAR_insecure=true` exists for a hosts apply against self-signed nodes). Renewal proof: `certbot renew --force-renewal --no-random-sleep-on-renew --cert-name <fqdn>` on a node (**`--dry-run` goes to Let's Encrypt staging, never the private directory**), `proxmox-backup-manager acme cert order --force` on PBS.

**P8 — the vault's machine URL is https landed 2026-08-25 ([ADR 0042](docs/decisions/0042-p8-the-vault-s-machine-url-is-https-on-the-service-domain-python-clients-trust-a-certifi-root-bundle-the-operator-and-probes-mount-the-root-8080-binds-to-localhost-the-vault-s-tls-material-rides-the-pbs-dump.md), [plan](docs/p8-vault-https-plan.md)):** `bootstrap_config.infisical_url` = `https://infisical.<service domain>` and every consumer derives from it. The compose publishes 8080 on `127.0.0.1` whenever the binding is https. The nightly `infisical_pbs_backup.sh` pxar carries `tls/key.pem` + `tls/cert.pem`, so `make rebuild-infisical` logs in over https right after the restore. Escape hatch for a pre-P8 dump restored into a fresh VM (no `tls/`): `sops --set` the binding back to `http://<services ip>:8080`, `make ansible infisical` twice, flip back, once more. The `infisical.vault` reads use `url` + `token_auth` (`login_data` is a no_log argument).

**P9 — the PKI tail landed 2026-08-25 (no new ADR — ADR 0041 consequences):** **worklab** gets its node cert and rsyslog + netconsole targets from the second play in `ansible/playbooks/proxmox-hosts.yml` (`make proxmox-hosts LIMIT=worklab`; SAN `worklab.<service domain>` only). **UniFi OS Server**'s `unifi-core.{crt,key}` is issued through **`api_certificate.yml` with `api_cert_ip: 127.0.0.1`** (not `cert_client`: the update supervisor dials `wss://127.0.0.1:11084`, so a DNS-only ACME leaf breaks every UniFi OS update), installed into the `uosserver_data` volume with `podman exec uosserver nginx -s reload`, and re-installed by a `cmp` whenever UniFi OS regenerates its self-signed pair. Kuma keeps the TCP port check (never auth-probe the controller). **blackbox `tls_connect` verifies** against the mounted root (Plex alone is `insecure_skip_verify`), with `preferred_ip_protocol: ip4`.

Landing dates, measurements and "found en route" notes for each pipeline: [docs/LESSONS.md](docs/LESSONS.md), same headings.

## What Never To Do

- **Never treat a 302-to-self from authentik's flow executor API as a failure** — `POST /api/v3/flows/executor/<slug>/` answers a stage with a redirect to its own URL, which means "accepted, GET the next stage", and stages with nothing to show redirect the same way, several in a row. Loop GETs until JSON; the `query=` parameter is the flow URL's own query string, and anonymous POSTs need no CSRF token
- **Never leave the embedded outpost's `config.authentik_host` unset, and never leave an OAuth2 provider's `grant_types` implicit in a blueprint** — with 2026.x the first makes every forward-auth 302 point at `http://localhost/…`, the second creates the provider with `grant_types: []` and every authorize request fails "Invalid grant_type". Both are silent in `ak apply_blueprint`'s output; `kubernetes/authentik/blueprint-internal.yaml` sets both
- **Never restore an Infisical dump older than the last secret rotation without re-writing what rotated since** — the restore rewinds every folder to the snapshot, so the vault comes back serving rotated-away values (e.g. `/shared` `pbs_backup_token`) and the next consumer pass bakes them. If an older snapshot must be restored, PATCH the rotated keys from `secrets.sops.yml` (`/api/v3/secrets/raw/<key>`) before any consumer resyncs
- **Never point PVE's native ACME client at Infisical** — Infisical ends the certificate download with `\r\n` and `PVE::ACME`'s PEM regex is anchored at `$`, so every order dies at "Server reply does not look like a PEM encoded certificate" after the DNS-01 validation passed. Nodes use certbot + `pvenode cert set` (ADR 0041). Infisical only signs a CSR whose key family matches the CA's (hence the RSA intermediate), and its ACME leaves carry an empty subject (SAN only), which MeshCentral cannot parse
- **Never run `proxmox-backup-manager acme account register` from Ansible without stdin** — it prompts "use external account binding? [y|N]" on stdin regardless of the directory and waits forever under a play. Use `printf 'n\n' |`; the first `acme cert order` also needs `--force`, and the CLI exits 0 on a failed order task — check for `TASK ERROR` in the output. PDM reads its domain list from `acme/certificate.cfg`; `node.cfg` is silently ignored
- **Never verify a renewal by the served fingerprint the instant the deploy hook returns** — `pvenode cert set --restart 1` bounces pveproxy asynchronously, so an immediate `s_client` still shows the old cert. Compare the served fingerprint against `fullchain.pem` after a pause, not against the pre-renew value in the same second
- **Never treat `certbot renew --dry-run` as a renewal proof for a private CA** — certbot silently sends dry-runs to Let's Encrypt **staging** whatever `--server` says, so it fails "No TXT record found" against internal names; and `certbot renew` sleeps a random 0–10 min first while holding `.certbot.lock`, so every later certbot call queues behind it. Prove renewal with `certbot renew --force-renewal --no-random-sleep-on-renew --cert-name <fqdn>`
- **Never build a regex-mode `redirect_uris` domain with a hand-written backslash in Jinja — use `regex_escape`** — `replace('.', '\\.')` inside a YAML block scalar renders two backslashes, every regex provider rejects its real redirect with "Redirect URI Error", and the deploy reports success because the blueprint applied. Validate a regex-mode provider by matching its live `redirect_uris[0].url` against a real callback URL, not by counting providers
- **Never write an authentik `redirect_uris` regex whose domain part is `[^/]+`** — `'^https://control\\.[^/]+:9443/?$'` matches `https://control.attacker.example:9443`, so an attacker-owned host is an accepted redirect target for that provider. Anchor with `${DOMAIN_RE}` (the deploy exports it as the regex-escaped service domain), or use `matching_mode: strict` with the exact URL
- **Never send a blueprint `attrs` partial update without re-sending every field the serializer's `validate()` reads** — blueprint updates run `partial=True`, but a DRF `validate()` sees only the incoming attrs, not the stored instance. The importer reports it as `Blueprint invalid` with the entry's unresolved `!KeyOf` printed as "failed to resolve" — read the `Serializer errors` dict, not the tag text.
- **Never seed `AUTHENTIK_BOOTSTRAP_EMAIL` with the operator's own address** — every consumer that keys users by email then has two authentik identities for one human; Grafana reports it as **"Login failed, user sync failed"**. akadmin gets `akadmin@<service domain>`; the env is read at install only, so an existing realm needs the user PATCHed by hand
- **Never expect an authentik application tile to launch a regex-`redirect_uris` provider** — authentik guesses a tile's target from the first redirect URI and gives up on a regex, so the tile links to `/` and bounces straight back to the dashboard. Every OIDC/SAML application in `blueprint-internal.yaml` therefore carries an explicit `meta_launch_url`, and `traefik-forward-auth` carries `blank://blank`
- **Never assume a MeshCentral site admin can see a device group it does not own — `managealldevicegroups` is a SECOND, independent condition** — `webserver.js` `GetAllMeshWithRights` returns every mesh only when `user.siteadmin == 0xFFFFFFFF` **and** the userid is in `settings.managealldevicegroups`; otherwise it returns `user.links`, empty for a fresh OIDC account. `meshcentral_manage_all_device_groups` in the `control` role is that list (`user//~oidc:<sub>` for an OIDC account). MeshCentral's `groups.scope` defaults to `groups`, a scope authentik does not have — set `scope: profile`
- **Never trust an authentik blueprint deploy that reports success — kubelet's ConfigMap sync can leave the worker applying the PREVIOUS blueprint** — `ak apply_blueprint` reads a mounted path that refreshes on kubelet's own period rather than when `kubectl apply` returns, so a deploy right after a ConfigMap change silently re-applies stale content and exits 0. Verify a blueprint change through the API (`/api/v3/providers/oauth2/`), never from the deploy's exit code.
- **Never install a DNS-only cert as UniFi OS Server's `unifi-core.crt`** — the host-side update supervisor reads that file as its trust anchor and dials `wss://127.0.0.1:11084`, so without `IP:127.0.0.1` every update fails `No connection to UOS Server Manager` while the UI and the container stay healthy. ACME cannot issue an IP SAN; the pair is API-issued (`api_cert_ip`). The tell is `certificate not valid for name "127.0.0.1"` in `/var/lib/uosserver/logs/uosserver-service.log`
