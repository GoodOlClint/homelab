## Canonical pipelines

- **Kubernetes / Talos ([ADR 0048](docs/decisions/0048-flux-reconciles-the-kubernetes-services-plane-from-the-repo-replacing-the-kubernetes-shell-deploy-layer-in-app-configuration-is-ansible-and-the-talos-lifecycle-stays-on-talos-sh.md)):** three owners, no fourth. **Talos lifecycle** = `kubernetes/talos/talos.sh` (configs from the `talos_nodes` terraform output + Infisical `/talos`; `make talos-secrets|apply|bootstrap`; `make talos-apply` is also how nodes pick up a changed root CA or kubelet arg) — **Ansible never touches a Talos node**, no second tool may render machine configs, `kubeconfig`/`talosconfig` live in `kubernetes/talos/.secrets/` (gitignored; `make talos-secrets` re-pulls). **Workloads** = Flux reconciling this public repo with no credential: one `Kustomization` per tree in `kubernetes/flux/apps/<tree>.yaml` (`postBuild.substituteFrom` the `cluster-bindings` ConfigMap), charts as pinned `HelmRelease`s in `kubernetes/<tree>/helm.yaml`; **a push to `main` is the deploy** — `make flux-reconcile TREE=<tree>` only skips the interval, and `make flux-check` refuses a tree whose `${VAR}` has no binding or whose pod-template container lacks a cpu+memory request (#31). Substitution is **strict** (an unset `${VAR}` fails the Kustomization); `axosyslog.conf` and `valheim-playfab-status.mjs` carry foreign `${…}` and are `kustomize.toolkit.fluxcd.io/substitute: disabled`; a binding-only change does not roll a pod. **Seed + in-app tail** = `ansible/playbooks/kubernetes.yml`: `make k8s-seed` (an allowlist, nothing else; needs `make pki-hosts` first), `make k8s-apps`, `make k8s-smoke` (fail-loud), `make k8s-update` (deletes the pods of `:latest` workloads so they re-pull through Zot — never `rollout restart`, Flux reverts the annotation and it bounces twice), `make plex-pbs-image`. Second run of seed and apps = 0 changed. **P3b add-ons (ADR 0034):** MetalLB L2 owns services offsets **64–79** (tree `metallb`; speakers need `ignoreExcludeLB` because every node is a control plane). cert-manager's `homelab-ca` ClusterIssuer is a **`ca` issuer over an intermediate signed by the Infisical internal root `Homelab Root CA`** (ADR 0039): `make k8s-seed` signs a fresh intermediate whenever the cluster's `tls.crt` does not verify against the root; the intermediate is disposable (never exported). Infisical's ACME server is HTTP-01 only; the cluster never uses it. The CA's DR path is the nightly `infisical_pbs_backup.sh` Postgres dump to PBS ns `databases` — verify by snapshot recency, `make infisical-backup` cannot carry PKI keys. Zot is `registry.<service domain>`, blobs on a ceph-rbd PVC; the name is pinned into `machine.registries`, so a rename is push the `zot` tree → restart the statefulset (Zot does not reload a renewed TLS secret) → `make talos-apply` → `make k8s-update` for every image-ref consumer. ARC scale sets (`psproxmoxve`, `pbs-collection`) are **hostNetwork dind pods pinned to talos-cp-a** sharing one RWO cache PVC; `runs-on:` must be the scale-set *name*. The ci-reaper CronJob destroys pool-`ci` guests older than 6 h. pfSense CI VLAN rules are hand-managed: [docs/pfsense-ci-vlan.md](docs/pfsense-ci-vlan.md). **P4a (ADR 0035):** HTTP apps publish a plain `Ingress` (`ingressClassName: traefik`, no `tls:` block) on `<name>.<service domain>` — Traefik sits on offset **65** with the Let's Encrypt wildcard as its default TLS store, and **external-dns publishes every Ingress host into BIND**. **Runtime secrets reach a pod only through an `InfisicalSecret` in the component's tree**; the single `kubectl create secret` in the cluster is `infisical-universal-auth` (a `make k8s-seed` object) — never add one-off create paths (ARC's two are grandfathered). The literal `${REGISTRY}` stays in every tracked image ref (renovate's image regex keys on it); a `kubernetes/<app>/` tree never contains a private address. **P4b (ADR 0036):** monitoring is tree `monitoring` (one `InfisicalSecret` on `/monitoring`, telegraf targets rendered from `vms.yaml` into a seed ConfigMap by `make k8s-seed`); **axosyslog is a MetalLB `LoadBalancer` at services offset 66 with `externalTrafficPolicy: Local`** (Cluster policy would SNAT every node to the same name) — `openobserve_listen_host` is the services prefix + `monitoring_syslog_offset`, never a `hostvars` lookup; pfSense's and UniFi's syslog targets are hand-set in their UIs. The OpenObserve image stays pinned (`v0.92.0-rc2`, schema 46). Node collectors: `make proxmox-hosts TAGS=node-exporter`. `make monitoring-users` recreates `monitoring@pve` + its token. ConfigMaps go through server-side apply (the dashboards exceed the last-applied annotation cap). **P4c (ADR 0037):** tree `plex-services` (tail `make k8s-apps`; Services keep the compose names so the Cloudflare tunnel routes resolve unchanged); the media tree is a **kubelet-mounted NFS PV**; SABnzbd scratch is a **node-local `local-zfs` disk on every Talos VM, mounted at `/var/mnt/scratch` and used as a hostPath**, never NFS and never Ceph; every tree with an in-tree Postgres includes **`kubernetes/pg-backup/`** as `../pg-backup`, parameterized through its `postBuild.substitute` (`NS PG_USER PG_SECRET BACKUP_ID SCHEDULE`, #37), whose `proxmox-backup-client` image is the registry's one local push (`make plex-pbs-image`, rebuild when the PBS major rolls). ## What Never To Do

- **Never evict Zot, Traefik and authentik in one drain — they form a cold-start cycle** — Zot **panics at startup** when its OIDC discovery against `auth.<service domain>` fails (fatal, not retried), and Traefik's + authentik's images pull through Zot, so all three down at once deadlocks. Move authentik first (Zot still serving), then Traefik, then drain
- **Never run a per-minute `:latest` pod against Zot without `imagePullPolicy: IfNotPresent`** — every start re-checks the tag upstream, Zot's on-demand sync forwards each check to Docker Hub anonymously, and the 100-pulls-per-6-h quota dies within minutes; every `docker.io` pull through Zot then fails `not found`. Prefer `public.ecr.aws/docker/library/*` mirrors for throwaway images
- **Never trust the Valheim image's "already the latest version" after a `state is 0x6` SteamCMD error, and never wait for `UPDATE_CRON` on a release day** — the updater falls back to the on-disk install and logs it as current while SteamCMD's content log shows `Failed to get manifest request code, 'Access Denied'`, and players see join → `connection lost` within seconds. Fix from inside the pod: `rm -rf /opt/valheim/dl/server/steamapps && supervisorctl restart valheim-updater`
- **Never run a MetalLB `L2Advertisement` without an `interfaces:` list on a multi-homed node** — with none, the speaker gratuitous-ARPs every LB address on every interface, so the Talos nodes' Ceph leg (`eth1`, VLAN 20) announces the vlan40 pool too and UniFi raises an *IP Address Conflict* for each LB address. `kubernetes/metallb/pool.yaml` pins `interfaces: [eth0]` — the services leg
- **Never name a Kubernetes Service after a container that reads `<NAME>_PORT` from its environment** — the pod gets the service-link env `SPEEDTEST_PORT=tcp://10.x:9798`, which the speedtest exporter read as its listen port and crash-looped. `enableServiceLinks: false` on the pod, or rename the Service
- **Never derive `openobserve_listen_host` from `hostvars['openobserve']`** — the guest is gone (ADR 0036); the address is the services prefix + `monitoring_syslog_offset` (66) and every sender (`rsyslog_client`, Docker syslog driver, nodes' `host-bindings.yaml`, pfSense, UniFi, Kuma) must point at that LB
- **A new Ingress hostname for SABnzbd must also land in its `host_whitelist`** — SAB rejects any Host header outside it (`Hostname verification failed`, 403). The whitelist lives only in SAB's live config: `api?mode=set_config&section=misc&keyword=host_whitelist` from inside the pod (`localhost` bypasses the check; the ingress path cannot fix itself)
- **Never leave a Postgres-backed arr Deployment without a liveness probe** — sonarr/radarr/lidarr/prowlarr treat a refused DB connection at startup as "non-recoverable failure, waiting for user intervention": the process stays alive, readiness never passes, nothing restarts it. `kubernetes/plex-services/app.yaml` carries `livenessProbe` on `/ping` for the four
- **Never expect a Traefik forward-auth annotation to protect only some hosts on a shared Ingress** — the `router.middlewares` annotation applies to EVERY router the Ingress creates, so a multi-host Ingress is all-or-nothing; protected hosts get their own Ingress (`monitoring-auth`, the same split `seerr` has). Whenever a host moves behind forward-auth, re-point every MACHINE consumer of it to in-cluster svc DNS first, or it goes red on the 302
- **Never read a pod's AGE as an outage duration, and never treat `up == 0` as crashloop coverage** — a `CrashLoopBackOff` line shows the pod's age next to its restart count, not how long it has been failing, and `HostDown` (`up == 0`, `for: 2m`) never sees a pod that answers again between restarts. `PodCrashLooping` and `PodNotReady` cover it; for a real timeline query Prometheus `up{job=...}` over a range. Container logs are not recoverable after the fact: Talos deletes `/var/log/containers/*` with the pod, so a drain destroys the evidence
- **Never apply a Talos VM resource change to more than one node at a time** — bpg stops and starts the guest to land a `cpu`/`memory` edit, and `make talos-build` targets all three control-plane VMs, so a bare run bounces every etcd member at once. Drain first and target one node: `make talos-build TALOS_TARGETS='-target=proxmox_virtual_environment_vm.talos_cp[\"talos-cp-a\"]'` — the escaped quotes are required (worklab's is `talos_cp_worklab`). Drain → apply → wait Ready → uncordon → check `talosctl etcd members` before the next node
- **Never ship a workload container into the cluster without a CPU and memory `request`** — kube-scheduler scores nodes by *requested* resources, so a pod with no request makes every node look equally empty and the spread is arbitrary and permanent. Requests are set per container in each `kubernetes/<app>/app.yaml`; set requests only — no CPU limits (throttling) and no memory limits (OOMKills)
- **Never give a Deployment that mounts an RWO ceph-rbd PVC the default `RollingUpdate` strategy** — the new pod is scheduled before the old one releases the volume, so it blocks on `Multi-Attach error for volume … Volume is already used by pod(s) …` until the eviction times out. Every such Deployment carries `strategy: {type: Recreate}`
- **Never write an absence alert as `sum(increase(<series>)) == 0`** — over a missing series it returns nothing and never fires. Use `absent()`, and confirm the series exists on the live Prometheus before trusting the rule
- **Never write a cron hour or a CronJob `schedule` assuming it is local time without checking the zone** — the LXC templates ship UTC and bpg's container resource has no timezone, while the VMs (cloud-init) run America/Chicago. `make ansible-infra TAGS=timezone` sets `{{ timezone }}` on every guest and restarts cron; Kubernetes CronJobs use the controller's UTC unless they carry `timeZone: "${TZ}"`
